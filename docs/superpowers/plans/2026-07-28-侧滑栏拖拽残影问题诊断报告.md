# 侧滑栏拖拽残影问题诊断报告

> **日期**：2026-07-28
> **埋点版本**：6 类埋点（ReorderableDiagnostics）
> **测试设备**：30211（待办分类测试）
> **测试命令**：`adb logcat -s DrawerDrag/Category:D DrawerDrag/Inspiration:D DrawerDrag/Profile:D`

## 一、问题现象

侧滑栏 4 个 Tab 长按拖拽时，**被拖拽项在交换的瞬间有残影/闪烁感**。目视判断是 graphicsLayer 缩放或位置在交换点有瞬时不连续。

### 2.2 关键发现

#### 发现 1：重组风暴（高频 onMove 触发整列表重组）

- 每次 `onMove` 回调触发 **25~101 次 Composable 重组**
- 正常情况下单次 onMove 预期只触发 1~3 次重组（仅被拖拽项）
- **实际是 50 倍以上** → 这是 Compose 性能问题，但**不是残影的直接原因**

#### 发现 2：第一次 MOVE 不触发重组，之后每次都触发

- 第一次 MOVE 后 `recomposeCount` 不变
- 第二次起每次都 +25~+101 重组
- 原因：第一次 MOVE 后才触发 `onReorder` 回调 → ViewModel 更新 → StateFlow 推送

#### 发现 3：拖拽结束后仍有大量重组

- Inspiration: STOP 时 340 → 拖拽后 LAYOUT 时 381（**+41**）
- Profile: STOP 时 171 → 拖拽后 LAYOUT 时 211（**+40**）
- Category: STOP 时 6957 → 拖拽后 LAYOUT 时 7002（**+45**）

**核心问题**：`onReorder` 回调触发 ViewModel → Repository → DAO → 数据库更新，整个 StateFlow 链路把所有 state 推回 UI 层，导致拖拽结束后仍重组 ~40 次。

#### 发现 4：非拖拽项在拖拽中无 LAYER 切换

- 所有 7 个标签在初始化时各打 1 个 `[LAYER] isDragging=false`（共 7 次，Profile 看到 3 次）
- 拖拽过程中**没有**非拖拽项的 LAYER 切换记录
- 说明 isDragging 仅作用在当前拖拽项，不会让其他项也切换

#### 发现 5：graphicsLayer 切换正常

- START 后 15ms 内必出 `LAYER isDragging=true (scale=1.05)`
- STOP 后 11ms 内必出 `LAYER isDragging=false (scale=1.0)`
- 时间线正常，但**重组风暴导致 graphicsLayer lambda 频繁重算**

## 三、根本原因分析

### 主因：`onReorder` 在 onMove 回调内同步触发

**问题代码**（3 个 Section 同款）：

```kotlin
val reorderableLazyListState = rememberReorderableLazyListState(lazyListState = listState) { from, to ->
    // 每次 MOVE 都调用 onReorder
    val newList = categories.toMutableList().apply {
        add(toIndex, removeAt(fromIndex))
    }
    onReorder(newList)  // ← 触发 ViewModel.updateOrder → DAO → StateFlow
}
```

**事件链**：
```
[1] 用户手指移动 1mm
    ↓
[2] Reorderable 库检测 onMove
    ↓
[3] onReorder(newList) 同步调用
    ↓
[4] ViewModel.updateOrder(newList)
    ↓
[5] Repository.updateOrder
    ↓
[6] DAO.updateAll
    ↓
[7] StateFlow 推送新值
    ↓
[8] MainScreen collectAsState 触发
    ↓
[9] AppDrawerContentImpl 重组
    ↓
[10] Section 重组
    ↓
[11] LazyColumn 重组 → 所有 item 重组
    ↓
[12] graphicsLayer lambda 重算（每次重组都执行）
    ↓
[13] Compose 触发 layoutInvalidation
    ↓
[14] 残影/闪烁
```

### 残影的直接原因

虽然 `LAYER isDragging` 切换次数正常（START 后 +15ms，STOP 后 +11ms），但**重组风暴**导致：
- graphicsLayer 的 lambda 在每次重组时都执行 `scaleX/Y = ...`
- 即使值不变，lambda 重新执行也会让 Compose 标记 layer 为 dirty
- 大量 dirty layer 在同一帧内 commit → 视觉上的残影/抖动

## 四、修复方案对比

| 方案 | 实现难度 | 效果 | 推荐度 |
|---|---|---|---|
| **A. 拖拽结束才持久化** | 中 | ★★★★★ | ⭐⭐⭐⭐⭐ |
| **B. 节流 onMove 回调** | 低 | ★★★ | ⭐⭐ |
| **C. 分离 UI 状态/数据状态** | 高 | ★★★★★ | ⭐⭐⭐ |
| **D. graphicsLayer 加动画过渡** | 低 | ★★ | ⭐⭐ |
| **A+D 组合** | 中高 | ★★★★★ | ⭐⭐⭐⭐ |

### 方案 A：拖拽结束才持久化（核心方案）

**思路**：在 Section 内部维护 `pendingReorder` 状态，拖拽过程只更新本地状态，**拖拽结束（STOP）才回调 onReorder**。

**修改前**：
```kotlin
val reorderableLazyListState = rememberReorderableLazyListState(lazyListState = listState) { from, to ->
    val newList = categories.toMutableList().apply { add(toIndex, removeAt(fromIndex)) }
    onReorder(newList)  // 每次 MOVE 都回调 → 重组风暴
}
```

**修改后**：
```kotlin
// 临时记录待提交的排序
var pendingReorder by remember { mutableStateOf<List<Category>?>(null) }

val reorderableLazyListState = rememberReorderableLazyListState(lazyListState = listState) { from, to ->
    // 只更新本地 pending 状态，不回调
    val fromIndex = from.index - 2
    val toIndex = to.index - 2
    if (fromIndex in categories.indices && toIndex in categories.indices) {
        pendingReorder = categories.toMutableList().apply { add(toIndex, removeAt(fromIndex)) }
    }
}

.longPressDraggableHandle(
    onDragStopped = {
        // 拖拽结束才提交
        pendingReorder?.let { onReorder(it) }
        pendingReorder = null
    }
)
```

**预期效果**：
- 拖拽过程中只重组 graphicsLayer 内部（Reorderable 库自己处理）
- STOP 时仅触发 1 次 ViewModel 更新
- 重组次数从 ~50 次/秒 降到 ~3 次/拖拽
- 残影消失

### 方案 D：graphicsLayer 加动画（辅助方案）

**思路**：用 `animateFloatAsState` 替代直接赋值，让 scale/shadow 平滑过渡。

```kotlin
val scale by animateFloatAsState(
    targetValue = if (isDragging) 1.05f else 1f,
    animationSpec = tween(durationMillis = 100)
)
val shadow by animateFloatAsState(
    targetValue = if (isDragging) 8f else 0f,
    animationSpec = tween(durationMillis = 100)
)

Box(
    modifier = Modifier.graphicsLayer {
        scaleX = scale
        scaleY = scale
        shadowElevation = shadow
    }
)
```

**预期效果**：
- 即使有重组，scale/shadow 变化是渐变的，不是突变的
- 视觉上更平滑
- 但重组风暴问题未解决

## 五、推荐方案

**方案 A + 方案 D 组合**：
- **方案 A** 解决重组风暴（治本，大幅降低 onReorder 触发频率）
- **方案 D** 解决 graphicsLayer 突变（治标，让 scale/shadow 变化平滑）
- 两者结合，从根本上消除残影
