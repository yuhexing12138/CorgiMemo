> **作者**：MiniMax-M3

> **关联项目**：CorgiMemo Android

## 1. 概述

### 1.1 目标

为侧滑栏 4 个 Tab（TODO / DATE / INSPIRATION / PROFILE）中的可排序项添加**长按拖拽重排**功能，**立即持久化**到数据库或 ESP，重启后保留用户自定义顺序。

### 1.2 范围

| Tab | Section | 拖拽 | 持久化方式 | 改动复杂度 |
|---|---|---|---|---|
| **TODO** | GROUP（自定义分类） | ✅ | DB Migration：新增 `sortOrder` 字段 | 中 |
| **TODO** | STATUS（状态过滤项） | ✅ | ESP 持久化 `List<String>` 顺序 | 中 |
| **DATE** | 日期类型（CustomDateType） | ✅ | 已有 `sortOrder` 字段，**零改动** | 最小 |
| **INSPIRATION** | 灵感标签（聚合自 `Inspiration.tags`） | ✅ | 新建 `inspiration_tag_order` 表 | 大 |
| **PROFILE** | 快速导航（4 个 hardcoded） | ✅ | 新建 `profile_nav_items` 表 + seed | 大 |

### 1.3 非目标

- ❌ 不支持跨区拖拽（如将"状态项"拖到"分组区"）
- ❌ 不改变现有 STATUS 6 个 enum 的语义（仅顺序可定制）
- ❌ 不支持跨进程并发修改排序（仅 UI 层串行）

## 2. 关键设计决策

### 2.1 已确认决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 拖拽手柄 | **整行可拖** | 与首页 todo 卡片拖拽一致，避免与"长按弹菜单"冲突 |
| 拖拽中视觉 | **标准 Reorderable（缩放 1.05 + 阴影）** | 库默认行为，零成本，视觉噪音最低 |
| 持久化策略 | **立即持久化** | 拖完即保存，无"待提交"状态 |
| 跨区支持 | **不支持** | 4 个 Section 互斥，跨区语义复杂 |
| 架构 | **方案 A：各 Tab 独立实现** | 与现有代码 1:1 对应，调试简单，零抽象成本 |
| 拖拽库 | **Reorderable 库 + `longPressDraggableHandle`** | 项目已统一封装，避免滚动误触 |

### 2.2 关键技术细节

- **统一拖拽模式**：`LazyColumn` + `rememberReorderableLazyListState` + `ReorderableItem` + `Modifier.longPressDraggableHandle`
- **onMove 同步完成数据重排**（避免闪烁）
- **`ReorderableItem` 的 key 必须与 `items(key = ...)` 一致**（用 `id` 不用 `index`）
- **拖拽中视觉**：`zIndex(1f) + graphicsLayer { scaleX/Y = 1.05f; shadowElevation = 8f }`
- **触觉反馈**：`onDragStarted` 时调用 `HapticFeedbackManager.TEXT_MOVE`

## 3. 组件设计

### 3.1 4 个 Section 的统一模式

每个 Section 都遵循以下模式（**模板化**）：

```kotlin
@Composable
internal fun XxxFilterSection(
    items: List<XxxItem>,         // 数据源（带 sortOrder 排序）
    onReorder: (List<XxxItem>) -> Unit,  // 拖拽完成回调
    // ... 现有参数
) {
    val listState = rememberLazyListState()
    val reorderableState = rememberReorderableLazyListState(listState) { from, to ->
        val newList = items.toMutableList().apply {
            add(to.index, removeAt(from.index))
        }
        onReorder(newList)  // 同步完成数据重排
    }

    LazyColumn(state = listState) {
        items(items, key = { it.id }) { item ->
            ReorderableItem(state = reorderableState, key = item.id) { isDragging ->
                Box(
                    modifier = Modifier
                        .zIndex(if (isDragging) 1f else 0f)
                        .graphicsLayer {
                            scaleX = if (isDragging) 1.05f else 1f
                            scaleY = if (isDragging) 1.05f else 1f
                            shadowElevation = if (isDragging) 8f else 0f
                        }
                        .longPressDraggableHandle(
                            onDragStarted = {
                                HapticFeedbackManager.performHapticFeedback(
                                    context = LocalContext.current,
                                    type = InteractionType.TEXT_MOVE,
                                    enabled = true
                                )
                            },
                            onDragStopped = {}
                        )
                ) {
                    XxxItemRow(item = item, /* ... */)
                }
            }
        }
    }
}
```

## 4. 数据流设计

### 4.1 统一数据流

```
用户长按 → longPressDraggableHandle 触发
        → ReorderableItem onMove(from, to)
        → Section 内 onReorder(newList) 回调
        → ViewModel 接收新顺序
        → ViewModel.updateXxxOrder(newList)
        → Repository.batchUpdateSortOrder(items)  // 事务性批量更新
        → DAO UPDATE ... WHERE id = ?  // 4 个独立 UPDATE（或 1 个 batch）
        → DB 提交 / ESP commit
```

## 5. 错误处理

| 场景 | 行为 |
|---|---|
| 拖拽中应用退出 | 拖拽未完成，DB 未更新，下次启动恢复原顺序（无副作用） |
| DB 写入失败（事务回滚） | 显示"保存失败" Snackbar，恢复原顺序 |
| ESP 写入失败 | 同上 |
| 拖拽到列表外 | 自动取消（库默认） |
| 跨进程并发修改 | `suspend` + `viewModelScope.launch` 保证串行 |
| 拖拽中数据列表被外部修改（如删除） | 重新加载 onMove 后再重排 |

## 8. 风险与缓解

| 风险 | 缓解 |
|---|---|
| PROFILE 改 hardcoded 为 DB，可能影响其他引用 | 加 alias + 旧调用兼容 |
| 4 个 Migration 顺序错误 | 一次性增加一个 Migration，version++ |
| `InspirationFilterSection` 当前用 `tags: List<String>`，可能只显示当前灵感用的 tag | 与 ViewModel 协商，改为"全部已知 tag" |

| P8 期间大量改动引入新 bug | 每完成一个 Tab 询问用户编译验证 |

## 9. 项目规则遵守

按 `.trae/rules/` 链：

- ✅ 长效 lambda 捕获（用内部最新 state，不捕获过期参数）
- ✅ `@ColumnInfo(defaultValue)` 与 Migration DEFAULT 一致
- ✅ 巨石组件拆分规范（`StatusFilterSection` 已 500+ 行，必要时拆 model/sections）
- ✅ 编译验证询问（不擅自编译）
- ✅ Git 提交询问（每 Tab 提交）
- ✅ 优化建议（每段设计给后续可优化点）
- ✅ 中文命名（文档 + 文件名）
- ✅ Reorderable 库使用规范（统一 `longPressDraggableHandle`）

## 10. 后续可优化方向

1. **跨 Section 拖拽**（未来如需）：可将 4 个 Section 合并为 `ZonedReorderableLazyColumn`，实现"把状态项拖到分组区"
2. **拖拽撤销**（Snackbar Undo）：5 秒内可撤销最近一次拖拽
3. **拖拽历史**（审计）：记录最近 N 次排序变化
4. **批量排序**（多选模式）：先勾选多个项再统一排序
5. **侧滑栏 Drawer 性能优化**：4 个 Section 都用 LazyColumn 后总节点数 < 200，性能无虞；如未来增长到 1000+，考虑 `key` 优化或分页
