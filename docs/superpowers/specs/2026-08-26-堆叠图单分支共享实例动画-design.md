> 日期：2026-08-26
> 关联原型：`图片库/expand-collapse-stack.html`（CSS transition 400ms cubic-bezier + 200ms opacity）
> 关联组件：`app/src/main/java/com/corgimemo/app/ui/components/SwipeableImageStack.kt`（~1500 行巨石组件，P1-P5 香肠式分步迁移）

## 1. 背景与问题

### 1.1 现状（改造前）
SwipeableImageStack 采用 **if/else 双分支架构**：
- 堆叠态（`!isExpanded`）：保留 V1.0 扇形拖拽 + 五属性 graphicsLayer 变换（x/y/rotate/scale/zIndex）
- 展开态（`isExpanded`）：V3.0 简化排图（`Row + Arrangement.spacedBy(8dp) + Box(size=120dp)`，纯 layout 无 transform）
- 两个分支各自 `order.forEach { Box(...) }`，卡片 Composable **实例不共享** → Compose 无法复用实例

### 1.2 用户问题
当前动画（`animateContentSize` 宽变化 + 3 元素 alpha）并没有实现原型级别的卡片 transform 连续过渡：
- 卡片瞬间"蹦"到横排位置，中间没有扇形角度、缩放、平移的补间
- 用户要求：**严格对齐原型**，卡片从扇形堆叠 → 横向铺开**每张卡独立连续运动**

### 1.3 原型实现机制（严格对齐目标）
原型 `expand-collapse-stack.html` 动画核心（L72-73, L356-477）：
```
单一 DOM 实例（createCards 一次创建，setExpanded 切换不增删）
→ 单一 getCardTarget(index, expanded) 统一返回 {x, y, rotate, scale, zIndex, shadow}
→ CSS transition: transform 0.4s cubic-bezier(0.22,1,0.36,1), box-shadow 0.3s ease
→ CSS transition: width 0.4s cubic-bezier(...)           (card-container 宽度)
→ CSS transition: opacity 0.2s                           (badge/expandBtn/collapseBtn)
→ pointer-events: isExpanded ? 'none' : 'auto'           (L450 手势互斥)
```

## 3. 架构设计（§1）

### 3.1 CardTarget 统一模型

```kotlin
/** 卡片在任意时刻的统一目标值（等价原型 getCardTarget 返回值） */
private data class CardTarget(
    val x: Dp,
    val y: Dp,
    val rotationZ: Float,    // degrees
    val scale: Float,
    val shadowElevation: Dp,
    val zIndex: Float,
)

/**
 * 单一目标函数（等价原型 getCardTarget）
 * - expandProgress = 0 → 堆叠态
 * - expandProgress = 1 → 展开态
 * - expandProgress ∈ (0,1) → 线性插值（400ms 补间每帧调用）
 * - S2 语义：displayIndex = order 中该卡的索引（保留翻牌进度）
 */
private fun calcCardTarget(
    displayIndex: Int,
    cardCount: Int,
    expandProgress: Float,
    cardW: Dp, cardGap: Dp, visibleDepth: Int,
    stackOffsetDp: Dp, fanAngleDeg: Float, scaleStep: Float,
): CardTarget {
    val ei = min(displayIndex, visibleDepth - 1)
    val denom = max(visibleDepth - 1, 1)

    val stacked = CardTarget(
        x = 0.dp,
        y = (-ei * stackOffsetDp.value).dp,
        rotationZ = fanAngleDeg * (ei.toFloat() / denom),
        scale = 1f - ei * scaleStep,
        shadowElevation = if (displayIndex == 0) 8.dp else 4.dp,
        zIndex = (visibleDepth - ei).toFloat()
    )

    val expanded = CardTarget(
        x = displayIndex.toFloat() * (cardW.value + cardGap.value).dp,
        y = 0.dp,
        rotationZ = 0f,
        scale = 1f,
        shadowElevation = 4.dp,
        zIndex = 1f
    )

    val p = expandProgress.coerceIn(0f, 1f)
    return CardTarget(
        x = lerp(stacked.x, expanded.x, p),
        y = lerp(stacked.y, expanded.y, p),
        rotationZ = stacked.rotationZ + (expanded.rotationZ - stacked.rotationZ) * p,
        scale = stacked.scale + (expanded.scale - stacked.scale) * p,
        shadowElevation = lerp(stacked.shadowElevation, expanded.shadowElevation, p),
        zIndex = if (p < 0.5f) stacked.zIndex else expanded.zIndex
    )
}

/** Dp 线性插值工具 */
private fun lerp(a: Dp, b: Dp, p: Float): Dp =
    (a.value + (b.value - a.value) * p).dp
```

### 3.2 架构对比（当前 → 目标）

| 维度 | 当前双分支 | 目标单分支 |
|---|---|---|
| 卡片实例 | ❌ 两套 forEach，不共享 | ✅ 单一 `SharedCardRow()` 两分支同调 + `key(card.stableId)` |

## 4. 动画驱动 + 手势互斥锁（§2）

### 4.1 单 expandProgress Animatable 核心

```kotlin
// ========== 核心：全局展开进度驱动（单一协程）==========
private val expandProgress = Animatable(initialValue = if (initialExpanded) 1f else 0f)

private val TRANSITION_400_SPEC = tween<Float>(
    durationMillis = 400,
    easing = CubicBezierEasing(0.22f, 1f, 0.36f, 1f)  // 严格对齐原型 cubic-bezier(0.22,1,0.36,1)
)
private val OPACITY_200_SPEC = tween<Float>(durationMillis = 200) // 严格对齐原型 opacity 0.2s

// ========== 派生状态（条件挂载判断）==========
private val isAnimating: Boolean get() = expandProgress.isRunning
private val isInStackedMode: Boolean  // 堆叠态：可扇形拖拽 + pointerInput 挂载
    get() = expandProgress.value < 0.01f && !isAnimating
private val isInExpandedMode: Boolean // 展开态：可 horizontalScroll + 任意卡点击预览
    get() = expandProgress.value > 0.99f && !isAnimating

// ========== 对外 isExpanded Boolean（兼容旧 API）==========
// remember + derivedStateOf：避免过渡中每帧都触发非必要快照通知 + 防止重组新建 derivedStateOf 对象
private val derivedIsExpanded: Boolean by remember { derivedStateOf { expandProgress.value >= 0.5f } }
```

### 4.2 setExpanded 状态切换入口

```kotlin
suspend fun setExpanded(expanded: Boolean) {
    val target = if (expanded) 1f else 0f
    if (abs(expandProgress.value - target) < 0.001f) return

    // --- 展开前：堆叠态 dragOffset 归零（V1.1 保留，避免切换瞬间顶卡偏移跳变）---
    if (expanded) {
        coroutineScope {
            awaitAll(
                async { dragOffsetX.animateTo(0f, TRANSITION_SPRING) },
                async { dragOffsetY.animateTo(0f, BOUNCE_SPRING) },
            )
        }
    } else {
        // --- 收起前：横滚归零 ---
        expandedScrollState.animateScrollTo(0)
    }

    // --- 触发 400ms 主进度补间（所有卡 5 属性同步连续过渡）---
    expandProgress.animateTo(target, TRANSITION_400_SPEC)

    // --- 阈值跨越时回调（防抖）---
    val effExpanded = target >= 0.5f
    if (effExpanded != lastCallbackExpanded) {
        lastCallbackExpanded = effExpanded
        onExpandStateChange?.invoke(effExpanded)
    }
}
```

### 4.3 条件挂载手势/滚动（方案A 严格互斥）

| 能力 | 挂载条件（Modifier.then 的判断） | 说明 |
|---|---|---|
| 扇形拖拽翻牌（`detectDragGestures`） | `isInStackedMode && displayIndex == 0` | 顶卡堆叠态才能拖，过渡/展开态完全 detach pointerInput 节点（比 return 更干净） |
| 顶卡点击全屏预览（堆叠态） | `isInStackedMode` | 仅堆叠态下 detectTapGestures(onTap) 生效 |
| 任意卡点击全屏预览（展开态） | `isInExpandedMode` | 展开态下 Modifier.clickable 生效 |
| 横滚 `horizontalScroll` | Layer-1 包裹层切换（`if (isInExpandedMode)` 才套 Box(widthIn+horizontalScroll)） | 过渡中卡片不处于横滚容器，防止用户手势与 400ms 动画冲突 |
| ExpandBtn clickable | `expandAlpha > 0.01f && expandProgress.value < 0.01f` | 透明 + 非堆叠时不挂 clickable，等价原型 pointer-events |

### 4.4 OneSharedCard 渲染层（关键 graphicsLayer）

```kotlin
@Composable
private fun OneSharedCard(
    displayIndex: Int,
    card: CardSlot,
    /* ...所有依赖项传参（避免 lambda 捕获外部可变状态陷阱）... */
) {
    // 实时目标值：expandProgress 变化时每帧重算（无需 Animatable）
    val target = calcCardTarget(
        displayIndex = displayIndex,
        cardCount = order.size,
        expandProgress = expandProgress.value,
        ...
    )
    // 拖拽偏移（仅堆叠态顶卡有效；过渡/展开态归零叠加）
    val dragX = if (displayIndex == 0 && isInStackedMode) dragOffsetX.value.dp else 0.dp
    val dragY = if (displayIndex == 0 && isInStackedMode) dragOffsetY.value.dp else 0.dp

    Box(
        modifier = Modifier
            .size(cardWidth, cardHeight)
            // 统一五属性变换（同步于 graphicsLayer，避免 layout 抖动）
            .graphicsLayer {
                translationX = (target.x + dragX).toPx()
                translationY = (target.y + dragY).toPx()
                rotationZ = target.rotationZ
                scaleX = target.scale
                scaleY = target.scale
            }
            .shadow(
                elevation = target.shadowElevation,
                shape = RoundedCornerShape(cardCornerDp),
                clip = true
            )
            .zIndex(target.zIndex)
            // 条件挂载：pointerInput / clickable（手势互斥 §4.3）
            .then(mountPointerOrClickModifier(displayIndex, card))
    ) {
        // 与原代码完全一致：SubcomposeAsyncImage / 色块 / 占位图 → 0 改动
        CardContentRenderer(card)
    }
}
```

### 5.2 Layer-1 完整实现（双包裹层 + 单一 SharedCardRow）

```kotlin
@Composable
private fun Layer1CardWrapper() {
    if (isInExpandedMode) {
        // 展开态：外层水平滚动（maxWidth 480dp，不与 stageBoxWidth 绑定）
        Box(
            modifier = Modifier
                .align(Alignment.TopStart)
                .padding(start = expandedContentStartPadding, top = topCardTopInStageDp)
                .widthIn(max = EXPANDED_SCROLL_MAX_WIDTH_DP)
                .height(cardHeight)
                .horizontalScroll(expandedScrollState)
        ) {
            SharedCardRow()  // 展开态下 CardTarget x = displayIndex × (cardW + cardGap)
        }
    } else {
        // 堆叠态 / 过渡态：直接 Box 不挂横滚
        // 过渡态（0 < progress < 1）：Stage animateContentSize 同步扩宽，
        // 卡片 graphicsLayer 连续 lerp → 完美视觉连续
        Box(
            modifier = Modifier
                .align(Alignment.TopStart)
                .padding(start = expandedContentStartPadding, top = topCardTopInStageDp)
        ) {
            SharedCardRow()  // 堆叠态下 CardTarget 扇形五属性
        }
    }
}

@Composable
private fun SharedCardRow() {
    order.forEachIndexed { displayIndex, card ->
        key(card.stableId) {
            OneSharedCard(displayIndex, card, ...)
        }
    }
}
```

### 5.3 关键：Compose Positional Memoization 实例复用机制

为什么"双包裹层调用同一 SharedCardRow + 同 key"可以实现跨切换实例共享？

Compose 重组规则（官方文档 Positional Memoization）：
> 当 Composable 树重组时，若某节点**位置（slot）相同**、**函数引用相同**、**key 相同** → 复用原有实例，保留其 remember/Animatable/LaunchedEffect 所有内部状态。

本设计中：
- 切换 expandProgress 时，Layer1CardWrapper 的重组只发生在 `isInExpandedMode` 阈值跨越瞬间（progress 0.99f → 1.00f）。此时：
  - 包裹层 Box 变了（一个加了 horizontalScroll，一个没有）
  - 但包裹层**内部子节点 `SharedCardRow()` 的位置**都是第一个子 slot
  - 函数引用完全相同（同一个 Composable 函数对象）
  - `key(card.stableId)` 在子层完全匹配

结论：**卡片 OneSharedCard 内部的 remember/SubcomposeAsyncImage/加载状态 100% 保留**（图片不会因为切换包裹层而重新加载，这是"连续动画"的底线保障）。

### 5.4 Layer-2/3 绝对定位坐标完全保留

| 元素 | 坐标计算方式 | 保证位置不变 |
|---|---|---|
| **ExpandBtn** | `buttonStartX = topCardRightX_box + showCountBadge? marginWithBadge : marginNoBadge`；`top = topCardCenterY`；`translationY = -btnActualHalfOffsetDp` | 所有变量基于 `stageBoxWidthDp`（堆叠态恒定），即使展开时 stageBoxWidth 变宽，Badge/ExpandBtn 仍按堆叠态参考计算 → 堆叠态相对堆叠图的位置一字不动 ✅ |
| **countBadge** | `start = topCardRightX_box`，`top = topCardBottomY_box - badgeEstH` | 同上 ✅ |
| **CollapseBtn** | `start = expandedContentStartPadding`，`top = topCardTopInStageDp + cardH/2 - btnH/2` | 独立于 stageBoxWidth 变量 → 按 V4.0 要求与标题行左对齐 ✅ |

## 8. 风险与缓解

| 风险 | 概率 | 影响 | 缓解措施 |
|---|---|---|---|
| **Layer1CardWrapper 包裹切换瞬间图片闪烁** | 中 | 用户感知"白屏一下" | ① 阈值调到 progress=0.995（接近完全展开才切换）② 迁移 P2 时先验证 SharedCardRow 在单分支内可跨重组保留 SubcomposeAsyncImage 状态，若失败则迁移到 AnimatedContent(targetState = isInExpandedMode) { ... SharedCardRow() }（ AnimatedContent 官方保证跨 target 共享同 key 实例） |
| **progress=0 堆叠态 graphicsLayer 计算导致性能回退** | 低 | 低端机掉帧 | calcCardTarget 用 `@Stable data class` 注解；expandProgress 声明为 `Animatable(0f)` 其 value 在静止时不会触发重组（Animatable 内部使用快照系统）；若 P2 验证存在性能回退，则给 OneSharedCard 的 target 加 `remember(expandProgress.value, displayIndex, ...)` 缓存 |
| **Stage animateContentSize 与 expandProgress 不同步** | 中 | 容器宽度补间与卡片 transform 节奏错位 | expandProgress.animateTo 与 animateContentSize 都用 TRANSITION_400_SPEC（同一 spec 对象，时长/缓动完全一致）；若出现错位可将 Stage 的 size 改为 `derivedStateOf { with(expandProgress.value) { lerp(stackStageW, expandedStageW, it) } }` 并配合 Modifier.animateContentSize 或直接 Animatable |
| **400ms 过渡中用户返回页面 → 协程泄漏** | 低 | 异常崩溃 | expandProgress 定义为 remember + lifecycle 绑定的 Animatable（Compose 内置 remember(Animatable) 会在 Composition 离开时自动停止）；若仍有问题，包一层 `DisposableEffect(onDispose = { scope.coroutineContext.cancelChildren() })` |
