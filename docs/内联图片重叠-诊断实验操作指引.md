## 三、日志长什么样

### 行高合成探针

```
[INLINE-LH] 段落#123456 段落行高=NaN 编辑器行高=24.0 图片高度=310.5 => 最终=310.5
```

四个字段含义：

| 字段 | 含义 | 单位 |
| --- | --- | --- |
| 段落行高 | 该段落自身声明的 lineHeight | sp |
| 编辑器行高 | `BasicRichTextEditor` 从 textStyle 注入的 `editorLineHeight` | sp |
| 图片高度 | 段落内最大图片高度（由覆盖层解码后写回） | sp |
| 最终 | 三者取 max 后真正写进段落 range 的值 | sp |

`NaN` = `TextUnit.Unspecified`，即"未指定"。

### 绘制坐标探针

```
[INLINE-IMG] lineCount=3 textLen=5 图片数=2
  #0 range=0..1 line=0 lineTop=0.0 lineBottom=310.5 行高=310.5 图高=310.5 落点=[0.0..310.5]
  #1 range=2..3 line=1 lineTop=310.5 lineBottom=621.0 行高=310.5 图高=310.5 落点=[310.5..621.0]
```

| 字段 | 含义 |
| --- | --- |
| `line` / `lineTop` / `lineBottom` | 排版引擎给该占位符分配的**真实行**及其纵向范围（px） |
| `行高` | `lineBottom - lineTop`，即排版引擎实际给这行分配的高度（px） |
| `图高` | 覆盖层算出的图片显示高度（px） |
| `落点` | 图片最终画上去的纵向区间（px） |
| `<<< 与上一张重叠 Npx` | 探针自动判定的重叠告警及重叠像素数 |

## 四、判定表（拿到日志后直接对照）

### 第一步：看 `[INLINE-LH]`，判定行高链路

| 现象 | 结论 | 下一步 |
| --- | --- | --- |
| `编辑器行高=NaN` | `editorLineHeight` **根本没注入** → 上一轮的行高修复完全没生效 | 查 `BasicRichTextEditor` 的 SideEffect 与 App 侧 textStyle |
| `图片高度=NaN` | 段落树里**找不到图片 span**，或 `setResolvedSize` 没写回来 | **根因 C**：写尺寸的 span 与排版读取的 span 不是同一对象 |
| `最终=NaN` | 三者全未指定，该段落完全不预留纵向空间 | 沿上面两条回查 |
| `最终 ≈ 24`（≈ 编辑器行高，远小于图片高度） | 行高被压制，图片高度没进 max | 查 `merge` 顺序与 `normalizedParagraphStyles` 的 default 覆盖 |
| `最终 ≈ 图片高度` | ✅ 行高链路正常 | 进入第二步 |

### 第二步：看 `[INLINE-IMG]`，判定坐标链路

| 现象 | 结论 |
| --- | --- |
| `行高 ≈ 图高`，且各图 `落点` 首尾相接不交叉 | ✅ 排版正常 —— 若此时仍视觉重叠，问题在**绘制之外**（如父容器 clip / 重复绘制） |
| `行高 ≈ 30`（一行正文）而 `图高 ≈ 310` | **根因 A：行高未生效**，纵向空间没预留 |
| `行高 ≈ 图高`，但两图 `line` 相同、`lineTop` 相同 | 两图挤在同一段落同一行 → 现有"同 line 错开"兜底应已处理；若仍重叠说明兜底未生效 |
| 两图 `line` 不同，但 `落点` 区间相交 | **根因 B：跨 line 坐标错乱**，`lineTop` 未累加前序行高 |
| 出现 `<<< 与上一张重叠 Npx` | 探针已量化重叠量，按 N 值反推是哪一环少算了高度 |
