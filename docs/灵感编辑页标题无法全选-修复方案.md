# 灵感编辑页「标题无法全选」修复方案

> 文档状态：待评审（先给方案，确认后再改源码）
> 关联代码：
> - `app/src/main/java/com/corgimemo/app/ui/screens/inspiration/InspirationEditScreen.kt`（标题编辑器 + 父容器）
> - `compose-rich-editor/richeditor-compose/src/commonMain/kotlin/com/mohamedrejeb/richeditor/model/RichTextState.kt`（选区/setText 机制）

---

## 一、问题根因（已定位）

标题「无法全选」由两层问题叠加：

### 主因：标题处于 `verticalScroll` 滚动容器，选区手势被吞
- 标题 `RichTextEditor` 的直接父容器是 `InspirationEditScreen.kt:1428-1436` 的
  `Column(..., .verticalScroll(rememberScrollState()))`。
- `RichTextEditor` 底层是 `BasicTextField`，其"长按→出选区手柄→拖拽扩展选区"依赖
  `TextFieldSelectionManager` 的指针手势；同一子树上的 `verticalScroll` 也在抢占竖向拖拽，
  **长按手势常被滚动容器抢走**，选区建立不起来，自然点不出"全选"。
- 这是 Compose 中 `TextField` 嵌在 `scrollable` 容器内的经典坑。标题位于滚动起点，最先暴露。

### 次因（隐患）：双向 `LaunchedEffect` 同步里的 `setText` 会折叠选区
- 标题用两个 `LaunchedEffect` 把编辑器和 ViewModel 双向绑死（`InspirationEditScreen.kt:1463-1477`）：
  ```kotlin
  LaunchedEffect(title) {
      val currentText = titleRichTextState.annotatedString.text
      if (currentText != title) {
          titleRichTextState.setText(title)   // ← 危险
      }
  }
  ```
- 库内 `setText(text)` 默认 `selection = TextRange(text.length)`
  （`RichTextState.kt:5418-5420`）——**一旦调用，选区被强制折叠到行尾**。
- 正文 `BodyBlocksEditor` 用 `snapshotFlow { Triple(annotatedString, selection, composition) }`
  观察器（`BodyBlocksEditor.kt:3216-3292`），**显式区分"纯选区变化"与"文本变化"，选区变化绝不调用 `setText`**，
  所以正文没有这个隐患。
- 纯"点击全选菜单项"那一下，标题同步本身有 `currentText != title` 守卫、不会触发 `setText`；
  但只要 `title` 在选区存续期间因任何外部原因被重发（如 `loadInspiration` 回填、语音输入
  `setTitle` 在 `InspirationEditScreen.kt:904`），`LaunchedEffect(title)` 就会跑 `setText`，把刚建立的选区瞬间清零。
  这条链路是"选区一旦建立就可能被立即折叠"的隐患，与主因相互放大。

### 为什么不是库的问题
已核实库层选区处理正确：`updateTextFieldValue` 对"纯选区变化且无背景色 span"走
`textFieldValue = tempTextFieldValue`（`RichTextState.kt:2610-2631`，标题是纯文本、
`treeHasBackgroundSpans()` 返回 `false`）；`updateAnnotatedString` 也用
`newTextFieldValue.selection` 原样保留选区（`RichTextState.kt:2908-2911`）。病在**应用层同步写法**。

## 二、修复方案（两处联动）

### 修复 1（针对主因）：选区展开时临时关闭父容器滚动
让"用户正在选择"期间的竖向拖拽只服务于选区扩展，不被 `verticalScroll` 吞掉。

**思路**：监听 `titleRichTextState.selection.collapsed`，当选区**展开**（正在选择）时，
把父 `Column` 的 `verticalScroll(enabled = ...)` 临时置为 `false`；选区收起即恢复滚动。

`selection` 是通过 `mutableStateOf` 的 `textFieldValue` 暴露的（`RichTextState.kt:233-237`），
在组合中读取即可随选区变化触发重组。

**改动点**：`InspirationEditScreen.kt` 标题区附近（约 `1457` 行起，需先取得 `titleRichTextState`）与
父 `Column`（约 `1436` 行）。

```kotlin
// 1) 在标题 titleRichTextState 创建后，取一个可观察的"是否正在选择"
val titleIsSelecting by remember(titleRichTextState) {
    derivedStateOf { !titleRichTextState.selection.collapsed }
}

// 2) 父 Column 的 verticalScroll 按选择态开关
Column(
    modifier = Modifier
        .fillMaxSize()
        .padding(innerPadding)
        .background(contentBackgroundColor)
        .padding(horizontal = 8.dp)
        // 正在选择标题时关闭滚动，避免选区手势被滚动容器吞掉；选区收起即恢复
        .verticalScroll(rememberScrollState(), enabled = !titleIsSelecting),
) { ... }
```

**收益**：长按标题可正常出选区 + 浮动工具栏（含"全选"）；拖拽选区手柄可扩展/收缩；
选区收起后页面恢复滚动。改动极小、风险低。

**取舍**：选择期间页面不能滚动——属合理权衡，且点空白处选区即收起、滚动恢复。

---

### 修复 2（针对次因）：把标题同步改成"选区零干扰"的快照式
对齐 `BodyBlocksEditor` 的 `snapshotFlow` 思路：文本变化才上送 ViewModel；
下拉同步（`title` → state）仅在**选区折叠**时调用 `setText`，绝不折叠用户正在进行的选区。

**改动点**：替换 `InspirationEditScreen.kt:1463-1477` 的两个 `LaunchedEffect`。

```kotlin
// 上行：state → ViewModel，仅文本变化才上送（天然不碰选区）
LaunchedEffect(Unit) {
    snapshotFlow { titleRichTextState.annotatedString.text }
        .collect { text ->
            if (text != title && !isLocked) {
                viewModel.setTitleWithRecommendation(text)
            }
        }
}

// 下行：ViewModel → state，仅当文本真的不一致、且用户当前没有正在选择的选区时才 setText
//       （loadInspiration / 语音回填时选区是折叠的，正常写入；选择期间绝不打扰）
LaunchedEffect(title) {
    val currentText = titleRichTextState.annotatedString.text
    if (currentText != title && titleRichTextState.selection.collapsed) {
        titleRichTextState.setText(title)
    }
}
```

**要点**：
- `snapshotFlow { annotatedString.text }` 只关心文本，选区伸缩不会触发上送，避免无谓的 `setTitleWithRecommendation` 回环。
- 下行 `LaunchedEffect(title)` 增加 `selection.collapsed` 守卫：用户正在框选标题时，即使 `title` 因外部原因重发，也不会用 `setText` 把选区折叠到行尾。
- 仍保留"文本真不一致才写回"的 `currentText != title` 守卫，避免自我回环。

## 三、自验证清单（改完后逐项核对）

1. 长按标题 → 出现选区 + 浮动工具栏含"全选"。
2. 点"全选" → 整段标题高亮，且**不**被瞬间折叠。
3. 拖拽选区两端手柄 → 选区可扩展 / 收缩，页面在此期间不滚动。
4. 点空白处收起选区 → 页面竖向滚动恢复正常。
5. 正常输入标题 → `viewModel.title` 实时同步、存档正确。
6. 编辑中触发语音输入 / `loadInspiration` 回填标题 → 不破坏用户正在进行的选区。
7. 正文（BodyBlocksEditor）选区/全选行为不受影响（回归）。
8. 标题外长文区竖向滚动正常（回归）。

## 四、风险与回退

- 修复 1 仅改滚动 `enabled` 开关，无数据/逻辑风险；如验证不佳，删除 `enabled` 参数即可回退。
- 修复 2 保持原有双向同步语义，仅加守卫，不改变"文本变化即同步"的既有行为；如验证不佳，
  还原为原两个 `LaunchedEffect` 即可。
- 两处改动相互独立，可分别落地、分别回退。
