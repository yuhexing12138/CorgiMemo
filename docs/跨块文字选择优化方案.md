# 灵感编辑页「跨块文字选择」优化方案

> 调研日期：2026-09-11（同日实现落地）
> 涉及文件：`app/src/main/java/com/corgimemo/app/ui/screens/inspiration/components/BodyBlocksEditor.kt`
> 目标：支持用户在灵感编辑页中**跨多个文本块连续选取文字**（此前只能在单个块内选）。
> **已确认决策**：触发方式 = 长按拖拽跨块（方案 A）；操作范围 = 复制 + 剪切 + 全选 + 保留富文本。

---

## 1. 现状与根因

### 1.1 现状

- 编辑页正文由 `BodyBlocksEditor` 以 `BlocksReorderableColumn` 渲染，**每个文本块是一个独立的 `RichTextEditor`**（`com.mohamedrejeb.richeditor.ui.material3.RichTextEditor`，底层是 `BasicTextField`）。
- 在 `BlockTextItem`（约 3786 行起）里，每块持有自己的 `RichTextState`（`BodyBlock.Text.state`）。
- Android 的文字选择（蓝色高亮 + 两端拖拽手柄 + 浮动工具条：复制/全选/翻译）是 **`BasicTextField` 内部机制**，选区范围被锁定在「这一个 `TextField` 的 `AnnotatedString`」内。
- 因此：手指在某块里长按选词、拖动扩选，一旦手柄拖到块上下边界外，**原生选择无法越界**——这就是「不能跨块选」的根因。

### 1.2 已有两套「选中」需区分，避免混淆

| 机制 | 字段 | 用途 | 与本次需求关系 |
|---|---|---|---|
| 块级选中（点选高亮） | `controller.highlightedBlockId` / `highlightedTapX` | 点击/两步删除时高亮整块（图片、分割线、删除） | **无关**，是「整块」不是「文字」 |
| 原生文字选择 | `RichTextState.selection` | 单块内选词/复制 | 本次要**在其之上扩展** |

> 结论：跨块选择不能依赖原生 `BasicTextField` 选择，必须新增一套**自定义跨块选区层**，与原生单块选择并存（单块内复制照旧可用）。

---

## 2. 方案总览

新增一个**全局跨块选区模型** + **每块的布局注册表** + **一块透明拖拽手势层** + **按行矩形绘制的高亮**，不与现有单块选择冲突。

### 2.1 数据模型（加在 `BodyBlocksController`）

```kotlin
/**
 * 跨块选区：起点与终点各自是「块 id + 块内字符偏移」。
 * start 在文档顺序上必须 ≤ end（越界时由控制器归一化）。
 */
data class CrossBlockSelection(
    val startBlockId: String,
    val startOffset: Int,
    val endBlockId: String,
    val endOffset: Int,
)

/** 控制器新增状态：null = 未进入跨块选择 */
var crossSelection by mutableStateOf<CrossBlockSelection?>(null)
    private set
```

### 2.2 每块布局注册表（命中测试用）

`BlockTextItem` 在组合期把本块的测量信息回传给控制器，供全局手势层做「指针坐标 → (blockId, offset)」命中：

```kotlin
/**
 * 单块文本布局快照：用于跨块选择的全局命中测试与高亮绘制。
 * - layoutResult：本块 TextLayoutResult（getBoundingBox/getLineForOffset）
 * - topLeftInWindow：块文本区左上角在窗口坐标系的位置（onGloballyPositioned.positionInWindow）
 * - textLength：有效文本长度（剥 ZWSP 后，跨块拼接用）
 */
data class BlockLayoutInfo(
    val blockId: String,
    val layoutResult: TextLayoutResult,
    val topLeftInWindow: Offset,
    val textLength: Int,
)
// 控制器持有：val blockLayouts = mutableStateMapOf<String, BlockLayoutInfo>()
```

## 3. 交互触发（已确认：方案 A，长按拖拽跨块）

**实现口径**（v2 修订，见 §8）：不拦截原生手柄，而是**自定义长按拖拽手势从 0 开始建立选区**——

- 跨块手势挂**编辑器根 Box（父容器）**的 modifier 上，用 `PointerEventPass.Initial` **先于所有子级观察**事件（v1 的全屏透明覆盖层兄弟节点实测会干扰子级手势检测，已废弃）；
- 观察阶段（未长按）**零消费**：短按（定位光标）、slop 内位移（滚动）、slop 外位移（原生单块选词/块拖拽排序）全部照常到达子级，行为与"没有这个手势"完全一致；
- 按住超过系统长按阈值 → 全局命中测试找到锚点文本块 → `startCrossSelection` 启动跨块选区（内部折叠原生光标、收起系统浮动工具栏），此后**在 Initial pass 消费所有 move/up**——子级在 Main pass 看到 isConsumed 自动退出，原生选择不会扩展，两套选区不打架；
- 拖动中终点持续跟随手指命中点（跨块自动延伸、整块全亮），抬指定格并**弹出系统文本工具栏**（复制/剪切/全选）。

**手柄区排除**：长按点落在编辑器内容区左缘之左（拖拽手柄/复选框区）不启动选择，块拖拽排序手势正常接管。

> 原方案 A 的"接管原生手柄"路线（风险最高）未采用；此处为等价体验的稳妥实现：长按拖拽的手感一致，但选区引擎从头到尾都是自定义层，无 hack。

## 4. 实现要点（已按此落地）

### 4.1 高亮绘制（每块本地画）

`BlockTextItem` 的 `RichTextEditor` modifier 链上挂 `drawBehind`：

- `controller.localRangeInBlock(selection, blockId, textLength)` 计算本块本地范围 `[start, end)`（起点块取尾部、终点块取头部、中间块整块、所有偏移 clamp 防越界）；
- `getLineForOffset` + `getBoundingBox` / `getLineLeft/Right/Top/Bottom` 逐行取矩形，画半透明蓝（`#4285F4 @ 20%`）；
- 坐标系校准：布局快照的 `topLeftInWindow` = 编辑器外框左上角 + `BLOCK_CONTENT_PADDING`(16dp) 水平偏移（= 文本排版原点），绘制时同量加回——命中与绘制同系。

### 4.2 布局快照与命中测试

- `BodyBlock.Text` 块在 `onTextLayout` / `onGloballyPositioned` 时向 `controller.blockLayouts`（`mutableStateMapOf`）上报 `BlockLayoutInfo(layoutResult, topLeftInWindow, textLength)`；`DisposableEffect` 卸载时 `unregisterBlockLayout`；
- `controller.hitTestCrossSelection(windowPoint)`：y 命中块内 → `getOffsetForPosition` 精确定位（x 超行宽自动取行端）；y 在缝隙/图片/分割线上 → 取纵向最近文本块、按中心线上下取块首/块尾。

### 4.3 选区操作（复制 / 剪切 / 全选）

- **复制（富文本优先）**：`getSelectedRichText()` 按文档顺序 `annotatedString.subSequence` 逐块拼接（块间 `\n`，SpanStyle 保留），空块 ZWSP 片段跳过；无样式内容退化 `getSelectedPlainText()`（剥 ZWSP）。写入 `ClipboardManager.setText(AnnotatedString)`（Compose Android 实现同时携带 plain + html，粘贴保样式）；
- **剪切**：对每个受影响文本块 `removeTextRange(本地范围)`（库内自动记 history）。删除前把光标**折叠到块尾**——`backspaceMerge` 判据是"删除前 selection 折叠在 0"，块尾折叠不满足，避免"恰好删了块首字符"被 observer 误判成块首退格而触发合并。v1 语义：只删文字、不删不合并被包住的整块（删空块走 ZWSP 不变量回空块，结构稳定）；
- **全选**：首个文本块块首 → 末个文本块块尾。

### 4.4 与现有机制共处

- **打字即退出**：内容 observer 检测"文本变长"时与块级选中一起 `clearCrossSelection()`；
- **按下/焦点切换即退出**：`onTextBlockPressed` / `onBlockFocused` 均清跨块选区（长按启动路径时序在前，不误伤）；
- **块级选中不重叠**：`startCrossSelection` 先 `clearBlockSelection()`；
- **锁定态**：`isLocked` 不挂手势层，行为与旧版一致。

## 5. 已知限制与后续优化

1. **v1 未渲染拖拽手柄**：长按锚点即起点、拖动即终点，暂无独立的起/终手柄（可后续按 `blockLayouts + getBoundingBox` 补两个可拖圆点）。
2. **拖出可视区不自动滚动**：手势层未接入滚动容器自动滚；长文档跨屏选择需分两次。
3. **剪切不删被包住的整块**（含图片/分割线）：结构稳定优先；如需"整段删除"语义，后续扩展为 CompositeCommand 原子操作。
4. **长按瞬间原生选词可能闪现一帧**：启动选区时已折叠原生光标 + 收起浮动工具栏，但框架内部长按处理在同一时序窗口，极短闪烁概率存在。
5. **性能**：命中测试每帧遍历 `blockLayouts`（O(块数)），常驻 Column 布局下块数有限，实测无压力；若未来改 lazy 列表需配合可见块注册。

## 8. v2 改造：手势挂接重构 + 操作入口并入系统文本工具栏（2026-09-11 同日）

v1 实装后真机实测暴露两个问题，全部返工修复：

### 8.1 踩坑：全屏透明覆盖层（兄弟节点）干扰子级手势

**现象**：正文区**所有点击全部失效**（含图片块点击选中），只有编辑区外的标题行正常；长按跨块选择本身能启动，但弹出的自建工具条按钮**也点不到**。

**v1 结构**：`CrossBlockSelectionLayer`（`matchParentSize` 透明 Box + `pointerInput` Main pass 常驻 await）作为块列表的**后组合兄弟节点**盖在上方。理论上"不消费即穿透"，实测该结构下子级手势检测被整体干扰。

**v2 结构**：手势改为挂**编辑器根 Box（父容器）** 的 modifier（`rememberCrossBlockSelectionGesture` 返回 Modifier），用 **`PointerEventPass.Initial`** 观察：

- Initial pass 父容器**先于所有子级**看到事件，观察阶段零消费 → 子级行为与"没有这个手势"完全一致（点击聚焦/滚动/原生选择全部恢复）；
- 长按达成后（`started`）在 **Initial pass 消费** move/up → 子级在 Main pass 看到 `isConsumed` 自动退出，比 v1 的 Main pass 消费语义更干净；
- 多指安全：内循环按 `downChange.id` 只跟踪发起手指。

> 教训：**Compose 里"全局手势观察"挂父容器 + Initial pass 是官方模式；全屏兄弟覆盖层常驻 await 在实测中会破坏子级手势，禁止再用。**

### 8.2 工具栏改造：废弃自建工具条，操作入口并入系统 TextToolbar

**要求**：不要新建"复制/粘贴"工具栏，在现有系统文本工具栏上改造。

**v2 实现**：

- 删除自建 `CrossBlockSelectionToolbar`（复制/剪切/全选/取消白胶囊）及相关常量、组件；
- 抬指定格后**主动调用 `textToolbar.showMenu(rect, ...)`**：`onCopyRequested` / `onCutRequested` / `onSelectAllRequested` 接控制器跨块操作，`onPasteRequested = null`（粘贴走块内原生光标）——系统工具栏只显示对应非 null 项，原生样式与行为；
- rect 契约是**窗口坐标**：选区终点末字符包围盒（`getBoundingBox` + `topLeftInWindow`），空块退化为块左上角点矩形；
- 工具栏随装饰链（`ImagePasteTextToolbar`）自动带上「粘贴图片」入口（剪贴板有图时）；
- **收起时机**：主动 `showMenu` 的工具栏不随焦点迁移自动消失 → 控制器新增 `onCrossSelectionCleared` 回调，`clearCrossSelection()`（点击别处/打字/复制/剪切）时由编辑层 `SideEffect` 接线 `textToolbar.hide()`；只在真清除了状态时触发，避免干扰原生菜单。

### 8.3 v2 验证清单增补

- [ ] 正文区点击任意文本块 → 光标聚焦、软键盘弹出（v1 回归已修复的判据）。
- [ ] 点击图片块 → 选中高亮 + 浮动工具栏照常。
- [ ] 长按拖拽跨块 → 抬指后弹出**系统样式**工具栏（复制/剪切/全选），无自建胶囊条。
- [ ] 点击"复制/剪切"后系统工具栏收起；点击正文别处也已收起。
- [ ] 剪贴板有图片时，跨块工具栏旁同时出现「粘贴图片」入口（装饰链自动生效）。

### 8.4 v3 统一选区：高亮色并入原生 + 全选重定向（2026-09-11 同日）

v2 实装后用户以 4 张截图反馈「两套不同的全选系统在工作」：

| 入口 | 现象 | 视觉 |
|---|---|---|
| 点击光标水滴 → 原生工具栏「全选」（图一→图二） | 只高亮第一行（**单块**全选，原生机制天花板） | 原生橙色 ✓ |
| 长按 → 跨块工具栏「全选」（图三→图四） | 三行都高亮（**跨块**语义正确） | 自绘淡灰蓝 `#4285F4@20%` ✗ |

**用户结论**：要图二的**高亮视觉**（原生橙）+ 跨块的**全选语义**（选中所有块内容），且拖拽跨块选取保留。v3 三处改造：

#### 8.4.1 高亮颜色统一：读原生 `LocalTextSelectionColors`

- `BlockTextItem` **组合期**读取 `val selectionHighlightColor = LocalTextSelectionColors.current.backgroundColor`，drawBehind 闭包捕获局部值（**draw 阶段不能读 CompositionLocal**，必须组合期下沉）；
- 该值与实际渲染色相等的依据（自举链）：库 `RichTextEditor.kt:140` 给 `RichTextEditorDefaults.colors` 的 `selectionColors` 默认参数就是**读同一个 CompositionLocal**——外层没显式 provide 时读到的就是同值 → `BlockTextItem` 与编辑器同层读取即原生橙色本身；
- 替换掉自绘 `Color(0xFF4285F4).copy(alpha = 0.20f)`，从此跨块高亮与原生单块选区**永远同色**（主题/应用换色自动跟随）。

#### 8.4.2 原生工具栏「全选」重定向为跨块全选

- `ImagePasteTextToolbar` 装饰器新增构造参数 `onCrossBlockSelectAll: (() -> Unit)? = null`；`showMenu` 内 `onSelectAllRequested` 非 null 时包装：`{ hide(); onCrossBlockSelectAll() }`（参数 null 时原样透传）；
- 灵感页接线 `onCrossBlockSelectAll = { bodyBlocks.selectAllCrossBlock() }`；**待办页不传（保持 null）** → 原生全选行为不变，重定向只作用于灵感编辑页；
- 包装里先 `hide()` 再触发：全选后弹出的应是跨块工具栏（见下），不能残留原生菜单。

#### 8.4.3 全选统一走跨块路径 + 自动弹工具栏

- `selectAllCrossBlock()` 末尾新增两步：① **折叠所有** Text 块的原生 selection（`TextRange(min)`）——防「原生高亮 + 跨块高亮」两套视觉并存（即图二/图四并存的根因）；② invoke 新增钩子 `onCrossSelectionToolbarRequested`；
- 编辑层 `SideEffect` 接线该钩子 → `showCrossBlockToolbar()`：全选完成后自动弹出/刷新跨块工具栏（复制/剪切/全选），锚点矩形按选区终点重算；
- 由此**任何入口的全选**（原生工具栏重定向 / 跨块工具栏自身「全选」按钮）都汇入 `selectAllCrossBlock` 这一条路径，工具栏自动弹出或刷新位置；
- `startCrossSelection`（长按拖拽启动）同样折叠所有块的原生 selection，拖拽扩选期间原生高亮不再残留。

### 8.5 v3 实测反馈两问题：手柄跨块接管 + 全选工具栏竞态（2026-09-11 第三轮）

v3 真机实测（用户截图）暴露两个问题：

1. **拖原生选择手柄只能在块内拖**：橙色水滴手柄是 `BasicTextField` 原生机制，选区天花板就是
   单块文本；v3 的跨块入口只有「长按直接拖」，用户习惯的「长按选词 → 拖手柄扩选」完全走原生
   路径，无法越块。
2. **原生工具栏点「全选」后跨块工具栏不弹**：接线链路（重定向 → `selectAllCrossBlock` → 钩子 →
   `showCrossBlockToolbar` → `showMenu`）代码齐全，问题在时序。

#### 8.5.1 原生手柄热区接管（拖手柄升级为跨块拖拽）

- 手势层 Initial pass 的「未启动」分支**优先**检测：按下点是否落在某块**非折叠**原生选区的
  起点 / 终点手柄热区内（`NATIVE_HANDLE_HIT_RADIUS` = 28dp；锚点 = 选区首字符包围盒左下 /
  末字符包围盒右下，均换算到窗口坐标）；
- 命中**立即升级**（不等长按阈值）：`startCrossSelection(块, 选区对端)`——拖终点手柄 → 锚 =
  选区开头；拖起点手柄 → 锚 = 选区结尾（往回拖由 normalize 自动换向）；内部折叠所有原生
  selection，原生手柄随之消失、跨块高亮无缝接管；
- 后续 move 在 Initial pass 消费 → 原生手柄拖拽在 Main pass 看到 isConsumed 自动放弃——
  与长按路径**同一套接管机制**，零新增风险面；
- 折叠光标的水滴手柄（移动光标）**不接管**，保持原生。

#### 8.5.2 全选弹工具栏延迟 150ms（避开 ActionMode 收起竞态）

- **根因**：全选回调执行在系统菜单 `onActionItemClicked` 调用栈**内**——回调返回后系统还要
  `mode?.finish()` 收起原生菜单；立即弹出的跨块菜单与这次收起走同一 ActionMode 通道，
  新菜单刚弹即被波及收走。
- **实现**：钩子接线改 `requestCrossBlockToolbarDeferred()`——专用 `Handler(Looper.getMainLooper())`
  `postDelayed` 150ms（`removeCallbacksAndMessages(null)` 防连续触发重入）；长按拖拽抬指路径
  无此竞态，保持**立即弹**；
- **防误弹**：150ms 窗口内若选区被清除，延迟回调里 `crossSelection == null` 早退，不会空弹。

#### 8.5.3 v3 第三轮验证清单

- [ ] 长按选词出原生手柄 → 拖任一手柄 → **跨块**延伸，高亮橙色（原生同色）。
- [ ] 原生工具栏点「全选」→ 所有块高亮 → 约 150ms 后跨块工具栏出现且**不闪没**。
- [ ] 跨块工具栏再点「全选」→ 工具栏刷新不消失。
- [ ] 折叠光标水滴拖动 = 移动光标（原生行为，未被接管）。
- [ ] 长按直接拖（原有路径）照常；点击别处/打字退出照常。

### 8.6 第三轮实测反馈：跨块手柄补齐 + 接管修正 + 长按选词优先（2026-09-11 第三轮+）

用户三点反馈：① "长按直接拖"无独立手柄、两端微调只能重新长按（§5 遗留限制 1 的遗留项）；
② "长按选词 → 拖手柄扩选"**仍然**无法跨块（8.5.1 修正未生效）；③ **长按选词永远优先**，
不要误触"长按直接拖"。

#### 8.6.1 手柄接管失效的两个根因与修正（问题 2）

- **热区锚点偏移**：原生水滴球体在字符包围盒**下方约 20dp**（尖端贴文本、球体朝下），
  8.5.1 把热区锚定在包围盒 bottom 本身——手指按在球体上距锚点已接近 28dp 边缘，经常够不到。
  修正：热区圆心下沉 = 包围盒 bottom + `CROSS_HANDLE_DROP`(16dp) + `CROSS_HANDLE_RADIUS`(7dp)，
  与自绘手柄圆点圆心**完全一致**；
- **观察循环提前退出**：长按选词后不抬手直接拖手柄，位移超 touchSlop 时旧逻辑**先一步
  break 放弃观察**——接管检测根本没机会跑。修正：接管检测收敛为两个时机——① down 捕获后
  立即（按住手柄再拖）；② 位移超 slop 时兜底（先试接管，不命中才 break）；
- 接管帧立即延伸 + 消费：观察/延伸从 `if/else` 改为两个独立 `if`——接管当帧即消费事件，
  原生手柄拖拽一帧都拿不到。

#### 8.6.2 跨块选区自绘手柄（问题 1）

- 新增 `CrossBlockSelectionHandles`：编辑器根 Box 内 `matchParentSize` 的**纯绘制 Canvas**
  （不参与事件）——竖线（包围盒 bottom → 下沉）+ 实心圆点，色取
  `LocalTextSelectionColors.current.handleColor`（与原生手柄**同源同色**、主题自动跟随）；
- 锚点计算 `crossHandleBase(info, offset, isStart)` 文件级私有函数，绘制与热区**共用同一
  计算** → 「画在哪就能拖哪」；
- 拖动复用手柄接管通道：按跨块手柄 = `startCrossSelection(选区对端)` + 拖动延伸 →
  端点微调 / 跨块重选，抬指定格弹工具栏（全复用现有路径）；
- 生命周期：`crossSelection == null` 或起/终点布局快照缺失 → 不绘制（自动隐藏）。

#### 8.6.3 长按选词永远优先（问题 3）

- 长按兜底启动加 **300ms 让位窗口**（`longPressTimeout + CROSS_LONGPRESS_GRACE_MS ≈ 800ms`
  才动手），启动前检查 `anyNativeSelectionActive()`——任一文本块原生 selection 非折叠
  （选词已发生）→ **不启动也不退出**（继续观察，用户拖原生手柄由时机②接管）；
- 正文长按的实际体验收敛为：原生选词永远先完成（约 500ms），跨块启动 = 「选词 → 拖手柄」
  （原生手感）+ 长按非文本区（图片/空隙，选词不会发生）兜底。

#### 8.6.4 验证清单

- [ ] 长按正文选词 → 拖任一原生手柄 → **跨块**延伸、橙色高亮（不抬手直接拖 + 抬手再按拖两条路径都验）。
- [ ] 长按正文不拖 → 出现的是**原生选词**（手柄 + 词高亮），跨块选择绝不抢启动。
- [ ] 跨块选区两端出现自绘圆点手柄（色同原生手柄）→ 按住拖动可微调端点 / 跨块重选。
- [ ] 全选后两端手柄在首块块首 / 末块块尾，拖动有效。
- [ ] 复制/剪切/取消/点击别处收起照常。

### 8.7 第三轮++：收编机制取代事件接管 + 手柄复用原生水滴样式（2026-09-11）

> ⚠️ **本节方案已废弃（2026-09-11 同日）**：收编机制 + 贝塞尔水滴手柄实施后经用户评估
> 全部回退（"别手绘拖拽手柄"）。本节仅保留作决策过程记录，**与当前代码不符**。
> 替代方案见 §8.8（选区本体拖动延伸）。§8.7.1 的根因结论（手柄是独立 Popup）
> 依然有效，且已被库内注释二次印证（`RichTextState.kt:682`）。

用户实测 8.6 后反馈：① 拖原生手柄**仍**不能跨块（不抬手/抬手两条路径均失败）；② 跨块
手柄要求**完全复用原生样式**。

#### 8.7.1 根因实锤：原生手柄是独立 Popup，事件级接管原理上不可行

8.6.1 的两个修正（热区下沉 / slop 兜底）仍未生效——排查确认真正根因：**Compose 文本选择
手柄渲染在独立 Popup 窗口**，触摸事件直接派发给 popup 自身、**不进入编辑器 Compose 事件
流**——父容器 Initial pass 收不到按在手柄上的 down。故"检测 down 是否落在原生手柄热区"
从原理上不可行（热区大小、检测时机都不是症结），`tryStartFromNativeHandle` 的原生手柄段
删除（改名 `tryStartFromCrossHandle`，只保留跨块自绘手柄段——自绘手柄画在编辑器内、
事件可见可拦截）。

#### 8.7.2 替代机制：原生选词结果「稳定窗口收编」

- 主函数 `LaunchedEffect(isLocked)` + `snapshotFlow` 监听所有 Text 块的原生 selection：
  出现非折叠选区（长按/双击选词完成）且跨块选区未激活 → 延迟
  [NATIVE_SELECTION_ADOPT_DELAY_MS](200ms) → 复核选区未再变化（稳定）→ 调用
  `adoptNativeSelectionAsCross(blockId, range)` 收编；
- **收编** = 把选词结果设为跨块选区 + 折叠所有原生 selection + 弹跨块工具栏（deferred）；
  视觉无缝（高亮同色、手柄同款），用户拖自绘水滴即可跨块延伸；
- **拖动扩选不打断**：拖原生手柄扩选中 selection 持续变化 → 每次变化重新进入 collect、
  delay 后复核值已变则放弃 → 停止拖动 200ms 后才收编；
- 收编后原生折叠 → snapshotFlow 发射 null → collect 无操作，无循环；
- 已知差异（记录备查）：原生选词后**立即打字**是"替换选区"，收编后为在起点插入。

#### 8.7.3 手柄视觉：原生水滴样式

- `CrossBlockSelectionHandles` 的手柄由"竖线 + 圆点"改为**贝塞尔水滴**：尖端贴文本
  底线、球体朝下（球心 = bottom + 16dp、球半径 10dp），左右两翼收腰曲线与原生手柄
  形状对齐；色仍取 `LocalTextSelectionColors.current.handleColor`（同源同色）；
- 热区圆心同步为**球心**（bottom + 16dp），半径 28dp 完整覆盖水滴；
- 锁定态防御：手柄不绘制、收编机制不生效（`LaunchedEffect(isLocked)` 以锁定态为 key，
  避免闭包捕获过期值）。

#### 8.7.4 验证清单

- [ ] 长按正文选词 → 约 200ms 后选区自动变为跨块选区（视觉无缝：同色高亮 + 水滴手柄）。
- [ ] 拖自绘水滴手柄 → **跨块**延伸（这是唯一的手柄跨块路径——原生手柄 Popup 机制限制）。
- [ ] 长按选词后拖原生手柄扩选 → 拖动中不被打断；停下约 200ms 后收编为跨块选区。
- [ ] 手柄形状/颜色与原生选择手柄一致（水滴、同色）。
- [ ] 收编后工具栏为跨块版（复制/剪切/全选）；复制/剪切/取消/点击别处照常。
- [ ] 待办页不受影响（收编机制仅灵感编辑页）。

### 8.8 方案 I：选区本体拖动延伸（2026-09-11 第四轮，替代 §8.7）

**背景**：§8.7 回退后转向调研库 `compose-rich-editor` 的现成跨块能力——结论
**没有**（`selection` 单一 TextRange、无跨实例模型、公共 API 全部单块；库内注释
自证手柄是独立 Popup）。完整信号链分析与方案对比见
`docs/跨块选择-库层钩子能力评估与方案.md`。用户拍板**方案 I：选区上按压拖动延伸**
（跟手、零手绘、原生手柄原样保留、几乎不改库）。

**交互设计**：
- 长按选词 → 抬手 → **再按在选区文字上并拖动**（位移超 slop）→ 接管为跨块延伸，
  跟手；轻点选区永不接管（原生弹工具栏照常）；
- **动端映射与手柄拖动同构**：按压点在选区覆盖字符**中点之前** = 调「起点」
  （锚 = 结尾端）；后半 = 调「终点」（锚 = 开头端）；反向延伸由 normalize 自动换向；
- 范围判定：hit 块序不早于起点块（同块 offset ≥ startOffset）且不晚于终点块
  （同块 offset ≤ endOffset）；中间非文本块整体视为在选区内；
- 接管优先级：原生/自绘手柄热区（`tryStartFromNativeHandle`）→ 选区本体
  （`tryStartFromSelectionBody`）→ 都未命中才放行（滚动/原生拖选照常）。

**代码落点**（`BodyBlocksEditor.kt`，均在 `rememberCrossBlockSelectionGesture`）：
1. 新增 `tryStartFromSelectionBody(downWindowPoint)`：范围判定 + 中点前/后半判定
   （遍历选区覆盖块累加字符数）+ `startCrossSelection` 定锚 + `textToolbar.hide()`；
2. 时机②（moved > slop）分支改为两级接管链（手柄热区 → 选区本体）。

**已知取舍**：接管占用「按在选区上滚动」——跨块选区激活期间想滚动页面需先点
空白取消选区（待实机反馈再调）。

**验证清单**：
- [ ] 长按选词 → 抬手 → 按住选区前半向上拖 → 起点端跨块向前延伸（跟手）。
- [ ] 按住选区后半向下拖 → 终点端跨块向后延伸（跟手）。
- [ ] 轻点选区 → 原生工具栏弹出，无接管。
- [ ] 拖原生手柄（块内微调）→ 原生行为，样式未变。
- [ ] 选区激活期间按住选区滚动 → 被接管为延伸（已知取舍，实测确认是否可接受）。
- [ ] 长按直接跨块拖选（原入口）、全选、复制/剪切/工具栏均不受影响。
