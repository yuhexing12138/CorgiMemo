在格式工具栏「加粗按钮 B」的左侧新增字体选择按钮。点击后收起软键盘，并在格式工具栏与「相机行」之间展开字体面板， 把带相机图标的那一行编辑栏向下推开，面板占据原键盘位置。面板内分两组网格预览：中文字体显示「刻记」，英文/数字字体显示「Corgi」，每行 4 块。 英文/数字组只列 3 款真实拉丁字体（无系统字体占位项），再次点击已选项可取消，回到英文/数字跟随中文字体的状态。

  • 字体按钮图标 Material Icons font_download（Icons.Default.FontDownload，字体语义最准；material-icons-extended 已引入）。原型右侧备选 4 个候选（font_download / text_fields / title / text_format）可点击对比。

  • 选中态写入 ContentFontManager（内容字体），与设置页「正文字体」（FontManager，仅 App chrome）互不影响
  • 面板头右侧 眼睛按钮 可 显示 / 隐藏预览块的字体名：隐藏后块高 66→44dp、预览字号放大（中文 22→26sp），一屏看更多、更利于逐块对比字形；隐藏时 hover 仍可看到字体名
  • 本次新增：在「字体按钮」与「加粗 B」之间插入 字号与颜色按钮（图标 4 选 1，见右侧切换器）， 点击后在同一槽位展开「字号 + 颜色」面板——与字体面板互斥、同高度，切换不跳动。 面板含三组：字号（8 档 12~32sp） / 颜色（12 色文字色板） / 自定义颜色（HSV 取色器）， 头部规格、网格列数、格子尺寸与字体面板完全一致。字号与颜色点选即时生效（写 SpanStyle），不做 pending「应用」两段式。

交互流程

  1. 用户点击 ⋮ → 格式工具栏展开
  2. 点击 字体按钮（B 左侧）→ 键盘收起，面板展开
  3. 面板把 相机行向下推（键盘让位 + 面板占位，位移 = 键盘高度）
  4. 点击预览块 → 选中并即时预览到正文（本原型可试）
  5. 点 完成 / 再次点字体按钮 → 面板收起
  6. 面板头 👁 眼睛按钮 → 显示/隐藏字体名（紧凑对比模式）
  7. 英文/数字组 再点已选项 → 取消，回到跟随中文
  8. 点 字号/颜色按钮（字体与 B 之间）→ 收键盘 + 展开字号颜色面板（与字体面板互斥）
  9. 字号 / 颜色均点选即时生效（无需「应用」），面板头右侧只保留「完成」收起

实现要点与待确认项

审核原型后确认以下要点，再改源码。

1. 源码改动落在哪几个文件？
RichTextFormatToolbar.kt（第一组新增字体按钮 + onFontPickerClick 参数）→ InspirationEditBottomBar.kt（Column 内格式工具栏与相机行之间插入面板 + 参数透传）→ InspirationEditScreen.kt（新增 isFontPanelExpanded 状态、收键盘、ContentFontManager.setContentFont()）→ 新建 FontPickerPanel.kt（网格 UI）。FontManager 不动（保持设置页 App chrome 通道）。
2. 拉丁（英文/数字）字体如何接入内容字体？
现有 ContentFontManager 只持单个 FontEntry，无拉丁回退层；而 FontManager 有 combinedFamily(cjk, latin)。需给 ContentFontManager 补 latinEntry + 组合逻辑 （或复用 FontManager.combinedFamily），否则选了英文/数字字体不会生效。
3. 字体选择的粒度：全局还是按灵感？
本原型按全局单例设计（ContentFontManager 一次设置，全 App 内容生效）。若要「每条灵感各自记字体」， 需落库字段（Room migration）+ 按 item id 取字体，改动量显著更大。请确认粒度。
4. 面板高度取多少？
建议 = 键盘高度（用 WindowInsets.ime 上次记录值），避免与键盘高度差过大造成跳动；内容用 LazyVerticalGrid 滚动。本原型取 388dp 是为一次看全 13 款，非最终值。
5. 预览块的「字体名」是否要显示？
本原型显示（10sp 灰色，便于识别与审核）。若想更极简，可去掉字体名、只留「刻记 / Corgi」字形预览， 块高可降至 48dp。请确认。
6. 字号 / 颜色如何写进正文？（项目目前完全没有这两项功能）
字号：走 RichTextState.toggleSpanStyle(SpanStyle(fontSize = 20.sp))； 颜色：走 toggleSpanStyle(SpanStyle(color = Color(0xFF…)))。当前值读取用 state.currentSpanStyle.fontSize / .color（对照现有 .fontWeight 用法）。
两个坑：① 源码 RichTextState.kt:1088-1093 写死 recordHistory(enabled = !selection.collapsed)——光标未选中文本时只改暂存样式、不进撤销栈，属库行为，需接受； ② 换值时必须先 removeSpanStyle 清旧值、再 toggleSpanStyle 设新值 （照抄 InspirationEditScreen.kt:1231-1238 的加粗写法），否则旧字号 / 旧颜色 SpanStyle 会叠加残留。
作用域：有选区 → 作用于选区；仅光标 → 作用于后续输入。
7. 新面板与字体面板的状态关系？为什么它只有「完成」没有「应用」？
新增 isSizeColorPanelExpanded，与 isFontPanelOpen 互斥（点开一个自动关掉另一个）； 两者插在 InspirationEditBottomBar Column 的同一位置，都用 AnimatedVisibility(expandVertically/shrinkVertically) + panelHeight = keyboardHeight， 因此同高、切换无跳动；展开时同样 keyboardController?.hide()。
刻意不做 pending「应用」：字体面板需要两段式是因为换字体要重建 Typeface（CJK 单文件 14~19MB，反复实时换必 OOM）； 而字号/颜色只是写 SpanStyle，成本极低，点选即生效反而更顺手，故面板头只保留「完成」收起。
8. 顺带发现的一处不一致（非本次需求，建议一并修）
InspirationEditScreen.kt:1132 清除字重时遍历的是 FontManager.currentEntry.value.boldTiers （设置字体），而工具栏探测（RichTextFormatToolbar.kt:142）用的是 ContentFontManager （内容字体）。两者一旦不同，会出现「按 B1 取消不掉加粗」的边界问题。建议统一为 ContentFontManager。
注：预览字体经 Google Fonts CDN 加载，离线时自动降级到系统字体栈（布局与交互不受影响）。
带 * 的为近似替代：源音黑體 / 獅尾半月字體 SC → Noto Sans SC，悠哉字体 → Klee One，初夏明朝體 → Shippori Mincho，Maple Mono → JetBrains Mono；App 内使用 res/font 真实字体文件。
