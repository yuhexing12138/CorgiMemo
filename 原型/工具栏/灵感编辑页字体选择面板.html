灵感编辑页 · 字体选择面板

在格式工具栏「加粗按钮 B」的左侧新增字体选择按钮。点击后收起软键盘，并在格式工具栏与「相机行」之间展开字体面板， 把带相机图标的那一行编辑栏向下推开，面板占据原键盘位置。面板内分两组网格预览：中文字体显示「刻记」，英文/数字字体显示「Corgi」，每行 4 块。 英文/数字组只列 3 款真实拉丁字体（无系统字体占位项），再次点击已选项可取消，回到英文/数字跟随中文字体的状态。

  • 推荐图标 Material Icons font_download（Icons.Default.FontDownload，字体语义最准；material-icons-extended 已引入）
  • 面板展开时 键盘必须收起，二者不同屏共存（避免双重占位挤压正文）
  • 面板高度建议 = 软键盘高度（Android 典型 291dp），内容超出时纵向滚动；本原型为便于一次审核全部分组，高度取 388px
  • 数据源：中文字体 FontCatalog.entries（10 款） + 英文/数字 FontCatalog.latinEntries（3 款）
  • 选中态写入 ContentFontManager（内容字体），与设置页「正文字体」（FontManager，仅 App chrome）互不影响
  • 面板头右侧 眼睛按钮 可 显示 / 隐藏预览块的字体名：隐藏后块高 66→44dp、预览字号放大（中文 22→26sp），一屏看更多、更利于逐块对比字形；隐藏时 hover 仍可看到字体名

  2. 点击 字体按钮（B 左侧）→ 键盘收起，面板展开

  5. 点 完成 / 再次点字体按钮 → 面板收起

实现要点与待确认项

审核原型后确认以下要点，再改源码。

1. 源码改动落在哪几个文件？
RichTextFormatToolbar.kt（第一组新增字体按钮 + onFontPickerClick 参数）→ InspirationEditBottomBar.kt（Column 内格式工具栏与相机行之间插入面板 + 参数透传）→ InspirationEditScreen.kt（新增 isFontPanelExpanded 状态、收键盘、ContentFontManager.setContentFont()）→ 新建 FontPickerPanel.kt（网格 UI）。FontManager 不动（保持设置页 App chrome 通道）。
2. 拉丁（英文/数字）字体如何接入内容字体？
现有 ContentFontManager 只持单个 FontEntry，无拉丁回退层；而 FontManager 有 combinedFamily(cjk, latin)。需给 ContentFontManager 补 latinEntry + 组合逻辑 （或复用 FontManager.combinedFamily），否则选了英文/数字字体不会生效。
3. 字体选择的粒度：全局还是按灵感？
本原型按全局单例设计（ContentFontManager 一次设置，全 App 内容生效）。若要「每条灵感各自记字体」， 需落库字段（Room migration）+ 按 item id 取字体，改动量显著更大。请确认粒度。
4. 面板高度取多少？
建议 = 键盘高度（用 WindowInsets.ime 上次记录值），避免与键盘高度差过大造成跳动；内容用 LazyVerticalGrid 滚动。本原型取 388dp 是为一次看全 13 款，非最终值。
5. 预览块的「字体名」是否要显示？
本原型显示（10sp 灰色，便于识别与审核）。若想更极简，可去掉字体名、只留「刻记 / Corgi」字形预览， 块高可降至 48dp。请确认。
6. 顺带发现的一处不一致（非本次需求，建议一并修）
InspirationEditScreen.kt:1132 清除字重时遍历的是 FontManager.currentEntry.value.boldTiers （设置字体），而工具栏探测（RichTextFormatToolbar.kt:142）用的是 ContentFontManager （内容字体）。两者一旦不同，会出现「按 B1 取消不掉加粗」的边界问题。建议统一为 ContentFontManager。
注：预览字体经 Google Fonts CDN 加载，离线时自动降级到系统字体栈（布局与交互不受影响）。
带 * 的为近似替代：源音黑體 / 獅尾半月字體 SC → Noto Sans SC，悠哉字体 → Klee One，初夏明朝體 → Shippori Mincho，Maple Mono → JetBrains Mono；App 内使用 res/font 真实字体文件。
