# 侧滑栏分组管理 / 状态管理统一多选+OR/AND/NOT+搜索框 实施计划

> **日期**：2026-07-28（v2 修订：统一为 1 个过滤集合 + 1 个 mode）
> **范围**：HomeViewModel、CategoryGroupSection、StatusFilterSection、AppDrawer（薄壳）、AppDrawerContentImpl、MainScreen
> **目标**：参考灵感页 `InspirationFilterSection` 的"多选 + OR/AND/NOT + 搜索框"模式，将待办页侧滑栏的"分组管理"和"状态管理"改造为**跨维度统一集合**（1 个多选 Set + 1 个 mode）

---

## Context（为什么做这次改动）

**现状**：

| 维度 | 灵感页标签筛选 | 待办分组管理 | 待办状态管理 |
|------|----------------|--------------|--------------|
| 选择模式 | 多选 `Set<String>` | **单选** `Long?` | **单选** `StatusFilter` |
| 组合模式 | OR / AND / NOT（TagFilterMode） | ❌ 无 | ❌ 无 |
| 搜索框 | ✅ OutlinedTextField（本地状态） | ❌ 无 | ❌ 无 |
| 拖拽闪烁修复 | ✅ Plan A + Plan D | ✅ Plan A + Plan D | ❌ **未修复** |
| 拖拽埋点 | ✅ ReorderableDiagnostics | ✅ 已接 | ❌ 未接 |

**问题**：

1. 待办分组只能"单选一个" → 用户想看"📁 工作 + 📚 学习"的待办时无法实现
2. 待办状态只能"单选一个" → 用户想看"置顶 + 已过期"或"已完成 + 重复提醒"时无法实现
3. 分组数量增多时无法快速定位 → 缺搜索框
4. 状态分区拖拽闪烁问题未修复 → 落后于其他 3 个分区
5. **跨维度组合缺失**：分组和状态是 2 个独立维度，无法混在一起多选+模式

**改造方向（用户已确认）**：

> - "全量借鉴（分组+状态都改多选+模式）" + "复用 TagFilterMode"
> - "AND 的意义在于既可以是分组里面的一项，也可以是状态管理里面的一项"
> - **"搜索"和"or/and/not"都支持"分组管理"和"状态管理"之间跨维度的组合**（v2 修订）
> - **统一为 1 个过滤集合 + 1 个 mode**（v2 决策）
> - **分组只有 OR/NOT，状态保留 3 种模式**（v2 决策）

**预期收益**：

- 与灵感页标签筛选**视觉和逻辑统一**（UI 一致性）
- **跨维度统一多选 + 模式**：分组项和状态项混选，1 个 mode 统一控制
- 状态管理拖拽闪烁问题**一并修复**（与 Plan A + Plan D 对齐）

## 总体设计（v2 跨维度统一集合）

### 核心抽象：FilterItem sealed class

```kotlin
/**
 * 待办侧滑栏统一过滤项（v2026-07-28 跨维度改造）
 *
 * 把"分组项"和"状态项"统一为一个 sealed class 集合，
 * 让用户可以跨维度多选（同时选中"工作"分组 + "置顶"状态），
 * 并用 1 个 OR/AND/NOT mode 统一控制组合方式。
 *
 * **AND 模式边界**：分组项在 AND 模式下被忽略（todo 只能属于 1 个分组），
 * 仅状态项参与 AND 组合。这是用户确认的语义。
 */
sealed class FilterItem {
    /** 分组项：id=0L 表示"未分类"，id>0L 表示具体自定义分组 */
    data class Category(val id: Long) : FilterItem()
    
    /** 状态项：仅 5 个非 ALL 的状态（PINNED/PENDING/COMPLETED/OVERDUE/REPEAT_REMINDER） */
    data class Status(val filter: StatusFilter) : FilterItem()
}
```

> **关键决策**：分组项的 `id=0L` 表示"未分类"（与现状 todo.categoryId==0L 一致）。
> **不包含**"全部待办"和"全部状态"——选中"全部"项时直接清空整个 `_selectedFilterItems`。

**新增 2 个工具函数**：

```kotlin
/** 单个 FilterItem 是否匹配某个 todo */
private fun matchesFilterItem(todo: TodoItem, item: FilterItem): Boolean = when (item) {
    is FilterItem.Category -> todo.categoryId == item.id  // 0L=未分类, >0L=具体分组
    is FilterItem.Status -> when (item.filter) {
        StatusFilter.PINNED -> todo.isPinned
        StatusFilter.PENDING -> !todo.isPinned && todo.status == 0
        StatusFilter.COMPLETED -> todo.status == 1
        StatusFilter.OVERDUE -> todo.status == 0 && MoodManager.isOverdue(todo.dueDate)
        StatusFilter.REPEAT_REMINDER -> todo.repeatType != 0
        StatusFilter.ALL -> true  // 不应出现（ALL 不作为多选元素）
    }
}

/**
 * 应用统一过滤（v2026-07-28 跨维度 v2）
 *
 * **OR 模式**：
 *   - 分组项内部 OR（属于任一选中分组）+ 状态项内部 OR（满足任一选中状态）
 *   - 跨维度 AND（同时满足分组和状态条件）
 *
 * **AND 模式**：
 *   - 分组项被忽略（todo 只能属于 1 个分组，AND 多个分组无意义）
 *   - 仅状态项内部 AND（同时满足所有选中状态）
 *
 * **NOT 模式**：
 *   - 分组项内部 NOT（不属于任何选中分组）+ 状态项内部 NOT（不满足任何选中状态）
 *   - 跨维度 AND（同时满足 NOT 分组和 NOT 状态条件）
 */
private fun applyFilterItems(
    todos: List<TodoItem>,
    selected: Set<FilterItem>,
    mode: TagFilterMode
): List<TodoItem> {
    if (selected.isEmpty()) return todos
    val categoryItems = selected.filterIsInstance<FilterItem.Category>()
    val statusItems = selected.filterIsInstance<FilterItem.Status>()

    return when (mode) {
        TagFilterMode.OR -> todos.filter { todo ->
            val catOk = categoryItems.isEmpty() || categoryItems.any { matchesFilterItem(todo, it) }
            val stOk = statusItems.isEmpty() || statusItems.any { matchesFilterItem(todo, it) }
            catOk && stOk
        }
        TagFilterMode.AND -> todos.filter { todo ->
            // AND 模式下分组项被忽略（按用户决策 D2）
            statusItems.isEmpty() || statusItems.all { matchesFilterItem(todo, it) }
        }
        TagFilterMode.NOT -> todos.filter { todo ->
            val catNotOk = categoryItems.isEmpty() || categoryItems.none { matchesFilterItem(todo, it) }
            val stNotOk = statusItems.isEmpty() || statusItems.none { matchesFilterItem(todo, it) }
            catNotOk && stNotOk
        }
    }
}
```

### 1. FilterItem sealed class（新增文件）

```kotlin
package com.corgimemo.app.viewmodel

/**
 * 待办侧滑栏统一过滤项（v2026-07-28 P8 跨维度改造新增）
 *
 * 背景：原 [_selectedCategoryId] 和 [_statusFilter] 是 2 个独立单选状态，
 * 分组和状态之间无法混选。v2 设计把两者统一为 [FilterItem] 集合，
 * 配合 1 个 [_filterMode] 实现跨维度多选 + OR/AND/NOT 组合。
 *
 * **为什么用 sealed class？**
 * - 类型安全：编译期保证只能添加 Category 和 Status 两类
 * - pattern match：`when (item) { is FilterItem.Category -> ... }` 无需 else 分支
 * - 易于扩展：未来可加 DateItem 等
 *
 * **AND 模式边界**：
 * 分组项（[FilterItem.Category]）在 AND 模式下被忽略
 * （todo 只能属于 1 个分组，多个分组 AND 退化为空集）。
 * 状态项（[FilterItem.Status]）在所有模式下都生效。
 *
 * @see HomeViewModel.applyFilterItems
 */
sealed class FilterItem {
    /**
     * 分组过滤项
     *
     * @param id 0L=未分类（与 todo.categoryId==0L 对齐），>0L=具体自定义分组 ID
     */
    data class Category(val id: Long) : FilterItem()
    
    /**
     * 状态过滤项
     *
     * 注意：[StatusFilter.ALL] 不应作为多选元素（选中 ALL = 全部 = 不过滤）。
     * UI 层在生成 [FilterItem.Status] 列表时跳过 ALL。
     */
    data class Status(val filter: StatusFilter) : FilterItem()
}
```

## 关键设计决策记录

### D1：是否保留旧单选 API 作为兼容层？

**决策**：**不保留**。全部统一改为 `toggleFilterItem` / `setFilterMode` / `clearAllFilters`。

**理由**：
- 改动范围可控（4 个 ViewModel 内部方法 + 2 个 MainScreen 调用点 + 1 个 topBarTitle）
- 旧 API 名称会误导
- 一次性切换更清晰

### D2：AND 模式下分组项如何处理？（v2 用户决策）

**决策**：**分组项在 AND 模式下被忽略，仅状态项参与 AND**。

**理由**：
- todo.categoryId 是单值，物理上无法同时属于多个分组
- AND 多个分组退化为空集是反直觉的
- 简化实现：applyFilterItems 中 AND 分支只处理 statusItems
- UI 表现：用户选 AND 模式时，分组项选中状态"失效"（不影响过滤结果），但不强制清空

### D3：选中"全部待办"/"全部状态"时如何处理？

**决策**：**清空整个 `_selectedFilterItems`**（不区分分组/状态，因为是统一的集合）。

**理由**：
- 与"全部"语义一致（选中 = 不过滤 = 空集合）
- 跨维度统一集合，不需要分别清空分组和状态

### D4：是否在 FilterItem.Status 中包含 `StatusFilter.ALL`？

**决策**：**不包含**。`StatusFilter.ALL` 是"不过滤"的语义，不作为多选元素。

**理由**：
- 与现状"选中 ALL = 不过滤"一致
- UI 层在生成 FilterItem.Status 列表时跳过 ALL
- 5 个非 ALL 状态项（PINNED/PENDING/COMPLETED/OVERDUE/REPEAT_REMINDER）可作为多选元素

### D5：搜索框是否需要持久化？

**决策**：**不持久化**。搜索 query 用 `remember + mutableStateOf`（与灵感页一致）。

### D6：Mode（OR/AND/NOT）是否需要持久化？

**决策**：**不持久化**。默认 OR，重启后回 OR。

### D7：StatusFilterSection 拖拽修复一并处理？

**决策**：**是**。这次顺便把 StatusFilterSection 的 Plan A + Plan D 拖拽修复补齐。

### D8：是否需要 FilterItem sealed class 而非简单 String ID？

**决策**：**是**。使用 sealed class 有 3 个优势：
1. 类型安全：编译期保证只能添加 Category 和 Status 两类
2. pattern match：`when (item) { is FilterItem.Category -> ... }` 无需 else 分支
3. 扩展性好：未来可加 FilterItem.Date 等其他维度

### D9：全局 FilterChip Row（OR/AND/NOT）的位置

**决策**：**放在 DrawerSectionTab 下方**（仅 TODO Tab 显示，其他 Tab 不显示）。

**理由**：
- 与 DrawerSectionTab 视觉上呼应（都是 TODO Tab 的元控制）
- 不与各分区的搜索框+列表冲突
- 跨 2 个分区共享 1 个 mode，符合 v2 统一集合设计

### D10：FilterItem.Category 的 id 语义

**决策**：**`id=0L` 表示"未分类"**（与 todo.categoryId==0L 对齐）。

**理由**：
- 与现状 todo.categoryId 约定一致
- "未分类"是真实可选的过滤维度，不是特殊值
- "全部待办"通过空集合表达，不占用 FilterItem 元素

### D11：applyFilterItems 在 OR/NOT 模式下跨维度的组合

**决策**：**跨维度用 AND 组合**（OR 模式 = 分组项 OR + 状态项 OR + 跨维度 AND；NOT 模式同理）。

**理由**：
- 符合用户"跨维度组合"的直觉
- OR 模式 = `catOk && stOk` = 必须同时满足分组和状态
- NOT 模式 = `catNotOk && stNotOk` = 必须同时不满足分组和状态
- 如果用户想要"OR 跨维度"（满足分组 OR 满足状态任一即可），可以后续优化
