## SwipeableImageStack 堆叠组件设计决策（方案 C）
- 来源：`图片库/重构滑动堆叠组件.md` 对话总结 + `图片库/preview_stack.html` 原型。
- 饱和系数 K（双曲饱和公式 `value = MAX×N/(N+K)`）：**保持固定，不随图片张数动态变化**。原因：K 是与 N 解耦的独立形状参数；若 `K∝N` 会退化成恒定角度（失去层叠），`K∝√N` 小张数反而被压平。
- 自适应方案采用**方案 C：可见深度 M**（非动 K）：`M = min(visibleDepth, cardCount)`，仅前 M 张参与层叠展开（饱和曲线有效索引 `ei = min(index, M-1)`），超出部分夹在栈底饱和位置。原型已加 `visibleDepth` 滑块（默认 12，范围 2–40）。
- 原型 `preview_stack.html` 已改：新增 `visibleDepth` 参数/滑块、`getCardStyle` 用 M 夹取 `ei`、StatusBadge 显示 `M`。
- **（第二轮修正）自动旋转角与饱和系数 K 均改基于可见深度 M = min(visibleDepth, cardCount) 计算**：`K = √M`（次线性，避免 K∝M 退化为恒定角），`tiltAngle = -90×M/(M+K)`。面板已注明完整公式与实时数值；原手动 K 滑块改为只读展示。
- **（第三轮）缩放/偏移/深度改为线性对齐旋转**：原 `scale = 1-0.5×ei/(ei+K)`、`offset = MAX×ei/(ei+K)`、`depth = MAX×ei/(ei+K)` 为饱和曲线，头重脚轻（顶卡第一跳跌幅最大，遮住底卡更多）。现改为与 rotation 同分母 `ei/(M-1)`，即 `norm = M>1 ? ei/(M-1) : 0`，`scale = 1-(1-MIN_SCALE)×norm`、`stackOffset = MAX_STACK×norm`、`depthOffset = MAX_DEPTH×norm`。各层缩放/偏移步长均匀（顶层 1.0 → 底层 MIN_SCALE=0.5）。同时清理了未使用的 `saturationK` 组件 prop（旋转直接用 App 算好的 tiltAngle，位置不再用 K）；面板"堆叠"区注明该线性对齐关系。
- **（第四轮）scale 由线性改为等比（几何）缩放**：`scale = Math.pow(MIN_SCALE, norm)`（norm = ei/(M-1)），各层面积比恒为 MIN_SCALE²，彻底消除小 M 时头重脚轻；offset/depth 仍保持线性。原因：人眼感知面积∝scale²，线性 scale 下相邻面积比递增、越往下收得越快。面板"堆叠"区已注明等比公式。
- 待办：若要把方案 C 落到 Compose 组件 `app/.../SwipeableImageStack.kt`，需加 `visibleDepth` 参数并执行同样的 `ei = min(index, M-1)` 夹取逻辑。
