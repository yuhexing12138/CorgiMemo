## 修复：正文卡在「正在装载…」（同日，上一轮改动引入的回归）

- **现象**：进入已有内容的灵感，标题 / 字数行正常，正文区一直停在「正在装载…」（JS 侧文案）。
- **根因**：`ready` 分支里同步调用了 `applyImeSuppression()`（内部 `evaluateJavascript`），
  而 `handleUpMessage` 由 `@JavascriptInterface` 调用、运行在 WebView 的 **Java 桥线程**
  → 抛 `IllegalStateException` → 被 `handleUpMessage` 外层 `catch` 静默吞掉
  → 同一行后面的 `mainHandler.post { flushIfReady() }` 不再执行 → `init` 永不下发
  → JS 侧 `booted` 恒为 false（它只在 `case "init"` 里 `setBooted(true)`）→ 一直「正在装载…」。
- **修法**：
  1. 止血：把注入与 `flushIfReady()` 放进同一个 `mainHandler.post { ... }`；
  2. 加固（用户选定）：**上行消息入口统一切主线程**——`handleUpMessage` 只负责
     `Log` + `mainHandler.post { handleUpMessageOnMainThread(json) }`，解析逻辑全部移入
     主线程侧的 `handleUpMessageOnMainThread`，各分支原有的 `post` 全部删除。
     线程正确性收敛为入口唯一一处约定，以后往分支里加 WebView 调用不会重踩。
- **教训**：① `@JavascriptInterface` 回调里任何 WebView 方法（`evaluateJavascript` /
  `loadUrl` / `setBackgroundColor`）都必须先 post 回主线程，**原来把 `flushIfReady` 包在
  post 里正是这个原因，改代码时不能拆散这层包装**；② `catch { Log.e }` 会把线程违规
  伪装成"某功能没生效"；③ WebView 问题要先分清「JS 内状态」与「Kotlin 侧状态」——
  本例装载文案在 JS，而切换它的 init 来自 Kotlin。

## 修复面板叠加 + 三面板互斥收敛为单一状态（同日，接续上一条）

**现象**：从「A」切到「T」或「Aa」时两个面板**同时可见**（叠加），把下方按钮行顶下去。

**根因**：三个面板用三个 boolean 表达互斥，`onFontPickerClick` 只关了 `isSizeColorPanelExpanded`、
`onSizeColorPanelClick` 只关了 `isFontPanelExpanded`，**两处都漏关 `isColorPanelExpanded`**
（A→T / A→Aa）。三个 `AnimatedVisibility` 挂在底部栏同一位置，漏关即两个同时可见。

**修法（按用户选择做结构性收敛）**：

- 新增 public enum `EditBottomPanel { FONT, SIZE_COLOR, COLOR }`（定义在
  `components/InspirationEditBottomBar.kt`），取代三处 boolean 参数：
  - `InspirationEditBottomBar(openPanel: EditBottomPanel?)`、`RichTextFormatToolbar(openPanel: EditBottomPanel? = null)`
  - 面板可见性 = `openPanel == X`；工具栏三个按钮 isActive 同源派生
- 宿主 `InspirationEditScreen`：`var openPanel by remember { mutableStateOf<EditBottomPanel?>(null) }`，
  三个按钮回调统一为「同值则置 null，否则置该值」；三处「完成」回调统一 `openPanel = null`；
  `isFormatPanelOpen = openPanel != null`。
- **互斥由状态本身保证**：任何时刻只可能有一个值，无处可漏。

**教训**：多个互斥的可选集若用 N 个 boolean 表达，互斥关系就是 N² 条需要人工维护的隐式约束，
新增一项时必然漏 —— 收敛为「单一可空枚举/密封类」是这类 bug 的一劳永逸解法。

## H 面板正文字号不生效——TextUnit 插值坑（v2026-09-21 续 6）

**根因**：onFontSizeSelect 下发 `"${sp.sp}px"`——sp.sp 是 TextUnit，插值调 toString() 得 "18.0.sp"，拼出 **"18.0.sppx"** 非法 CSS 值 → addStyles 无效 → 所有非默认档字号全部不生效（默认档走 "default" 正常）。v2026-09-21 字号从 Aa 面板迁入 H 面板时随迁移引入。
**修复**：改 "${sp}px"（Int 直接插值）。JS 侧期望 "18px" 形式（removeStyles 对 "16px"）。
**教训**：⚠️ TextUnit/.dp 的 toString 是「值.单位」格式，绝不能用于字符串拼接 CSS；桥接 CSS 值一律数值直接插值。
