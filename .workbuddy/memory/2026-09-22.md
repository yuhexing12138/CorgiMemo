## 修复「可折叠标题」H1/H2/H3 点击无效 + 折叠态持久化（待真机验证）

**根因（与上一条不同源，更严重）**：`EditorApp.tsx` 的 transform 分支把
`toggleHeading` / `toggleHeading2` / `toggleHeading3` **当成独立块类型**传给 `updateBlock`。
BlockNote 里折叠标题 = `heading` 块 + `props.isToggleable = true`
（官方斜杠菜单 getDefaultSlashMenuItems.ts 即如此构造），**不存在 toggleHeading\* 类型**；
本项目 schema 只有 defaultBlockSpecs 那 14 个类型。于是 `blockToNode` 的
`schema.nodes["toggleHeading2"].isInGroup()` 对 undefined 取属性 → TypeError。
加上 format 分支与整个下行 switch 都无 try/catch → 异常从 Java 桥回调抛走，
宿主 error 通道收不到 = 点了完全没反应且无日志。

**同源连带损伤（一并修）**：
1. `toggleList` 同为错名（正确 `toggleListItem`）→ 工具栏「折叠列表」也是死按钮；
2. 回显口径错：`blockType.startsWith("toggleHeading")` 永不成立（真实 blockType 恒为 heading）
   → 可折叠分区永远点不亮、还会误点亮普通分区同号格子。改为「是否 heading 块 + 新增上行字段
   `headingToggleable`」分流（JS pushBlockState / bridge.ts / Kotlin BlockState / HeadingPanel /
   InspirationEditBottomBar 全链）；
3. 持久化：官方 markdown 导出把 `<details><summary><h3>…` 削成普通 `### 文本`，isToggleable 丢失
   → converter.ts 新增 `encodeToggleHeadings` + 三个 token，导出时展开成
   `<details><summary>` / `### 标题` / `</summary>` / 子块 / `</details>` 标记序列；
   解析侧无需改动（details/summary 在官方 HTML_BLOCK_TAGS 白名单，rawHtml 透传，
   拼接 HTML 后 `<h3>` 落在未闭合 summary 内 → 命中 heading spec 的 DETAILS 分支）。
   ⚠️ 消费方连带：`InspirationTextUtils.markdownToPlainText` 必须剥离这些标记行，
   否则污染列表摘要/字数/搜索（已加规则）。

**行为决策**：折叠标题点同一格再点一次 → 退回普通段落（与「普通标题」语义一致）。
**改动文件**：EditorApp.tsx / bridge.ts / converter.ts（JS）+ BlockNoteEditorWebView.kt /
HeadingPanel.kt / InspirationEditBottomBar.kt / InspirationTextUtils.kt（Kotlin）+ 两份 docs。

**待办/风险**：① 产物需**再次**重建（上一轮 H4-H6 的产物已由用户重建，工作区 editor.html

## 修复 A 面板「选中文字色 / 选中背景色」无效 + 行内色持久化（待真机验证）

**根因（第三次，又换了一层）**：不是通道问题也不是命名问题——命令送达、`addStyles`
也确实把 mark 写进了文档，但**看不见**。
- BlockNote 的 `textColor`/`backgroundColor` 是 `createStyleSpec` 型 → 定义了 `addMarkView`；
  Tiptap `EditorView` **无条件**接收 markViews（`@tiptap/core/src/Editor.ts:606`）→ 编辑器内
  渲染走 spec 的 **`render()`**（`schema/styles/createSpec.ts:100-111`）。
- 官方 `render()`（`blocks/defaultBlocks.ts:69-76 / 105-112`）**只造裸 span、不设任何颜色**，
  颜色只写在 `toExternalHTML()`（导出/粘贴路径）→ 颜色**完全依赖 CSS 的 9 条预设色名规则**
  （`Block.css:601-710`，产物实测 9 条）。
- A 面板行内色下发的是 **自由 hex**（`blockColorHexOf` → `#FF9A5C`）→ 无规则命中；
  而块级色下发的是**色名** → 命中 → 正常。这解释了"行内无效、块级有效"。
- 对照：项目 fontSize 能生效是因为它用 `createReactStyleSpec` 把值写进了**内联 style**。

**修法（用户拍板：覆盖 spec + 一并做持久化）**：
1. `editor/schema.ts` **同名覆盖** textColor/backgroundColor：`render`/`toExternalHTML` 内联
   `span.style.color|backgroundColor`（色名经 `COLORS_DEFAULT` 映射，hex 原样）；
   保留官方 `parse` 并新增**形态归一**（`rgb(r,g,b)` → 大写 `#RRGGBB`）。
2. `converter.ts` 行内色 token 往返：导出前把带色 text 片段拆成
   `@@@CORGI_IC_TC_<值>@@@` + 原文 + `@@@CORGI_IC_END@@@`（背景色 `BG_` 前缀，link 内文本递归），
   导出后反向替换成原生 `<span style="color:…">`；解析侧靠官方 `tryInlineHtml` 透传 +
   本项目覆盖后的 `parse`，无需改动。
3. `InspirationTextUtils.markdownToPlainText` 增加"只删 span 标签本体、保留文字"的规则。

**关键坑（已规避，值得记）**：`element.style.color` 读出来是 `rgb(255, 154, 92)` 而非 hex，
若原样入库，第二轮保存会因"值形态不安全"被编码逻辑跳过 → 表现为"第一次有颜色、重进再存就丢"。
故 `parse` 必须归一化。同理，纯文本剥离 span 时**不能整行删**（文字在标签之间）。

**未处理**：fontSize 仍是"已接受损失"（markdown 丢）。

**块级色（段落色）持久化（用户追加要求，本轮一并做）**：
- 不用 HTML 包裹承载——块级属性必须贴块自己的标签（`<p data-text-color=…>`），而块导出成
  p/h2/li/blockquote 不可预知；外包 `<div data-…>` 会在 ProseMirror 解析时被当不匹配元素
  **下钻丢弃**，属性照样丢。
- 改用**块内容行首纯文本 token**：`@@@CORGI_BC_TC_red@@@` / `@@@CORGI_BC_BG_blue@@@`
  （导出插入 token + 剥 props；载入 `decodeBlockColorTokens` 从句首剥离并写回 props，
  必须在装载编辑器**之前**，否则 token 闪现）。**不需要任何 CSS**，块级色继续走官方渲染
  路径，语义无损（含"背景色铺满整块"）。
- ⚠️ 块级色 token 是**纯文本**、会留在库里的 markdown 原文里 → Kotlin
  `markdownToPlainText` 新增统一前缀通配剥离 `@@@CORGI_[A-Za-z0-9_#]*@@@`
  （同时覆盖分割线等既有 token，后续新增同类无需再改）。

**改动文件**：schema.ts / converter.ts（JS）+ InspirationTextUtils.kt + docs/bridge-protocol.md。
**已通过 `tsc --noEmit`（用户同意后执行，两次均 exit 0）**。
**待办**：产物重建；真机专项验证「行内色 / 段落色 → 退出 → 重进是否保留」、摘要无 token 泄漏。

## A 面板行内色回显 + 摘要 token 泄漏修复（待真机验证）

### 1. 行内色色块选中高亮（用户要求：默认第一个「/」块高亮）
根因：`ColorStylePanel` 的两个「选中色」行传 `showSelection = false` —— 当时**没有行内色的
状态上行**，宿主拿不到"选区已有的行内色"，强行回显会让「默认」项恒定高亮造成误导。
修法（全链）：
- JS `pushBlockState` 新增 `inlineTextColor` / `inlineBackgroundColor`（`getActiveStyles()` 原始串，
  与 fontSizePx 共用同一次调用）；`onSelectionChange` 已在上行，故选中文字/点色后自动刷新；
- `bridge.ts` 类型 + `BlockState`（Kotlin）+ `InspirationEditBottomBar` 接线；
- 新增 `blockColorNameOf(hex, isDark, background)`（`blockColorHexOf` 的反函数）：
  空 → `""`（高亮默认块）；命中色板 → 色名（点亮色点）；不在色板（外部粘贴的自定义色 /
  切主题后色值变了）→ 原样返回 hex（**无高亮**，比谎报"默认"更诚实）。

### 2. 摘要出现 `@@@CORGI_` 字面量
**根因（不是剥离规则失效）**：灵感纯文本字段 `Inspiration.content` 由**保存流程**写入，
而 `InspirationEditViewModel` 那里调的是 `MarkdownParser.stripMarkdown` ——
**只处理 markdown 语法，不剥 HTML 标签、不剥 `@@@CORGI_…@@@`**；
而卡片摘要优先读 `content`（非空即不走 markdownToPlainText 兜底）→ 污染值直接上卡面。
即"同一个 markdown→纯文本需求存在两份口径"，我上一轮只在其中一份加了规则。
**修法**：完整口径下沉为 `MarkdownParser.toPlainText()`（单点真相），
`InspirationTextUtils.markdownToPlainText` 变薄委托；保存路径 + 启动回填路径统一改调它。
**并且顺手修历史数据**：`backfillEmptyInspirationContent` → 扩权改名
`repairInspirationPlainText`（content 空 或 含 `@@@CORGI_`/`<span` 即用 toPlainText 重算，
幂等），否则用户得逐条重存才能消除。
⚠️ 待办的两处 stripMarkdown（HomeViewModel / HomeScreen 搜索）**保持原样**（独立口径）。

## 面板收起后按需恢复软键盘（v2026-09-22，待真机验证）

**需求**：T/H/A 三面板点「完成」或收起后，若光标仍处于聚焦状态，应同步弹出手机键盘
（此前约定是「解除抑制但不主动弹回」，用户需再点一次正文）。

**关键判断：焦点真值只能来自 JS**。Android 侧 `View.hasFocus()` 会失真——点底部栏按钮后
视图焦点已转移到 Compose 根视图，而 WebView 内 contenteditable **仍持有 DOM 焦点**
（光标还在闪）。故新增上行 `editorFocus { focused }`（document 级 focusin/focusout +
`activeElement.closest('.bn-editor')`，翻转才上行）→ `BlockNoteBridgeController.editorFocused`。

**弹键盘三步（顺序不可换）**：
1. 下行新增 `focusEditor`：JS 对 `.bn-editor` 调 `focus()`（已聚焦时空操作，不打断选区）
   ——Chromium 只在编辑元素持有焦点时才建立输入连接；
2. `requestFocus()`（先打开 isFocusableInTouchMode，触摸模式下否则 requestFocus 无效）；
3. `post { restartInput + showSoftInput(SHOW_IMPLICIT) }`。

**编译踩坑（已修）**：原本还加了 `WebSettings.keyboardDisplayRequiresUserGesture = false`
作"双保险"——**该 API 在 Android 上不存在**（编译报 Unresolved reference；API 35 android.jar
里与键盘相关的只有 `MediaPlaybackRequiresUserGesture`，该语义属别的平台/别的 WebView 封装）。
弹键盘本来就只需 IMM 显式 showSoftInput（直接请求输入法，不受 WebView 用户手势策略约束），
已删除该行并在原地留注释警示。教训：跨平台 WebView API 名不能凭印象搬，先 javap/解 jar 核对。

**宿主时序**：`openPanel = null` → `suppressIme` 回 false（解除 inputmode）→
`LaunchedEffect(isFormatPanelOpen)` 用 `wasFormatPanelOpen` 判「true→false」（避开首次组合=进页）
→ delay 180ms → 正文 editorFocused 则 `restoreIme()`，否则标题 isTitleFocused 则
`keyboardController.show()`，都没有则不弹（无光标不抢键盘）。标题焦点由新增的
`.onFocusChanged` 记录（面板期间点击被 Initial 消费，但已有焦点不会被清掉）。

**改动文件**：bridge.ts / EditorApp.tsx（JS，需重建产物）+ BlockNoteEditorWebView.kt
（editorFocused / focusEditor / restoreIme / showImeNow）+ InspirationEditScreen.kt
（IME_RESTORE_DELAY_MS=180L、恢复 effect、isTitleFocused、注释同步）+ docs/bridge-protocol.md。

`focusEditor:`（JS 侧 diagnostic）。
