## 修复 A 面板「选中文字色 / 选中背景色」无效 + 行内色持久化（待真机验证）

**根因（第三次，又换了一层）**：不是通道问题也不是命名问题——命令送达、`addStyles`
也确实把 mark 写进了文档，但**看不见**。
- BlockNote 的 `textColor`/`backgroundColor` 是 `createStyleSpec` 型 → 定义了 `addMarkView`；
  Tiptap `EditorView` **无条件**接收 markViews（`@tiptap/core/src/Editor.ts:606`）→ 编辑器内
  渲染走 spec 的 **`render()`**（`schema/styles/createSpec.ts:100-111`）。
- 官方 `render()`（`blocks/defaultBlocks.ts:69-76 / 105-112`）**只造裸 span、不设任何颜色**，
  颜色只写在 `toExternalHTML()`（导出/粘贴路径）→ 颜色**完全依赖 CSS 的 9 条预设色名规则**
  （`Block.css:601-710`，产物实测 9 条）。
- A 面板行内色下发的是 **自由 hex**（`blockColorHexOf` → `#FF9A5C`）→ 无规则命中；
  而块级色下发的是**色名** → 命中 → 正常。这解释了"行内无效、块级有效"。
- 对照：项目 fontSize 能生效是因为它用 `createReactStyleSpec` 把值写进了**内联 style**。

**修法（用户拍板：覆盖 spec + 一并做持久化）**：
1. `editor/schema.ts` **同名覆盖** textColor/backgroundColor：`render`/`toExternalHTML` 内联
   `span.style.color|backgroundColor`（色名经 `COLORS_DEFAULT` 映射，hex 原样）；
   保留官方 `parse` 并新增**形态归一**（`rgb(r,g,b)` → 大写 `#RRGGBB`）。
2. `converter.ts` 行内色 token 往返：导出前把带色 text 片段拆成
   `@@@CORGI_IC_TC_<值>@@@` + 原文 + `@@@CORGI_IC_END@@@`（背景色 `BG_` 前缀，link 内文本递归），
   导出后反向替换成原生 `<span style="color:…">`；解析侧靠官方 `tryInlineHtml` 透传 +
   本项目覆盖后的 `parse`，无需改动。
3. `InspirationTextUtils.markdownToPlainText` 增加"只删 span 标签本体、保留文字"的规则。

**关键坑（已规避，值得记）**：`element.style.color` 读出来是 `rgb(255, 154, 92)` 而非 hex，
若原样入库，第二轮保存会因"值形态不安全"被编码逻辑跳过 → 表现为"第一次有颜色、重进再存就丢"。
故 `parse` 必须归一化。同理，纯文本剥离 span 时**不能整行删**（文字在标签之间）。

**未处理**：fontSize 仍是"已接受损失"（markdown 丢）。

**块级色（段落色）持久化（用户追加要求，本轮一并做）**：
- 不用 HTML 包裹承载——块级属性必须贴块自己的标签（`<p data-text-color=…>`），而块导出成
  p/h2/li/blockquote 不可预知；外包 `<div data-…>` 会在 ProseMirror 解析时被当不匹配元素
  **下钻丢弃**，属性照样丢。
- 改用**块内容行首纯文本 token**：`@@@CORGI_BC_TC_red@@@` / `@@@CORGI_BC_BG_blue@@@`
  （导出插入 token + 剥 props；载入 `decodeBlockColorTokens` 从句首剥离并写回 props，
  必须在装载编辑器**之前**，否则 token 闪现）。**不需要任何 CSS**，块级色继续走官方渲染
  路径，语义无损（含"背景色铺满整块"）。
- ⚠️ 块级色 token 是**纯文本**、会留在库里的 markdown 原文里 → Kotlin
  `markdownToPlainText` 新增统一前缀通配剥离 `@@@CORGI_[A-Za-z0-9_#]*@@@`
  （同时覆盖分割线等既有 token，后续新增同类无需再改）。

**改动文件**：schema.ts / converter.ts（JS）+ InspirationTextUtils.kt + docs/bridge-protocol.md。
**已通过 `tsc --noEmit`（用户同意后执行，两次均 exit 0）**。

## 修复灵感详情卡正文出现 `@@@CORGI_` 字面量（待真机验证）

## 修复「段落文字色/背景色在灵感详情页不显示」（待真机验证）

**修法**：
- `MarkdownParser` 新增 `extractBlockColorMarkers(markdown): Pair<BlockColorMarkers?, String>`

  与 `stripStructuralMarkers`（丢弃语义）区分开）。
- `InspirationViewCard`：
  - `paragraphColors = paragraphs.map { extractBlockColorMarkers(it).first }`（与索引一一对应）
  - 新增 `blockColorOf(name, background)`：色名 → Compose 色，**未知色名返回 null 不覆盖**
    （不能回落 Transparent，否则文字全透明="消失"）
  - 新增主题判定（`ThemeManager.themeMode` + `isSystemInDarkTheme`，与 ColorStylePanel 同款自洽订阅）
    —— 色板明暗两套，必须与编辑页同源
  - `InspirationBodyParagraph` 新增 `textColor` / `backgroundColor` 参数：
    color = `textColor ?: (勾选降级 ?: #666666)`；bg 用 `Modifier.background(...)` 包在 pointerInput 之前
  - 两个调用点（任务列表段 / 普通段）都传入 —— 标题也走普通段分支 ✔
- 补 import：`isSystemInDarkTheme` / `collectAsState` / `getValue` / `ThemeManager`
