## 轮十七（14:06~）：自链接文字编辑 → href 同步跟随

**需求**：「只填 URL」插入的自链接（显示文本 == href），用户在编辑器里直接改它的
文字（如把 `https://www.baidu.com` 改成 `https://百度www.baidu.com`），**href 要
同步跟随**（改文字即改链接本身）。不改则保存后变 `[新文字](旧href)`，重进链接
仍指旧地址，与「我在改这个链接」的预期相悖。

**实现（新文件 `src/editor/linkHrefSync.ts` + EditorApp 注册）**：BlockNote 扩展
（`createExtension` 的**对象重载** `createExtension({key, prosemirrorPlugins})`——
函数重载会被推断成「工厂返回工厂」而类型不匹配 extensions 数组）挂
`appendTransaction` PM 插件（与官方 autolink 同机制）：
1. 旧文档变化区间（±1 字符，覆盖链接右缘打字）内找 link mark 的 text 节点；
2. 仅处理**自链接**（单节点文本 === href）；
3. `transform.mapping.map(from,-1)/map(to,1)` 映射到新文档；
4. 新文档映射邻域（±1）收集**同 href** 相邻 text 片段（打字继承 mark 会扩出
   旧边界），拼出全文；
5. 全文非空且 ≠ href → `removeMark + addMark(href=新全文)`。

**刻意取舍**：多 text 节点自链接（局部带色）不触发（单节点文本≠href，安全降级）；
文本删空不同步（mark 随文本消失=解除链接，符合直觉）；href 允许任意字符串（含
中文，用户自担）。**无循环**：PM appendTransaction 一轮机制 + 「文本===href」身份
随更新自然延续。

**API 确认**：`createExtension` 由 `@blocknote/core` 主入口公开（index.ts
`export * from "./editor/BlockNoteExtension.js"`）；`useCreateBlockNote` options
的 `extensions?: ExtensionFactoryInstance[]`。

**验证**：tsc 0 错；重建 `bn-src:e94c237cd3b6` 机检 [OK]（清单自动扩为 11 文件，
含新 linkHrefSync.ts）；产物内插件 key `linkTextHrefSync` 特征命中。
**PM 插件逻辑无单测环境（需 DOM）→ 依赖真机验证**。

**真机验证清单**：① 自链接文字中间加字/删字 → 链接浮条「打开」地址跟随变化、

## 轮十八（14:30~）：含中文自链接重进丢失 —— autolink 补「协议后紧跟 CJK」分支

**真机报**：自链接文字改成 `https://百度www.baidu.com`（href 同步生效）→ 完成重进
→ **变普通字符**。根因：display==href 导出退化为裸 URL，但 **BARE_URL_GLOBAL_RE
对「协议后紧跟 CJK」匹配长度为零**（`https://` 后第一个字符「百」即被段内 CJK

**修法（BARE_URL_GLOBAL_RE 改交替分支，分支一优先）**：
```
/https?:\/\/(?:[^\s<>"`CJK排除集]+        ← 分支一：常规 URL（段内不吞 CJK）

)/g
```

正则交替顺序保证：分支一能成立的位置绝不走分支二（`https://a.com，很有用` 的
「URL 后跟中文说明」回归不受影响）；仅协议后**第一个字符**就是 CJK 时才走宽松
分支（吃到空白/引号，尾标点仍由 trimUrlTail 剥）。⚠️ 固有模糊已注释说明：
`https://百度…，参考` 会把中文说明一并吞进链接——协议后紧跟 CJK 无合法 URL 语义
可依，按用户手工拼接整体处理（自担）。
