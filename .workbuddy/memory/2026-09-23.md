## 修复「滑动起手闪一下原生波纹」（Nest/Unnest，待真机验证）

**现象**：左右滑动底部工具栏，起手落在 Nest/Unnest 上时瞬间闪一下原生波纹；其他按钮不会。

**根因**：上一轮根因修复（手势全权驱动 interactionSource）里 Press 在 down 即 `tryEmit`；
而其他按钮走 IconButton（内部 clickable），Foundation 1.11 在 horizontalScroll 容器内会把
Press 交互延迟 `TapIndicationDelay`（= `ViewConfiguration.getTapTimeout()` = **100ms**）发射、
滑动被父级消费时**什么都不发**——所以其他按钮滑动起手不闪、这两个连发按钮闪。
（官方源码核对：foundation-android-1.11.2 `Clickable.kt` 的 `ClickableNode.handlePressInteraction`
2228-2271 行 + `Clickable.android.kt` 的 `TapIndicationDelay`。）

**修法（逐条复刻官方 handlePressInteraction 语义）**：
- `longPressRepeat` 新增 `delayPressIndication: Boolean = false`；`RiFormatButton` 传 `true`。
- 滚动容器路径：`onPress` 内 `coroutineScope{}` 起 delayJob，延迟
  `DEFAULT_PRESS_INDICATION_DELAY_MS`（自定义常量 100L，对齐 internal 的 TapIndicationDelay）
  再发 Press——
  ① 延迟期间被父级消费（滑动起手）→ `cancelAndJoin` 且**什么都不发**（不闪波纹）；
  ② 延迟期间正常抬起（快速点按）→ 瞬时补发 Press+Release（点按波纹不受影响）；
  ③ 延迟已过（Press 已发）→ 抬起发 Release、取消发 **Cancel**（对齐官方，取消不再误用 Release）。
- finally 兜底从「必发 Release」改为「pendingPress 未收尾时补发 Cancel」——协程被杀
  （enabled 翻转重启 pointerInput / 组合离开）时波纹照常消散（Cancel 与 Release 视觉等价）。
- **两处作用域各有理由勿混用**：波纹 delayJob 挂 onPress 内 `coroutineScope{}`（结构化子协程，
  随手势协程消亡、无孤儿发射）；连发定时器仍在 `rememberCoroutineScope()` 普通域（不受手势
  生命周期限制）。KDoc 要点 3/5 已写明。
- 顶栏撤销/重做（无 interactionSource）与默认 `false` 路径行为不变，零回归。

**改动文件**：LongPressRepeatIconButton.kt（新常量/新参数 + onPress 重写）+
RichTextFormatToolbar.kt（RiFormatButton 传参 + 注释块补一条）。纯 Kotlin，无需重建 JS 产物。
**已提交 `f2072daf`**（仅上述两个 Kotlin 文件，2 files changed, +125 −21；pre-commit 钩子
正确跳过。editor.html / st9.txt 等并行会话在制品未卷入）。

**真机验证点**：
1. 在 Nest/Unnest 上起手左右滑动 → 全程无波纹闪现（与其他按钮同观感）；

## 核实：官方内置行内按钮在 content:"none" 块上是库级缺口

**结论（源码级证据）**：`content:"none"` 的块（分割线/图片/视频/音频/文件/分页符）在
`nodeToBlock` 后 block 对象的 `content` **是 `undefined`**（`blocks-CiuUGa1E.js` 函数 `M(e,t)`：
`if(f.content==="inline")m=j(...); else if(f.content==="table")m=tt(...); else if(f.content==="plain")m=[...];

**官方判据**：`@blocknote/react` 的 bold/italic/underline/strike（styleButton `Z`）、

——对 `content:"none"` 的块而言 `b.content === undefined` → `find` 得 undefined → 返回 undefined → 不渲染。
即**官方这道防线本来就为"无文本块"设计**，divider 也覆盖到了（先前"字符串 'none' ≠ undefined"的猜测是错的，
未证实前不要写进结论）。

与 `blockTypeSelect`（把段落/标题/引用换成 divider 会让按钮自身失去落点）——两者判据不含 content 检查。

## 修复「分割线工具条宽高随位置变化」（真机 3 张截图）

**用户表述**：点击分割线后，工具栏按钮在不同位置时宽高都不一样。

**关键取证（推翻「位置相关」这个前提）**：把三张 1080×2400 原图裁上部区域放大比对，
发现图1 与图2 的**页面内容逐字相同**（都是「测试二和一些克隆你二弟也行」+ 蓝条 +

按钮尺寸就不同。所以**根因与位置完全无关**。

**真实根因（宽度由最长按钮决定 + 折行行数浮动）**：
- 工具条 `display:flex`，按钮只给 `padding:4px 10px`，**无固定 width**；
  行内 flex 项默认 `flex-shrink:1`，三档相互挤压 → 每个按钮的可用宽度由**最长者**（虚线）决定。
- 单行 6 个 `╌` 的 textWidth > 折行后每行的宽度 → **折行反而更宽** → 按钮被拉宽。
- 而 `╌`(U+254C) `〰`(U+3030) 是冷僻码位，各设备字体度量不同、缺字时还可能落成豆腐块
  → **折行行数随机**（截图实测：图1 两行 / 图2 三行 / 图3 一行）。
- `line-height: normal` 按继承字号推导 → 行数 × 行高 ⇒ **高度也跟着变**。
- 宽度变 ⇒ `useLayoutEffect` 实测 `rect` 变 ⇒ `left = x − rect.width/2` 变 ⇒ **位置也跟着跳**。
- 次要项：工具条未声明 `fontSize`，继承 `.editor-page` 上的「正文字号」可变值。

**修法**：
1. 写死 `TOOLBAR_BASE_FONT = 12` 截断继承链；
2. 写死 `TOOLBAR_BTN_W=52 / TOOLBAR_BTN_H=28 / TOOLBAR_DEL_W=46`，加 `boxSizing:border-box`
   + `lineHeight:1` + `whiteSpace:nowrap` → 工具条恒定 240×40；
3. 标签 `─────`/`╌ ╌ ╌`/`〰〰〰` 换成 **SVG 线性图标**（新增 `DividerStyleIcon`，
   共用 `viewBox="0 0 24 12"`、`y=6` 中线、`stroke-width=1.5`、`strokeLinecap=round`），
   线型由几何路径确定，与字体/字号/设备彻底无关。

**教训（重要）**：用户描述的现象里常混着**错误归因**（本次「不同位置」是用户目测归纳，
实际是「同位置的两次点击」）。**先用原图逐像素比对确认变量是否真的变了**，
再决定排查方向；否则会一路去查 WebView 缩放 / viewport / transform / Mantine 变量，全部白费

## 修复「切换分割线样式时工具栏跟着点击位置跳走」

**现象**：点分割线弹出工具栏后，再点样式按钮切线型，工具栏移动到被点的那个按钮处。

**根因：事件冒泡覆写定位坐标**。工具栏虽是 `position: fixed`（视觉悬浮），但在 DOM 上是
**分割线外层 div 的子节点**、React 里是 `DividerRender` 的子组件 —— `position: fixed`
**只改绘制位置，不改 DOM 树关系，也不阻断事件冒泡**。点样式按钮一次点击触发三件事：
① 按钮 onClick 切样式 + 关工具栏；② 事件冒泡到外层 div 的 `onClick`；
③ 外层把**本次点击坐标（按钮位置，非分割线位置）**写进 `toolbar` → 工具栏被重新打开并定位到按钮处。

进入条件：最后一次渲染时 `toolbar` 已是 `null`。否则 React 批处理两次 setState 会合并，看不出跳位。
**这正是"时好时坏"的经典成因，真机上稳定命中**。

**修法（双防线，均保留）**：
1. 三个样式按钮 + 删除按钮，`onClick` 首行统一 `e.stopPropagation()`（就近拦截）；
2. `DividerToolbar` **外层 div 也加** `onClick={(e) => e.stopPropagation()}`（控件边界兜底），
   将来新增按钮忘了写也不会把 bug 带回来；

## 链接点击：三层导航拦截 + LinkToolbar「打开」改走桥（v2026-09-24 定案）

**问题**：灵感编辑页 WebView 无 `shouldOverrideUrlLoading`；用户实测曾出现「WebView 原地加载
目标页、编辑器被顶掉」，且「点链接没反应」。

**根因（三条，官方源码确证）**：
1. `@blocknote/core` 的 `clickHandler`（Link 的 handleClickLink）首行
   `if (event.button !== 0 || !view.editable) return false;` —— **编辑态拦、只读态放行**给 DOM 默认导航。
2. 不配 `links.onClick` 时官方默认分支是 `window.open(href, target)`，而 Link 扩展
   `HTMLAttributes` 默认带 `target: "_blank"`；**Android WebView 的
   `setSupportMultipleWindows` 默认 false → 带 target 的 window.open 被 Chromium 静默丢弃**
   （不导航、不回调、无日志）。官方 LinkToolbar 的「打开」按钮（`OpenLinkButton.tsx`）
   同样是 `window.open(url, "_blank")` —— 这就是"点打开没反应"。
3. 两处 WebViewClient（正式页 BlockNoteEditorWebView.kt + 探针页 BlockNoteEditorScreen.kt）
   都没有任何导航拦截。

**方案 A（JS 侧，用官方 API 而非自写 ProseMirror 插件）**：
- `useCreateBlockNote({ links: { onClick: handleLinkClick } })` —— 官方注释原文
  「If provided, the default open-on-click behavior is disabled and this function is called instead」，
  一挂即**关掉官方 window.open 默认路径**，两条病根同时消失。
- `handleLinkClick`：左键才接管；`event.target.closest("a")` 取**用户实际点的那个** href；
  **编辑态 → return true 只落光标**（弹 LinkToolbar 由用户决定）；**只读态 → 上行 openLink**。
  ⚠️ 必须 return true 而非 false（false = 交给 DOM 默认行为，正是要避免的）。
- `sanitizeOutboundUrl`：口径同官方 sanitizeUrl（非 `javascript:` 才放行）+ 解析失败丢弃。
- `ProjectLinkToolbar`：只换「打开」按钮（EditLinkButton / DeleteLinkButton 照用官方）。
  ⚠️ 官方 `<LinkToolbar>` **只收 LinkToolbarProps、不收 className**，且类名硬编码在内部 Root
  → 直接渲染 `Components.LinkToolbar.Root className="bn-toolbar bn-link-toolbar"`。
  ⚠️ 自绘外链图标（官方用 mantine 图标，本项目无该独立依赖包）。
- 挂载方式：`<LinkToolbarController linkToolbar={ProjectLinkToolbar} />` 放进 BlockNoteView children。

**方案 B（宿主侧三道拦截，工具函数一律 internal 以便两页复用）**：
- `shouldOverrideUrlLoading`：非白名单 → openInBrowser + return true。
- `onCreateWindow` + `settings.setSupportMultipleWindows(true)` +
  `javaScriptCanOpenWindowsAutomatically = true`（**两开关必须成对**，只开前者仍可能因
  "非用户手势"被丢弃）。⚠️ onCreateWindow **取不到 URL**：必须造一个一次性 WebView 塞进
  `WebViewTransport` 发回，让 Chromium 让它加载目标 URL、在其 shouldOverrideUrlLoading 里
  取 URL 外送 + destroy；无论如何都要 `resultMsg.sendToTarget()`（不塞 = 取消，但必须发）。
- `onPageStarted` 兜底：主框架加载非白名单 → `stopLoading()` + `loadUrl(EDITOR_URL)` 自愈。
  ⚠️ onPageStarted **本就只对主框架触发**，无需判 isForMainFrame。
- `isEditorInternalUrl` 白名单三类：`file:///android_asset/blocknote-web/`、
  `https://corgimemo.local/`、`file://` 与 `content://`。
  ⚠️ **必须用 startsWith 而非 host 比较**：file:// 的 host 为空串，用 host 判会把编辑器自身也拦掉。
- `openInBrowser`：Uri.parse + scheme 空则丢弃 + `FLAG_ACTIVITY_NEW_TASK` + try/catch。
  ⚠️ `ACTION_VIEW` 是隐式 Intent，**Android 11+ 包可见性不影响 startActivity**，
  Manifest **无需加 `<queries>`**（实测确认当前 Manifest 也没有）。
- ⚠️ 跨文件复用的工具函数**必须写 `internal` 而非 `private`**：Kotlin 的 private 是**文件级**的，
  探针页看不见（首次写成 private 后才发现，两处已改为 internal）。

**产物**：`npm run build:editor` 重建，`bn-src:c7024a491925`（10 文件），
`scripts/check-blocknote-artifact.ps1` 报 [OK]。指纹 `2026-09-23 14:46:15 d58b4c53-dirty`。

**验证**：tsc --noEmit EXIT=0；产物内含 `openLink` 2 处、`打开链接` 1 处；
两文件 import 全量核对无缺失（顺带清掉探针页本就未使用的 `android.content.res.Configuration`）。

**⚠️ 待真机验证**：编辑态单击只落光标 + LinkToolbar 弹出；工具栏「打开」跳到系统浏览器；

② 用户点外部/按 Esc（官方 popover dismiss，**宿主完全无从得知**）。故新增上行

## 第七轮（15:55+）灵感首页列表摘要漏出分割线

**用户报**：分割线在灵感首页列表不需要渲染（首页时间线摘要里出现了 `---`）。

**根因（两处，第二处是排查中才发现的）**：

### 1. 三处摘要渲染点用 `removeHtmlTags` 而非项目统一口径
`Inspiration.content` 是**纯文本字段**（保存时 `InspirationEditViewModel` 已按
`MarkdownParser.toPlainText` 生成），但三个摘要渲染点各有一份**私有** `removeHtmlTags()`——
它只 `.replace("<[^>]*>", "")` + 解 HTML 实体，**对 markdown 一无所知**：

| 文件 | 行 | 场景 |
|---|---|---|
| `TimelineInspirationItem.kt` | 381 | 灵感首页时间线 |
| `InspirationCard.kt` | 116 | 回收站列表（`RecycleBinScreen`） |
| `InspirationCalendarDialog.kt` | 380 | 日历弹窗（`MainScreen`） |

⇒ `---` / `***` / `#` / `**` / `@@@CORGI_…@@@` 全部原样漏进摘要。
**修法**：三处统一改走 `InspirationTextUtils.markdownToPlainText`
（= `MarkdownParser.toPlainText`，项目唯一纯文本入口，见其 KDoc「凡灵感正文取纯文本，一律走」）。
三份 `removeHtmlTags` 定义随之成为死代码，已删。

### 2. ★ `toPlainText` 的分割线正则漏了带样式载体（补丁）
改完渲染端后**实测**发现：`toPlainText` 第 6 步的正则
`^\s*([-*_])(\s*\1){2,}\s*$` 要求**整行仅由同一符号构成**，
而项目样式载体是 `--- dashed` / `--- wavy`（符号后**有样式后缀**）⇒ **匹配不到**：

```
---          -> 剥净 ✓
***          -> 剥净 ✓
--- dashed   -> 残留 '--- dashed' ✗   ← 漏网
--- wavy     -> 残留 '--- wavy'   ✗   ← 漏网
```

**若只改渲染端，虚线/波浪线分割线仍会在摘要显示 `--- dashed` 字样。**
已补第 6b 条：`^\s*[-*_]{3,}[ \t]+(?:dashed|wavy)[ \t]*$`。
误伤已排除：`- 列表项` / `- [ ] 待办` / `**粗体**` / `--- 正文句子` / `### 标题` 全不受影响
（后缀须**恰好**为 dashed/wavy 且**行尾**）。

**教训**：Compose 侧的分割线载体规则要与 TS 侧 `DIVIDER_STYLED_LINE`
（`/^(-{3,}|\*{3,}|_{3,})[ \t]+(dashed|wavy)[ \t]*$/`）对齐——那边早就单独定义了带样式行，
这边漏了，是"两端口径漂移"的又一例。

**历史数据**：用户选「不改污染线索、靠渲染层兜底」。
`POLLUTED_PLAIN_TEXT_HINTS` 仍只有 `@@@CORGI_` / `<span`，
但渲染端每次无条件走 `toPlainText`，旧数据不会再漏出。

**新增**：`InspirationTextUtilsTest.kt` 追加 3 组用例——
分割线六形态剥离（含 `--- dashed` / `--- wavy` / `***` / `___` / 内部 token）、
对纯文本幂等（渲染端无条件再剥一道的依据）、行内粗体不被误伤。

## 第八轮（16:20+）链接面板「首次点不出现」+「被裁剪」双 bug 破案

**用户两个问题**：
① 第一次点底部工具栏链接按钮，链接工具栏不出现，再点一次才出现；
② 在编辑区靠上的位置点该按钮，面板被裁剪（只露下半截）。

### 现象①根因（**两个独立缺陷叠加**，任一个都足以致此）

**(a) `useRef` + `useEffect` 承载快照 → 首帧取不到锚点，且永远补不上**
`LinkEditPanel` 原写法用 `snapRef` + `useEffect(..., [props.open])` 冻结 props 快照。
`useEffect` 在**渲染之后**才跑，`ref` 赋值又**不触发重渲染** ⇒ 首帧
`snap.range.from === -1` ⇒ `anchorPosition === undefined` ⇒
`PositionPopover` 按 `position !== undefined && children`（其源码第 43 行）
**不渲染任何 children**；`useEffect` 随后更新了 ref 却因为没有 setState 而不会再来一帧
⇒ 整个「打开」周期面板都是空的。第二次点击因 `props.open` 再次翻转才补上。
**修法**：改用 `useMemo(() => ({...}), [props.open])` —— 快照在**同一帧内**取好。

**(b) `GenericPopover` 内建的 `FloatingFocusManager` 打开当帧就把自己关掉**
`PositionPopover` → `GenericPopover` 无条件套 `FloatingFocusManager`，默认语义 =
「弹出时把焦点移入面板 + 焦点离开面板即关闭（`closeOnFocusOut`）」。本场景下必然自毁：
① 面板内两个 Mantine `TextInput` 带 `autoFocus`，焦点被搬走 ⇒ 编辑器 `contenteditable` 失焦；
② **Android WebView 里焦点转移的 `relatedTarget` 常为 `null`**，`closeOnFocusOut`
据此判定「焦点跑到面板外」⇒ 立刻 `onOpenChange(false)`。
**真机日志实证**（`log/panel-seq2.txt`）每次都呈同一模式，全部 12 次无一例外：
```
16:12:04.966 down({"type":"openLinkPanel"})
16:12:04.969 up({"type":"diagnostic","message":"openLinkPanel: 6-6 url="})
16:12:04.993 up({"type":"editorFocus","focused":false})   ← 打开后 ~25ms 就失焦
16:12:06.758 up({"type":"linkPanelClosed"})               ← 随后被判关闭
```
**修法**：`<PositionPopover focusManagerProps={{ disabled: true }} ...>`。
面板本身不需要焦点管理——它是宿主命令驱动的受控浮层，开关权在 `props.open`；
点外部 / 按 Esc 仍由 `useDismiss`（经 `getFloatingProps` 注入的监听）覆盖。

### 现象②根因：Portal 目标 `editor.portalElement` 在 `bn-container` 内，被祖先 overflow 裁掉

`GenericPopover` 的 Portal 目标解析顺序是 `props.portalElement ?? editor.portalElement`，
而 `editor.portalElement` 由 `BlockNoteView` 挂在 **`bn-container` 内部**
（`BlockNoteView.tsx:195`）。该节点在编辑页里处于带 `overflow` 约束的滚动容器中 ⇒
`placement: "top-start"` 的面板一旦向上溢出容器顶部就被**沿容器边界裁掉**。
**修法**：`<PositionPopover portalElement={null} ...>`。`GenericPopover` 对
`props.portalElement === null` 会走 `document.body`（见其 `portalRoot` 解析），
彻底逃出所有祖先 `overflow` / `transform` / `clip-path`。
⚠️ 两个参数必须**同时**给：只给 `portalElement={null}` 会让面板落到 `document.body`，
而 `document.body` 正是 `FloatingFocusManager` 判定的「外部区域」⇒ 不配 `disabled` 必被立刻关闭。

### 复用要点
- ★ **`useRef` 当「快照」用是 React 里的经典陷阱**：ref 变更不触发渲染，
  凡「渲染结果依赖该值」就必须用 state / `useMemo`。用 `useEffect` 去补 ref，
  补上了也不会重渲。**判断口径：这个值变了需不需要重画？需要就不能放 ref。**
- ★ **官方 `PositionPopover` 不是「素」浮层**：它带 `FloatingFocusManager` + 默认 Portal 到
  `bn-container` 内部，与 WebView 场景存在两处硬冲突（焦点自毁 / 裁剪）。
  在 WebView 里复用它，`focusManagerProps={{disabled:true}}` + `portalElement={null}`
  基本是标准配置。
- ★ **日志能同时排除和坐实多个假设**：本轮先凭日志确认了「不是传参/不是命令链路」
  （`openLinkPanel: 6-6 url=` 正常上行），再看到 `editorFocus=false` 这条**唯一的异常信号**
  才把矛头指向 `FloatingFocusManager`。若不看日志，很容易先去查 `position` 计算。
- 产物：`bn-src:2bda0c9fd677` → **`bn-src:c0b3bb43813f`**（1,924,339 字节，
  时戳 `2026-09-23 16:20:17`），钩子 `[OK]`；`tsc --noEmit` EXIT=0。

## 第九轮（16:35+）灵感时间线摘要「行距翻倍」——块间空行被 Compose 原样渲染

**排查起点（重要）**：用户问的是"为什么多了空格"，但**先确认了字符完全一致**

### 续（同一轮，用户追加）：分割线上下行的空格 —— 发现「空格占位」是第二个漏网口

**用户报**：「测试分割线」里的分割线在时间线页不渲染，**但上下行中间也不要出现空格**。

**复现（Python 等价实现）**：
```
原文      '第莫四个了年龄已不\n\n---\n\n测试二和一些克隆你二弟也行'
剥分割线后 '第莫四个了年龄已不\n \n测试二和一些克隆你二弟也行'   ← 中间那行是「一个空格」
```
**根因（我的第一版修复有缺口）**：`toPlainText` 第 6 步把分割线替换成 **`" "` 空格占位**，
于是该行变成"**只含一个空格的非空行**"——它**不是空行**，`collapseBlankLines` 里的
`\n{2,}` **匹配不到 `\n \n`** ⇒ 躲过折叠，上下行之间仍多出一整行。

**修法（两层，都必须改）**：
1. **`MarkdownParser.toPlainText` 第 6/6b 步：替换串 `" "` → `""` + 吃掉行尾换行**。
   依据：分割线是**独占一段**的块级元素，该行文字内容本就为零，
   "用空格隔开相邻词"的理由不成立（相邻词在分割线的**上/下两行**，中间本就有换行）。
   ⚠️ **行尾锚 `[ \t]*$` 必须保留**：我第一版草稿把它去掉、只留 `[ \t]*\n?`，
   结果 `--- dashed` 的前三个连字符被单独吃掉、**后缀 `dashed` 残留**（真机风险）；
   并因此**把「带样式」那条从 6b 提到 6a 先执行**，让正确性由**顺序**保证而非依赖锚点。
2. **`InspirationTextUtils.collapseBlankLines` 改「整行判定」**：`split("\n").filter { it.isNotBlank() }`
   —— 行内仅含空白即整行丢弃。**顺带修正口径**：从"把连续空行压成一个换行"
   改为"**删除所有空行**"（用户口径是摘要里**不出现任何空行**，不是保留一个）。
   这样即便将来别的移除规则又留了空格占位，也会被兜住。

**验证（Python 等价实现逐句对齐 Kotlin）**：
- 分割线**六形态**（实线/虚线/波浪线/星号/下划线/带缩进+尾空格）→ 全部 `上\n下` ✓；

## 第九轮（16:26+）链接面板图标变「eat」乱码 —— `portalElement={null}` 的代价

**用户报**：在如图所示位置点链接按钮，面板出现但 `Edit URL` / `Edit title` 的**前置图标变成「eat」**，
输入框也没边框/背景。

**根因（上一轮 `portalElement={null}` 修过度了）**：Mantine 的**全部 `--mantine-*` CSS 变量
直接定义在 `.bn-mantine` 选择器上**（`@blocknote/mantine/src/mantineStyles.css:133` 注释原文
「Mantine default CSS variables, scoped to `.bn-mantine` element」，第 135 / 401 / 532 行三条规则，
后两条是 `[data-mantine-color-scheme="dark"|"light"]` 明暗分支）。
而 `bn-mantine` 类由 `@blocknote/mantine/src/BlockNoteView.tsx:93`
`mergeCSSClasses("bn-mantine", …)` 加在 **`editor.portalElement`** 上。

⇒ 传 `portalElement={null}` 让面板落到 `document.body`，**它不在 `.bn-mantine` 内**
⇒ 变量全失效 ⇒ `TextInput` 的 `leftSection` 尺寸/定位塌掉 ⇒ 左侧图标 SVG 被挤压，
只露出中间几个字母残片（`Edit URL` → 「eat」）。同类规则还有 `.bn-root` 承载的 `--bn-*`（边框/圆角/阴影）。

### 正确解法：自建 Portal 宿主（两边都要）
| 目标 | 逃出 `overflow` 裁剪 | 继承 CSS 变量 |
|---|---|---|
| `editor.portalElement`（默认） | ✗ 在 `bn-container` 内被裁 | ✓ |
| `null` → `document.body` | ✓ | **✗ 图标乱码** |
| **自建容器** | ✓（挂 `document.body` 下） | ✓（自带 `bn-root bn-mantine`） |

```tsx
const panelHost = useMemo(() => {
  const el = document.createElement("div");
  el.className = "bn-root bn-mantine";
  el.setAttribute("data-mantine-color-scheme", scheme);   // ← 属性名不能写错
  document.body.appendChild(el);
  return el;
}, [editor]);
useEffect(() => () => { panelHost?.remove(); }, [panelHost]);
// ... 传 portalElement={panelHost ?? null}
```

### 三个易错点
- ★ **属性名是 `data-mantine-color-scheme`**，不是 BlockNote 用的 `data-color-scheme`。
  Mantine 明暗变量挂在前者（第 401 / 532 行），写错则暗色主题下拿不到暗色变量。
- ★ **scheme 不能只从 `editor.portalElement` 读**：那两处属性由 `BlockNoteView` 的
  `useEffect` 赋值，而本 `useMemo` 可能跑在赋值之前（时序不稳）。改为
  `document.querySelector(".bn-mantine[data-mantine-color-scheme]")` **现查活元素**，
  再回落 `data-color-scheme` → 系统偏好。并在 `useEffect([panelHost, props.open])` 里再校准一次。
- ★ **容器本身绝不能设 `position` / `overflow` / `transform`**：内的 `GenericPopover`
  靠 `position: fixed` + 内联 `left/top` 定位；父级一旦有 `transform`/`filter`，
  `fixed` 会退化为相对该父级定位，定位直接崩。

### 通用教训（最重要的一条）
★ **「逃出裁剪」和「继承样式变量」是两件事，Portal 换目标时二者会同时变**。
上一轮我只验证了「不裁了」，没验证「样式还在不在」——因为**裁剪是肉眼可见的、
变量失效是肉眼不可见的**，于是漏掉了后者。**凡是把 UI Portal 到新目标，
必须同时检查：① 位置/裁剪 ② 该元素的 CSS 变量/字体/主题类名从哪继承**。
本项目此前已有同型踩坑记录（divider 工具条 Portal 后 `--editor-primary` 静默退回硬编码蓝）。

## 第十轮（16:52+）链接面板宽度塌陷（第三轮返工）

**用户报**：在「链接1/2/3」处点底部工具栏链接按钮，面板仍被裁剪。三张截图显示：
面板**左缘贴锚点、右缘贴编辑区右边界**——即宽度 = 「锚点到容器右缘的剩余空间」。

**好消息（可确认前两轮修复生效）**：第三张图里 `Edit URL` / `Edit title` 两个输入框都在、
**图标正常、有边框** ⇒ 第九轮的 CSS 变量修复有效；日志中 `linkPanel anchor: open=true … anchor=yes`
每次都立即出现 ⇒ 第八轮的「首次点不出现」也好了。**本轮纯粹是宽度问题。**

### 根因：宽度不由内容撑，而由「包含块可用空间」决定
`GenericPopover` 的浮层 div（`GenericPopover.tsx:226-236`）被写成：
```js
style: { display: "flex", ...floatingStyles }   // floatingStyles 来自 useFloating
```
`useFloating` 默认 `strategy: "absolute"` ⇒ 浮层是 **`position:absolute; width:auto`**。
此时 `width:auto` 的解析规则 = **可用宽度（包含块宽 − left）**，而非 `fit-content`。
于是链条变成：
1. `.bn-form-popover` 自身**没有 width**（库 `blocknoteStyles.css:218`）；
2. 官方的撑开机制是内部 `.bn-form-popover .mantine-TextInput-root { width:300px }`
   （同文件 **17-20 行**）——**但那只在「浮层不受外部宽度约束」时才成立**；
3. 我的第十轮前代码给 `panelHost` 设了 **`width: 0`**（当时的设想是「只作挂点、不占位」）
   ⇒ 包含块可用宽度 ≈ 0 ⇒ flex 项被压缩 ⇒ 面板塌成一条窄条。

★ **教训：`width:0` 的 Portal 挂点容器会掐死内部 `position:absolute; width:auto` 的浮层。**
「零尺寸挂点」这个直觉对 `fixed` 定位的浮层成立（如 emoji 面板），
但对 **`absolute` 定位**的浮层**不成立**——后者要吃掉包含块的可用空间。

### 修法（两处，互为防线）
1. **容器铺满视口**：`panelHost` 改 `position: fixed; inset: 0`。
   ① 明确成为包含块，且内容区与视口**完全重合**（左上角对齐）
   ⇒ floating-ui 按视口算出的 `left/top` 落进来后坐标不变；
   ② `fixed` 脱离文档流，不会把 `body` 撑高、不产生滚动条。
2. **内容宽度写死**：内容 div 显式
   `boxSizing:border-box; width:min(306px, calc(100vw - 32px)); minWidth:0; flexShrink:0`。
   - **306 的出处**（对齐官方，不另创尺寸）：`TextInput-root 300px`
     + `.bn-form-popover` 左右 padding 各 2px（库第 14 行 `padding:2px`）
     + 左右 border 各 1px（库第 8 行 `border: var(--bn-border)`，本项目主题为 1px）= **306px**。
   - `minWidth:0` 覆盖库的 `min-width:145px`，避免两套宽度打架。
   - `flexShrink:0` 必需：外层是 flex 容器，空间不足时会把写死的 width 压掉。
   - 用 `100vw` 而非 `window.innerWidth`：WebView 里等价，且**不会因键盘弹出而取值过时**。

### 同时新增「浮层实测矩形」埋点（供本轮真机判读）
`useEffect` 里经**双 `requestAnimationFrame`** 后回捞 `panelHost.firstElementChild`
的真实 `getBoundingClientRect()`，上报：
`x/y/w/h` + `vw/vh` + `position/display/minWidth/maxWidth` + 内联 `left/top/transform`
+ `hostW`（容器宽）+ `contentW`（内容层宽）。
- 为何要双 rAF：floating-ui 在 mount 后的 effect 里才写入 `left/top`，同步读会拿到 0。
- 判读表：`w` 远小于 306 → 宽度仍被约束；`hostW=0` → 容器样式没生效；
  `x` 恰等于锚点 x 且 `w = vw - x` → 仍是「锚点到右缘」的旧病。

### 三点提醒（写进注释防回退）
- ⚠️ 容器**不能设 `display:none` / `visibility:hidden`**：子树无法测量，floating-ui 的
  「先测后定」直接失效（`getBoundingClientRect()` 全返回 0）。

## 第十一轮（17:00+）编辑页无法聚焦/键盘呼不出 —— 轮十 `inset:0` 未配 `pointer-events` 的代价

**用户报**：编辑页正文区聚焦不了光标、光标消失、键盘呼不出，并直接点名「是你改动造成的吗？」
——**答案：是**。轮十给 `panelHost` 改 `position:fixed; inset:0` 时没设 `pointer-events`。

**根因机制**：
- `panelHost` 由 `useMemo([editor])` 创建，**挂载即建、常驻 DOM**（不随面板开关出现/消失）；
- `position:fixed; inset:0` = 一层覆盖整个视口的透明 div；
- **透明 ≠ 点击穿透**：CSS 命中测试只看几何与 `pointer-events`，完全不看透明度；
  而它没有 `pointer-events:none` ⇒ 命中测试永远命中最上层的它 ⇒ **所有触摸被吃掉**，
  编辑器 `contenteditable` 收不到任何 down 事件 → 无法聚焦、光标消失、键盘不弹。
- **为什么轮十之前没暴露**：更早版本容器是 `width:0`——零命中面积，纯挂点；
  改 `inset:0` 铺满视口后才产生全屏命中区。属「修 A（宽度塌陷）引入 B（吃触摸）」。

**修法（分层，两处成对）**：
1. 容器：`el.style.pointerEvents = "none";`（宿主不吃任何点击，只作挂点）；
2. 浮层：`<PositionPopover elementProps={{ style: { pointerEvents: "auto" } }}>`——
   `pointer-events` 是**可继承属性**，容器 none 会让子树全部穿透，故浮层必须显式恢复 auto。
   已核对 `GenericPopover.tsx:226-236` `mergedProps` 合并顺序：
   `{...props.elementProps, style:{display:"flex", ...elementProps?.style, zIndex, ...floatingStyles, ...}}`
   —— `elementProps.style.pointerEvents` 先展开、不被后续键覆盖 ⇒ **存活**。

**⚠️ 修正轮十笔记里的错误结论**：「不要给容器加 pointer-events:none（输入框要点）」是**错的**——
正确姿势是**分层**：容器 none（不吃点击）+ 浮层 elementProps 恢复 auto（面板可交互）。
两者缺一：只 none → 面板点不了；只 auto 不设 none → 全屏吃触摸（本轮故障）。

**★ 教训（升级为通用规则）**：
1. **透明 ≠ 点击穿透**——「看不见」的浮层照样拦截触摸；判断一个常驻 DOM 层是否挡事件，
