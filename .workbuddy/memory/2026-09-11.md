## 双指非中心放大 → 松手"生硬归位"（09:56 修复，未编译）

**根因**：双指抬起几乎总有先后 —— 第一根手指一抬就进单指分支，旧逻辑**瞬间把 offset 夹回边界**；
缩放锚点换算在"未撑满轴"（如竖屏看方图，纵向 maxOffset=0）上产生的越界量被直接砍掉 → 图片瞬移。
缩小时没被抱怨是因为 scale<1 走 scale+offset 同步回弹，把瞬移盖住了。

**修复（统一归位动画）**：
1. 新增 `launchSettleAnimation`：把越界 offset 用与「缩小时归位」「松手收回」同一条弹簧
   （ZoomReboundSpec）拉回边界；返回是否真的启动（界内 no-op）。
2. 手势循环加 `prevMultiTouch`：多指→单指过渡瞬间启动该动画并置 `settling=true`；
   settling 期间 offset 由动画**独占**（跳过平移写入、跳过翻页判定、丢弃 pan 输入），
   循环开头用 `settleJob?.isActive` 检测动画结束自动恢复。
3. `settleJob`（remember 的 Job 状态）管理动画生命周期：双指重新按下、缩放回弹启动前
   都先 cancel，避免双动画写同一状态打架。
4. settling 期间**不累加 desired**（否则动画结束后 desired≠offset 会跳变）；
   `screenOverscroll` 用 when 冻结（multiTouch||settling 不动翻页状态）。
5. 松手 `scale>=1f` 的内联收回动画改为调用同一个 `launchSettleAnimation`。

**设计要点**：settling 只在"offset 越界"时发生；翻页中图像钉在边界（界内）→ 过渡不越界
→ 不启动动画 → 与跟手翻页互不干扰。

## 灵感编辑页「重新进入时缩小图从大到小闪一下」（v2026-09-11，未编译）

**根因**：`BodyBlock.Image.shrunk` 是内存字段，持久化真相在 DB 的 `displayWidthRatio`。
加载分两步：① `initialize` 解析 markdown 只还原 path，`shrunk` 默认 `false` → 首帧满宽；
② `hasInitialized` 触发 `LaunchedEffect` 读 DB `loadContentBlocks` 再 `applyImageProps` 把 `shrunk`
补成 `true`。`BlockImageItem` 的 `animateFloatAsState(target = if(shrunk) 0.5f else 1f)` 只在
targetValue 跨重组变化时播动画 —— 这次**后置回填翻转**被误判为值变化，从 1f 动画到 0.5f，
即"从大到小变一下"。`InlineImagePreview` 只透传 widthFraction，自身不播宽度动画（Coil crossfade 是淡入）。
新建灵感（inspirationId==null）不跑 applyImageProps，故仅"保存退出再进已有灵感"复现。

**修复（方案 A：加载回填期禁用动画）**：
- 新增 `BodyBlocksController.loadRestoreComplete`（internal var）+ `resetImagePropsRestore()`（置 false）/
  `markImagePropsRestored()`（置 true）。
- `BlockImageItem` 动画 spec：`loadRestoreComplete` 为 false 用 `snap()`（瞬时），为 true 用 `tween`。
  回填翻转走 snap 不播动画；回填后用户点「缩小/恢复」才平滑。
- `InspirationEditScreen` 的 `LaunchedEffect(hasInitialized)`：进入先 `resetImagePropsRestore()`；
  已有灵感在 `applyImageProps` 之后 `markImagePropsRestored()`；新建灵感早退分支也 `markImagePropsRestored()`。
  reset 防 ViewModel 跨退出再进入被保留时残留 true 导致二次进入复现。
- 新增 import `androidx.compose.animation.core.snap`。

**验证点（待用户 build）**：保存缩小图→退出→再进，缩小图应直接以半宽静止呈现（无缩小动画）；
进入后点「缩小/恢复」仍平滑缩放。

### 二次修复（15:49 用户复测仍闪烁）—— snap 治标不治本，改为首帧前回填

**用户复测结论**：snap 方案无效，仍"从大到小"。**重新推演确认方法不彻底**：
snap 只消除缓动过程，没消除「首帧满宽 → DB 回填半宽」的**可见时间窗口**——
`loadContentBlocks` 是 suspend DB 查询，`LaunchedEffect(hasInitialized)` 触发到
applyImageProps 之间主线程已让出，满宽图渲染了几十~上百 ms 后跳到半宽，
跳变本身就是"从大到小"（tween 只是让它看起来像动画）。修复代码未丢失
（git show 确认 80dc0df4 在，工作区后续改动是图片粘贴工具栏另一条线）。
