# 2026-09-17

## BlockNote 撤销/重做按钮收归宿主顶栏（v1.7）

**需求**：灵感编辑页删除 BlockNote 内部的「↺ 撤销 / ↻ 重做」按钮，桥接到页面左上角画红圈的撤销栈图标。

**关键发现**：截图里那对胶囊按钮**不是 BlockNote 官方 UI**，而是 `blocknote-probe/src/editor/EditorApp.tsx` 里自绘的
`AutoRepeatButton`（位于 `.editor-toolbar` 容器，调 `editor.undo()/redo()`）。官方从未内置这对按钮，
`BlockNoteView` 也没有对应关闭配置——**只能删代码**。
而宿主顶栏那对 ↶/↷ 图标按钮**早已桥接完成**（`blockNoteController.undo()` → JS `editor.undo()`），
所以核心工作其实只是「删 JS 侧自绘按钮 + 补可用态上行」。

### 撤销/重做的正确判定 API（重要）

BlockNote **公开** `editor.can(editor.undo)` / `editor.can(editor.redo)` 返回 boolean。
原理（读 `node_modules/@blocknote/core/src/editor/managers/StateManager.ts`）：
`can(cb)` 置 `isInCan=true` 调 cb，`exec()` 见 `isInCan` 走 `canExec()` 分支——**只判定不 dispatch**，
绝不污染历史栈。
> ⚠️ 不要走 `editor._tiptapEditor.can().undo()`（私有字段、跨版本易碎），也别
> `editor.on("transaction", ...)`——`BlockNoteEditor extends EventEmitter<{ create: void }>`，
> **只有 `create` 一个事件**，没有 transaction 事件（`EventEmitter.ts` 的 `emit` 是同步的）。

`editor.on("update", cb)` 存在但不覆盖全部路径，故本方案用「onChange + undo/redo 后主动推」覆盖。

### 长按连发已放弃

原 JS `AutoRepeatButton` 有按住连退（450ms 后每 150ms），**本次未在 Compose 侧复刻**（用户选「仅删按钮+同步 canUndo 状态」）。
顶栏 `IconButton` 是即点即走。若日后要恢复，需 `pointerInput` + `awaitPointerEventScope` 自建长按循环。
