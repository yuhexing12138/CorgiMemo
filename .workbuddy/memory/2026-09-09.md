## 图片块拖拽交换"上下跳动"诊断与修复（A + B）

- **根因**：`sh.calvin.reorderable.ReorderableColumn`（非 Lazy 版）内部是 `Column { list.forEachIndexed }`（`Reorderable/reorderable/.../ReorderableList.kt:406`），**item 无 key**。交换两块后第 i 个组合槽位被复用渲染另一个块 → `SubcomposeAsyncImage` model 变化 → Coil 重载 → 状态回 Loading → 高度掉到 180dp 占位 → Success 后弹回 → 下方内容上下跳动。只在图片之间出现（文本高度不依赖异步加载）；撑满宽度后高度落差大，现象才明显。
- **已排除**：落点几何本身连续——`settle()` 里 `itemOffsets[i].animateTo(offsetToTarget)` 是 suspend，动画结束才 `onSettle`，被拖项落点 offset 与交换后布局位置严格相等（相邻交换让位量 = size+spacing）；且 `remember(list, spacing)` 按结构相等比较，交换后 list 不等 → state 重建 → offsets 归零，无残留错位。
  - **隐患记录**：若 `BodyBlock` 改成 data class，或两块内容完全相同（同 path 图片），list 判定相等 → state 不重建 → 残留 offset 会造成真正的错位跳动。
- **修复 A（根除）**：`BlocksReorderableColumn` 新增 `itemKey: (T) -> Any?`，在 `ReorderableItem` 内用 `key(itemKey(item))` 包 content；`BodyBlocksEditor` 传 `{ it.id }`。组合身份跟随块移动，painter 不重载。
- **修复 B（兜底）**：`InlineImagePreview.kt` 新增进程级 `ImageAspectRatioCache`（ConcurrentHashMap，path→宽/高），success 写入；loading/error 占位态命中缓存时改用 `aspectRatio(cached)` 而非固定 180dp —— 任何重载场景（交换/旋转/详情页返回）高度都不塌陷。
