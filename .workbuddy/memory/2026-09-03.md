- **用户新证据（关键）**：设置页「正文字体」点选多次同样闪退。设置页与编辑页**共享 FontCatalog/FontEntry + 各自面板预览 helper** → 崩因是**结构层**的，不是页面局部：① 两页预览都经 `ResourcesCompat.getFont` 把 12 款字体驻留进 `TypefaceCompat` LruCache(16)；② 两页「内容」（设置=全局 Typography、编辑=LocalContentTypography）点选逐次经 FontFamilyResolver 再各驻留一款 → 预览 12 + 内容逐次 N 双计，占满 16 槽即瞬态 OOM。
- **新方案（统一引擎，两页共用）**：新建 `ui/theme/FontPreviewEngine.kt`——
  - 有界 Typeface 池 `LruCache(3)`：`Typeface.Builder(String)` 从 cacheDir 临时文件即时构建（绕过 TypefaceCompat），画完即弃；
  - 预览位图缓存 `LruCache(16)`（白色字形蒙版，tint 着色）；
  - `prerenderAll`（编辑页：刻记 26sp / Corgi 19sp）与 `prerenderBodyRows`（设置页：各字体 displayName 18sp）两套预热，均 `Dispatchers.IO` 顺序渲染 → 完成后 `clearTypefaces()` 清池 → **预览常态 0 常驻字体**（只留位图）；
  - `typefaceForWeight(context,entry,weight)` 供 FontWeightProbe/工具栏字重探测（同样走有界池，避免探测再驻留一套）。
- **接入**：`FontPickerPanel.kt`（删私有 fontPreviewCache/loadPreviewTypeface/renderFontPreviewBitmap/spToPx，`LaunchedEffect{prerenderAll}` + 单元格只读 `getBitmap`）；`AppearanceScreen.kt`（拉丁组预览也改走 `FontBodyPreview` 位图分支——仅选中行走实时 Text；删全部私有 helper + ResourcesCompat import，`LaunchedEffect{prerenderBodyRows}`）；`FontCatalog.kt` `typefaceForWeight` 委托引擎（删 `resources.getFont`/Build import）。
- **结构结论**：预览只留位图（~0 常驻字体）；「内容」字体经 FontFamilyResolver 常驻 ≤12 款 CJK ≈204MB，与预览隔离 → 整体 <256MB。预览与内容各走各的缓存不再双计，两页反复点选均不崩。系统默认条目用 `Typeface.DEFAULT` 渲染（保持「系统默认字体」行可见）。
- **验证方向**：编辑页顺序点选（含第 5 款起）+ 设置页反复点选均不崩、实时变字；两页预览位图首开预渲染（首次 IO 预热后即快）。未编译（约定）。改完未提交。

## 七次修复（用户方向确认后落地）：重编后十几次点选仍崩 → 平台硬约束确认 + 「点选即预览 + 完成/离页应用」
- **新证据（用户）**：重编后在两页各反复点选十几次仍崩。此轮先用 javap 核查 compose-ui 1.11.2：`FontFamily.Resolver` 仅 `preload`/`resolve`，**无清缓存 API**（无法程序化逐出已缓存字体）→ **「内容/全局」字体经 FontFamilyResolver 对每款点选字体按 (族,字重) 永久缓存、且整页 UI 用多字重，每款实际驻留 ~20-50MB**；largeHeap 已开但设备上限 256MB → 只要「点选即真实切换内容字体」物理上必 OOM。
