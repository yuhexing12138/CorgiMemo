## 收起按钮「展开后不可见」bug 修复（animateContentSize clipToBounds 裁剪）

- 现象：时间线档（按钮左移出 Stage 左缘）时，展开后按钮消失；图片行档（按钮在 Stage 内）正常。
- 根因：`animateContentSize` 内部实现是 `this.clipToBounds().then(animModifier)`，**持续裁剪 Stage 内容到布局边界**；
  按钮右缘要相切竖线左缘 77dp，而 Stage 展开态布局左缘 = 88dp，按钮必然落到 Stage 左缘之外 → 被 clipToBounds 裁掉。
  之前堆叠图左滑能溢出是因为堆叠态 Stage 已左扩 StackLeftCompensation(130dp)，卡片左滑不超出布局边界。
- 修复（复用项目「布局空间预借」机制，展开态 Stage 左扩）：
  1. 新增 `collapseBtnLeftExtend = 11.dp + collapseBtnW`（collapseBtnW = 收起按钮宽 = H/2）。
  2. Stage offset 加 `- collapseBtnLeftExtend * p`（展开态左扩 11+W，覆盖按钮本体）。
  3. 内容包装层 offset 加 `+ collapseBtnLeftExtend * p`（补偿，图片行左缘恒定 88）。
  4. 按钮 offset 简化为 `(StackLeftCompensation - 11.dp - collapseBtnW) * (1 - p)`（展开态 = 0，按钮左缘恰在 Stage 左缘、不被裁）。
- 高价值经验：**凡是依赖「超出容器布局边界显示」的内容（offset 移出），若祖先有 animateContentSize，
  必被其内部 clipToBounds 裁剪**；解法不是 clip=false（挡不住祖先 clipToBounds），而是「容器左扩 + 内容层 offset 补偿」。

## 收起按钮左扩的副作用修复（图片行左缘消失边界左移）

- 现象：Stage 左扩覆盖按钮后，展开态图片行左滑的「消失边界」跟着 Stage 左缘从 88 左移到 47
  （原本图片行左滑消失边界由 Stage clipToBounds 左缘提供）。
- 修复：给内容包装层 drawWithContent 补「左缘裁剪」，随 p 过渡：
  `left = -StackLeftCompensation.toPx() * (1f - p)`（堆叠态 = -SLC 允许顶卡左滑翻牌、与 Stage 堆叠态左缘一致；
  展开态 = 0 即视口左缘 88，图片行左滑到 88 消失）。按钮在包装层外，不受该左缘裁剪，仍落在 Stage 内可见。
- 关键：包装层左缘（本地 0）恒 = 屏幕 88，故左缘裁剪线本地 0 正好对应消失边界 88，与 Stage 左扩无关。

## 图片行「同行空白」点击不进详情页（V8.16 吞噬层）

- 需求：点「堆叠态」和展开后「图片行状态」的同一行空白处，不应进入灵感详情页。
- 根因：外层卡片 Box 的 `combinedClickable` 覆盖整卡；图片区只有卡片自身有 clickable，
  同行空白必然穿透冒泡进详情页。组件内 V8.14f 吞噬层补不上，有两个洞：
  ① 激活条件 `swallowActive = expandProgress > 0f` → 堆叠稳态 p=0 完全不吞噬；
  ② 吞噬范围只有 Stage 自身 bounds → 堆叠态 Stage 右缘 ≈288dp 到屏幕右缘的空白不在范围内。
- 修复（用户拍板左边界 = 整行，屏左→屏右）：在 `TimelineInspirationItem.kt` 图片**外层 Box**
  自身 modifier 挂 `pointerInput(Unit) { detectTapGestures(onTap = { }) }`（在 graphicsLayer 之前）。
  该 Box 是 SwipeableImageStack 的祖先、fillMaxWidth + offset(-18dp) → 覆盖屏幕 0 ~ 屏宽-36 整行，
  pointerInput 恒在命中链末端，接住所有未被更深层消费的 tap。
- 两层吞噬分工（已写入两处注释）：调用方外层 Box 兜底整行；组件内 Stage 层保留，
  因为展开态 Stage 右缘 ≈屏宽+52，超出调用方 Box 右缘，「屏宽-36 ~ 屏宽」这段只有 Stage 能接住。
- 高价值经验（Compose 命中测试）：**做「空白点击吞噬」必须把 pointerInput 挂在祖先的 modifier 上**，
  挂成兄弟 Box 不可靠 —— 实测（V8.14f）兄弟吞噬层会被上层子树遮蔽，
  上层子树 layout 覆盖区内即使没有任何 tap 消费者，事件也不会回落到兄弟吞噬层。
- 手势安全：detectTapGestures 不提供 onLongPress → 长按仍走外层 combinedClickable 弹菜单；
  drag 被更深层消费 → tap 自动取消，翻牌/横滚/列表竖滚不受影响。

  （含 TimelineInspirationItem.kt +27、SwipeableImageStack.kt +10/-2 注释）。

## 收起按钮去掉点击水波纹（V8.17）

- 需求：点击「收起」按钮时不要有水波纹。
- 改动：`SwipeableImageStack.kt` 收起按钮 `.clickable {}` → 
  `.clickable(interactionSource = remember { MutableInteractionSource() }, indication = null) {}`。
  新增 import `androidx.compose.foundation.interaction.MutableInteractionSource`。
- 坑：`indication = null` **必须同时显式传 `interactionSource`**，否则不生效
  （clickable 的 indication 参数默认值依赖 interactionSource）。
- 去波纹只影响绘制：点击语义、点击热区、无障碍语义均不变。
- 范围：用户最终拍板**两个按钮统一都无波纹** —— 展开按钮（L2196）与收起按钮（L2300）
  均已改为 `indication = null`。
- 实现细节：两个 interactionSource 都提到各自 `if` 分支**外** remember。
  展开按钮的 `isBtnClickable = expandBtnAlpha > 0.01f && isInStackedMode && !isAnimating`
  随展开/收起动画频繁翻转，若 remember 写在分支内会因 slot 位置漂移被反复重建。
- 高价值经验：**Compose 里在条件分支内调用 remember 有风险** —— 条件频繁翻转时
  slot table 位置漂移 → 状态被丢弃重建。应把 remember 提到分支外，
  分支内只引用该变量。
