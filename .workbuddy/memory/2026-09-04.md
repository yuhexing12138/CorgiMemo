## 第三轮：连续换字 ~25 款后 OOM 闪退（实测 meminfo 数据）
- 实测两份快照（mem_before/after.txt，UTF-16 编码需 iconv 转 UTF-8）：连切约 25 款字体后 TOTAL PSS 232975→462197（+229MB）。

## 第六轮：第五轮修复后仍「中文不生效」——真正根因是 setFallback 误用
- **现象（用户复测）**：第五轮用 `Typeface.Builder(latin).setFallback(cjk).build()` 合成后，拉丁生效、中文仍不变（编辑页 + 设置页两处）。
- **真正根因（javap 反编译 android-36 `Typeface.Builder` 实证）**：`setFallback` 在该 stub 里**只有 `setFallback(String familyName)` 一种重载**，参数必须是**系统已注册的字族名**（如 "sans-serif"），传文件路径会被当成家族名找不到→回退链失效→中文落系统字体。且 `setFallback(int)` 与 `addCustomFallback` 在该 stub 中**均不存在**（第五轮最初误用 `addCustomFallback` 报错、改 `setFallback` 也没真生效，同源）。`Typeface.create(FontFamily, FontStyle)` 也不存在于该 stub。
- **正确修复（字形级回退）**：改用 **`Typeface.CustomFallbackBuilder`(API 29+)**：`CustomFallbackBuilder(latinFamily).addCustomFallback(cjkFamily).setStyle(...).build()` 把拉丁作 base、中文作自定义兜底，单一 Typeface 内按字形回退（拉丁字形走拉丁、中文走中文）。构建 `FontFamily` 用 `android.graphics.fonts.Font.Builder(File).build()` → `FontFamily.Builder(font).build()`（与 Compose 的 `Font`/`FontFamily`/`FontStyle` 重名，已用 `GFont/GFontFamily/GFontStyle` 别名隔离）。
- **降级**：`Build.VERSION.SDK_INT >= Q` 守卫；API 26–28 无公开自定义回退 API，退化到单一字体（优先中文，`Typeface.createFromFile`）。守卫内引用 Q-only 类在 <29 不执行，不会触发类加载异常。
- **改动文件**：`FontCatalog.kt`（imports 加 `android.os.Build` + 三个 graphics 字体别名；`fileTypefaceCache` 改 `LruCache<Long,Typeface>`（合成 key 含字重，避免 Int 溢出），`FilePathTypefaceLoader` 同步 `.toLong()`；`CombinedTypefaceLoader` 加 `weight` 参数，逻辑改走 `buildCombinedTypeface`+`combinedKey`+`buildFontFamily`；`CombinedAndroidFont` 传 `weight.value`）；`FontManager.kt`（combinedFamily 注释同步为 CustomFallbackBuilder）。
