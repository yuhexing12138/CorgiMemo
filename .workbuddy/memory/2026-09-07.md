## 空列表项回车按层级区分（灵感编辑页 bug 修复）
- 用户反馈：有序列表 "1. 测试1" 下空的二级项 "(1)" 回车，出现 "1.测试1"+"空行"，应出现 "1.测试1"+"2."。
- 根因：`BodyBlocksEditor.kt` 中 `splitTextBlock`（硬键盘）与 `normalizeBlockParagraphs`（软键盘）的「空列表项回车」分支一刀切——`isEmptyListItem` 命中即整块替换为普通空块（退出列表）。该行为当初为一级列表定制，未区分层级。
- 修复（用户确认方案：层级区分 + 有序/无序对称）：
  - 新增共用函数 `exitListOrDedentEmptyListItem(block, idx)`：一级空项回车 = 退出列表（原行为）；二级及以上 = 降一级（dedent），整块重建为上一层级同类型空列表项。
  - 有序编号不手动算：`executeAndPush` 内既有 `renumberOrderedBlocks()`（层级感知位置语义）自动把降级块续为 "2."。
  - 光标经 `refocusListBlock` 修正到 marker 之后；撤销走既有 `ReplaceBlocksCommand`（stash 原样还原）。
- 关键机制确认：库解析（`RichTextStateMarkdownParser` v2026-09-05 改版）按**源码行首缩进**还原列表 level（spaces/2+1），与 `listLevelOfMd` 对称；独立块 `setMarkdown("  1. ")` 即得 level 2 空项（<4 空格不落代码块）。
- 测试：`BodyBlocksControllerTest` 新增 4 用例（二级有序降级续号 2 / 一级退出列表回归 / 二级无序对称降级 / 降级可撤销还原）。未编译（按约定），待用户验证。

## 六级罗马空项降级光标错位（第二次反馈修复）
- 用户反馈：六级"ⅰ."空项回车降为五级"Ⅰ."后光标落在 marker 左侧（应在右侧）。
- 根因：库的罗马数字（`OrderedListStyleType.LowerRoman/UpperRoman`）用 **ASCII 字母**拼写（"i"/"I"，`formatToRomanNumber`），非 Unicode ⅰ/Ⅰ；`refocusListBlock` 旧正则 `[Ⅰ-Ⅿ]`（U+2160-216F）匹配不了 ASCII "I."，`[a-z]+` 只覆盖小写 → 五级 "I. " 失配 → markerEnd 回退 0 → 光标落最左。六级 "i."（小写）恰被 `[a-z]` 兜住，只有降入五级才暴露。
- 修复：`refocusListBlock` 正则 `[a-z]+|[Ⅰ-Ⅿ]+` 合并为 `[a-zA-Z]+`（覆盖四级 a. 与大小写罗马 ASCII 形态），删除永不命中的 Unicode 罗马分支。可见 marker 解析仅此一处（isMarkerOnlyMarkdown/renumber 走 markdown 字面编码，不受影响）。
- 测试：新增 `空六级罗马项回车降五级光标落marker右侧`（逐级 indent 到 6 → 回车降 5 → 断言 pendingFocus offset=3）。
- 提交：949b1b6e（层级降级修复）、3029ab8c（光标修复）。

## 纯文本缩进改版（用户需求：不出现列表符号）
- 需求：无列表纯文本按「缩进」键 → 直接缩进两字符，不转无序列表（旧行为"自动转列表"是 2026-09-05 用户选定，本次明确替换）。用户确认：视觉=**首行空两格**（EM SPACE 文本前缀，折行后第二行顶格）；**6 级封顶**（与列表一致）。
- 实现（纯 App 侧，零子模块改动）：`indentPlainBlock`——段首插/删 2 个 U+2003（EM SPACE，每级≈两字符宽）：
  - 持久化零成本：U+2003 是普通文本字符，CommonMark 不当缩进/代码块前缀，随块 markdown 原样往返（规避了列表层级前缀 ≥4 ASCII 空格落代码块的坑——EM 不是 ASCII 空格）；
  - 字数统计不受影响（InspirationTextUtils 按 isWhitespace 过滤，U+2003 属空白）；
  - 撤销走块内 history（库 onTextFieldValueChange 统一 recordHistory，Typing 组可能合并→测试用循环 undo 断言）；
  - 光标/选区操作后平移 ±2 保持相对位置；canIncrease/canDecreaseIndent 普通文本分支改按前导 EM 级数判断；
  - observer 兼容：EM 块文本非空不触发 ZWSP 空块维护；无 \n 不拆块；isOrderedList 不翻转。
- 边界口径：缩进层级只认 U+2003（功能自插字符），用户手打的全角空格（U+3000）不计入（如需再扩展）。
- 测试：新增 4 用例（缩进不转列表+markdown 保留 / 可撤销 / 6 级封顶+逐级减少 / 往返保留+加载后可减）。

## 纯文本缩进第二版：整体缩进（用户实测后否定首行缩进）
- 用户反馈：连按缩进应是**整体缩进**（整段所有行左移），非首行缩进。EM 文本前缀只能首行缩进 → 改为**段落属性**方案（改子模块）。
- 库改动（compose-rich-editor，3 文件）：
  - `DefaultParagraph` 属性化：实现 ConfigurableListLevel，`level`（1=无缩进）；getStyle 返回 `TextIndent(firstLine = restLine = config.orderedListIndent × (level-1))`（整段左移，步长复用 30sp）；equals/hashCode 含 level；copy/getNextParagraphType 保留 level。
  - parser 编码端：`appendParagraphStartText` 对 DefaultParagraph level>1 输出段首 EM 前缀（每级 2 个 U+2003）；decode 对每段落无条件输出 start text（空缩进块也有前缀 ✓）。
  - parser 解码端：onOpenNode 记录 PARAGRAPH 起始段落 index；onCloseNode(PARAGRAPH) 剥首个文本 span 的段首 EM 前缀 → `(type as DefaultParagraph).level = 前缀对数+1`（EM 是连续源文本前缀，单 span 剥除安全；剥空移除 span）。
  - `RichTextState.setParagraphIndent(level, commitHistory)` 公开 API：抄 setListMarker 模式（updateParagraphType 校正光标；仅作用 DefaultParagraph 段落，列表 no-op）。
- App 改动：indentPlainBlock 改调库 API（层级读 markdown EM 前缀 plainIndentLevelOfMd，与 listLevelOfMd 同款）；canIncrease/canDecreaseIndent 同口径；mergeTextBlocks 对后块 curMd 剥 EM 前缀（markdown 拼接后非段首、解码不剥会残留宽空格；Word"合并到前段格式"同语义）。
- 关键验证：`toMarkdown(range)` 经 extractRangeState 的 `paragraph.copy()` 保留 type/level → 缩进块拆块前后段都自动带前缀继承缩进（无需 App 补偿）；查看卡片等整篇 setMarkdown 路径经库解码钩子同样还原缩进（编辑/查看渲染一致）；旧版 EM 文本数据加载时被解码端剥除转属性（无缝迁移）。
- 语义统一：用户手打的段首 U+2003 加载时也会被转为缩进属性（视觉一致，Backspace 不再可删——缩进升级为格式语义）。
- 测试：4 用例断言改版（EM 只在 markdown 载体、段落文本干净；撤销循环断言；往返用例加"文本剥前缀"断言）。未编译（按约定）。

## 缩进块内容起点退格：逐级减缩进（用户需求）
- 需求：6 级缩进的"测试"，光标移到"测"左侧退格应一级一级减缩进（Word/Notion 标准行为），而非删字/合并。
- 三路拦截汇聚 `onBackspaceAtStart`（最前加缩进分支：纯文本 level>1 → dedent，return；一级回落原合并/删除语义）：
  - 硬键盘 onPreviewKeyEvent Backspace：条件从 `start==0` 扩展为「内容起点」= `collapsed && effectiveText(substring(0,start)).isEmpty()`（raw 0 或前导 ZWSP 后的 raw 1）——拦截在删除前，文本无损；
  - 软键盘 observer 新增 `plainIndentBackspace`：IME 已删前导 ZWSP（lastText 以 ZWSP 开头 && text==lastText.drop(1) && lastSelection.start==1）且 isPlainIndentedBlock → 转发 onBackspaceAtStart。与 backspaceMerge（start==0，删的是 ZWSP）互补；非缩进块维持现状（ZWSP 静默删除无感）。
- dedent 实现 `dedentPlainBlockAtContentStart`：ReplaceBlocksCommand 重建，**dedentMd = 上一级 EM 前缀 + ZWSP + 内容**——ZWSP 让重建块保持打字结构（前导退格锚点），软键盘才能继续逐级退格（否则 setMarkdown 结构光标 0 退格是检测死角）；focusAfter=(id,1)（内容起点）。一次命令一步撤销，revert stash 完美还原（撤销链干净，无补 ZWSP 的 Typing 脏步——避免 undo() 块内 history 优先调度被污染）。
- 空缩进块退格同样命中（dedentMd = 前缀+ZWSP，content 空）→ 逐级减到一级后走空块删除分支，链路完整。
- 测试：新增 `缩进块内容起点退格逐级减缩进`（软键盘场景复刻：removeTextRange 删 ZWSP → 退格 → 断言前缀 -2/ZWSP 补回/块数不变/循环到一级 no-op/撤销恢复 12 EM）。

## 缩进块回车行为闭环（用户需求 1+2）
- 需求 1：空缩进行回车 = **减一级缩进**（原地），逐级返回，到无缩进才正常新起一行（此前是直接拆出新空行丢层级）。需求 2：有内容缩进行回车，新行**继承同层级**（此前新行顶格）。
- 实现（BodyBlocksEditor）：
  - 顶层 helper：`plainIndentPrefix(level)`（EM×2×(level-1) 前缀构造，与库编码端同款）、`isEffectivelyBlankLine(state)`（剥 ZWSP/图片占位后 isBlank，**含 \n**——软键盘回车后空块文本 "\u200B\n" 用 isEffectivelyEmpty 判不出）。
  - splitTextBlock（硬键盘）+ normalizeBlockParagraphs（软键盘）入口对称加「空缩进行」分支：isEffectivelyBlankLine && level>1 → 复用 dedentPlainBlockAtContentStart（减一级、不拆块）。
  - 行尾回车新空行继承：splitTextBlock 的 afterMd 空分支 + normalize 的 trailingBlanks/兜底空块 → markdown = `plainIndentPrefix(srcPlainLevel) + ZWSP`（ZWSP 退格锚点必备，纯前缀空段落解码后无 ZWSP 会成软键盘死角）。
  - **行中回车无需处理**：toMarkdown(range) 经 extractRangeState 的 paragraph.copy() 保留缩进属性 → 前后半 md 自动带 EM 前缀 → 解码还原（用例锁定该自动行为防回归）。
- 行为闭环：3 级行尾回车 → 新空行 3 级 → 再回车逐级 2→1 → 无缩进空行回车 → 普通新行。列表空项不受影响（effective 文本含 marker 非空白，不误入缩进分支）。
- 测试：新增 3 用例（空缩进行逐级返回+无缩进后正常新行 / 行尾继承+新行 ZWSP+可减缩进 / 行中继承防回归）。
