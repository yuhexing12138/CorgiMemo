### 补充需求：相邻文本块自动合并（v2026-09-15）

用户要求"当文字块相邻时，应当自动合并为一个块"，并确认三个口径：**时机 = 加载 + 运行时**（任何用户操作后都归一化）；**缩进差异 → 转写为块内行首 EM 前缀**（用户选择"合并后保留缩进"口径；**已知渲染为可见宽空格而非真缩进**）；**加载时的合并不进命令栈**（否则一进页面就能撤销回旧结构）。

实现 `BodyBlocksEditor.normalizeAdjacentTextBlocksInto(into)`：

- 切「连续文本块段」（载体空块 / 图片 / 分割线阻断）→ **倒序**生成 `ReplaceBlocksCommand`（倒序避免前面段合并后让后面段的 index 失效）
- 接缝**单 `\n`**（与"回车不拆块"同语义）；**不能 `\n\n`**——那是块间分隔符，写进块内下次加载会被重新拆开

- 接线：`executeAndPush`（全部用户操作）+ `executeAndPushWithImageSeparators`（删图 / 删分割线）+ `initialize`（加载规范化，replaying 门控内直接 apply）
- ⚠️ **undo / redo 不经过这些入口** → 撤销不会被立刻又合并回去（否则撤销无意义）

⚠️ 配套：`effectiveText` 增剥 `PLAIN_INDENT_CHAR`（EM）——转写的缩进前缀不能污染字数统计 / 复制全文 / 空行判定。

现在「编辑过程中实时合并」覆盖全部结构变更入口：`executeAndPush` / `executeAndPushWithImageSeparators` / `moveBlock` / `insertImagesAtFocused` / `initialize`（加载规范化）。唯一刻意例外：**undo / redo 不合并**（否则撤销会被立刻合并回去、撤销失去意义）。

**★ 教训（本项目重要）**：结构归一化（载体空块 / 相邻文本块）是**逐入口手工接线**的。新增归一化规则时必须 `grep pushExecuted\(` 把所有**自组装命令**的入口捞出来逐个补，否则会出现"某条路径不生效、只有加载时才收敛"这类隐蔽缺陷（用户实测才会暴露）。

**★ 根因修复（`e48b2e14`，用户实测反馈"1、2 两点都不能实时合并"）**：

`pushExecuted` **只把命令压进撤销栈、不执行命令**（其注释写明"命令已被调用方 apply 过——批量插图的循环路径"）。`normalizeImageSeparatorsInto` 是**自己 apply** 的（`onEach { it.apply(this) }`）✅，但我新写的 `normalizeAdjacentTextBlocksInto` **只 `into += command`、没有 apply** ❌ → 合并命令只进撤销栈、从未执行。

**诊断指纹**：加载路径（`initialize` 里我自己写了 `forEach { it.apply(this) }`）**正常**，运行时路径全部静默失效——"只有加载时才收敛"这个现象本身就指向"运行时的命令没被执行"。

修法：合并命令生成后**立即 apply**（与载体归一化同一约定，代码内注明原因）；`initialize` 改为只触发一次扫描（避免重复执行）。

**★ 项目约定（易踩）**：**归一化命令必须在收集时就 apply** —— 因为最终 `pushExecuted(CompositeCommand)` 不执行命令。新增归一化入口时照抄 `normalizeImageSeparatorsInto` 的 `onEach { it.apply(this) }` 模式。

### 结构归一化入口收敛（`758ff723`，用户说"做归一化"）

执行上轮建议的重构，把"逐入口手工接线"收敛为两个函数：

### 方案 D 配套：markdown 加载保留软换行（子模块 `7a5d43e` / 主仓库 `015004c3`）

**根因（parser 两处）**：
1. `RichTextStateMarkdownParser.onText`：`text.replace('\n', ' ')` → 段内换行符被抹成**空格**；
2. EOL 处理：**只要上一段非空就 `richParagraphList.add(RichParagraph())`** → markdown 里**每一行都成为独立段落**。

→ 重进后块内 = 「多段落 + 无 `\n`」→ `isSoftLineBreakBlock()` 不命中（size == 2）→ 回到"段末占位空格"老路径 → 行尾 offset 落到下一段首字符 → **跳变复现**。

**修法**：
- `onText`：**保留 `\n`**（不再替换成空格）；
- EOL：仅当"本行之后**紧跟空行**（跳过行内空白后仍是 `\n`，即真正的段落分隔）"才新起段落；单 `\n` 视为**软换行** → `onText("\n")` 把换行符写进当前段落，使"行尾"在文本层获得真实 offset 归属。

**★ 完整一致性条件（四点，缺一不可）**：`checkForParagraphs` 不拆段 + `updateAnnotatedString` 不替换 `\n` + `updateTextFieldValue` 不用 span tree 覆盖文本 + **parser 保留软换行且不按行拆段**。任一处遗漏就会出现"输入时正常、保存重进异常"（本次）或反向。

**待验证**：保存 → 重进 → 拖拽手柄应保持正常；同时回归列表 / 任务列表 / 图片 / markdown 往返 / 中文 IME。

### 方案 D 的架构性副作用：段落级操作失去行粒度（待决策）

**用户报告**：块内换行后（单段落 + 段内 `\n`）点击复选框按钮，**所有行的开头都出现勾选框**；期望是"光标在哪行、哪行才出现"。

- 段落粒度粗（合并）→ 手柄/行尾正常 ✅，但段落级操作无法按行区分 ❌
