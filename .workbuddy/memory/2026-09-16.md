### 编译修复（子模块 `6c42781`，用户构建反馈）

`copy()` / `withChecked()` / `withCheckedLines()` 三处构造调用的具名参数写成了 `lastKnownLineCount = ...`，
而主构造参数名是 `initialLastKnownLineCount`（**先加字段、后补构造参数时漏改调用点**）→ 三个候选
构造器全因参数名失配被否，报 `None of the following candidates is applicable`；`getNextParagraphType`
不传该参数故未报错——报错组数（3 组）直接指向肇事调用。
**教训：给 private 主构造补新参数时，全文件 Grep 类名构造调用逐一核对具名参数。**

**★ 关键实现事实（后续改库必读）**：
- **行 0 与行 ≥1 双字段**：`checked` = 行 0（兼容 `setTaskListChecked`/`toggleTaskListChecked`/markdown 行 0 编码）；`checkedLines` 只存行 ≥1。两者都通过 setter 重建 `startRichSpan`（CheckBox 相等性驱动重绘）。
- **历史快照**：走 `RichParagraph.deepCopy()` → `type.copy()`——`copy()`/`withChecked*` 必须携带 `checkedLines` + `lastKnownLineCount`；运行时翻转**必须换新实例**（`withCheckedLines`），就地变更会污染 undo。
- **续行剥除的 span 定位**：EOL 软换行把 `currentRichSpan` 置 null → PARAGRAPH open 创建新 span 承接该行前缀 tokens → 行首 span = 段落 children **最后一个** span（行内样式 span 挂其下）。
- **EOL 分段的 Triple→Pair**：`nextLineListInfo = (isTaskLine, level)`；null = 下一行非列表项。
- **decode() 的 chunk**：TaskList 行 0 前缀在 `appendParagraphStartText`（chunk 外），chunk = children 输出；`<br>`/`appendLine` 在 chunk 处理之后，不受影响。

**已知取舍 / 限制**：
1. 增删 `\n`（编辑改变行数）⇒ `checkedLines` 全清（行 0 保留）——保守丢状态不错位；行结构不变的操作（勾选翻转、undo/redo）不受影响。
2. 段末空行（段落最后字符是 `\n`）的行起点超出"最后非空 offset"，`getBoundingBoxes` 返回空 → 不画勾选框，输入首字符后出现。
3. 跨行样式（如 `**` 包两行）被行前缀截断，样式按行拆分、内容不丢。
4. 勾选行文字降级（40%）暂缓（设计第 5 条）——`taskListCheckedSpanStyle` 仍按整段 `checked`（行 0）驱动。
5. 混合列表（`- [ ] a` 下一行 `- b`）分段的普通项仍会被 `getNextParagraphType()` 变成 TaskList——pre-existing 语义未动。
6. 普通列表项分段恢复（parser 4/4）**顺带修复**了方案 D 期间 `- a\n- b` 重载并段的回归。

**App 侧零改动**（命中走 `toggleTaskListCheckedAtPosition`，签名未变）。

### 编译修复 4（子模块 `b60ed59` / 主仓库 `aa40d2b7`，用户构建反馈）

### 真机三连修复（库 `39fecda` / 主仓库 `009600d8`，用户截图反馈：行 2 插不了 / 行 0 不能勾 / 行 0 文字错位）

   入口都要考虑光标在末尾的场景。**
3. **行 0 文字比行 1+ 靠右一个 NBSP**：单段落混合下 marker（NBSP）只在行 0 占宽。

   **教训：单段落多行里"行 0 独有 marker"的占宽必须由 restLine 补偿，否则行 0 与后续行错位。**

### 对齐修复二轮（库 `9a8ac55` / 主仓库 `eef03b5e`，用户实测补宽无效 → 换 ZWSP 根治）

restLine 补 `startTextWidth` **未生效**（该回填对 TaskList 未发生——阶段 A 的"测量回填"记忆
不适用于当前路径），错位依旧。用户提议删占位符 → **采纳变体：marker NBSP → ZWSP（U+200B）**：
- ZWSP 零宽不占宽 → 行 0 与行 1+ 文字起点**天然对齐**，`firstLine = restLine` 恒成立（撤补宽）。
- marker 仍需**非空**（空文本折叠 range → 绘制守卫跳过），ZWSP 是"零宽锚点"。
- **绘制定位同步从字符 boundingBox 改为 `getCursorRect`**：零宽字符使行宽为 0，
  `getBoundingBoxes` 的 `startOffset >= lastOffset` 守卫（lastOffset 依赖最后非空行右缘）
  会让**空任务段**的框退化消失；getCursorRect（left=行首文字 x、top/bottom=行高）对
  零宽/空行/空段全部有效。每行框 x 单一基准（行 0 cursor.left - reserved）+ 各行独立 y。
- App `isSkipChar` 已剥 ZWSP（空块锚点同字符）✓ 字数/序列化不污染；App 空块 ZWSP
  不变量与 marker ZWSP 层次不同（children vs startRichSpan）不冲突。
- **待观察**：空任务段（text=ZWSP）的软键盘退格现在会命中 App 的 `emptyBackspace`
  （lastText==ZWSP && text==""）走块级退格——NBSP 时代是普通删字——行为变化待真机确认。

**教训：库的"测量回填"（startTextWidth）不能假设对新增段落类型生效——依赖它做几何补偿前
先确认回填链路；对占位字符的鲁棒做法是定位不依赖其测量宽度（用行几何/光标矩形）。**

### 回车空行补位（主仓库 `71bbf9f9`，用户澄清场景：空待办来自回车而非尾插）

上一轮只修了尾插/加载路径；**任务段内回车**（软键盘 IME 提交 \n）的新空行同样无实宽字符

- 触发：光标折叠 + isTaskList + composition==null + **text.length == lastText.length + 1**
  （单字符插入 = 回车特征）+ 光标处空行（前是行界 && 后是行界）→ `addTextAtIndex(cursor, NBSP)`。
- **防循环**：退格删 NBSP 是长度 -1 不满足 +1；补后光标下一字符是 NBSP（非行界）不满足空行。
- 已知边缘：粘贴多空行（长度 +多）不触发（保存重进 strip 兜底）；连续回车第二行光标偏
  （打字/点击即恢复）。undo 粒度碎一步（回车与 NBSP 占位分属两步）。
- **经验**：空态行的占位体系 = ZWSP（marker 锚点，零宽）+ NBSP（光标占位，实宽）双字符
  分工；App 层维护走 observer「长度差 +1 特征」防退格死循环。
- **编译修复**：`const val A = ... + B`（B 声明在后）报 `Variable 'B' must be initialized`

## 灵感编辑页 WebView 接入 editor.js 方案评估（结论：不建议替换）

产出：`docs/灵感编辑页-WebView接入editorjs-评估报告.md`。

- **实测规模**：`inspiration/` 31 kt / 18,083 行；`BodyBlocksEditor.kt` 4,903 行；compose-rich-editor 子模块 244 kt / 48,356 行（自维护 fork）。
- **前提修正**：Accompanist WebView 已被官方弃维护（"API is no longer maintained, recommend forking"）——真实底座只能裸 AndroidView+WebView + 自建 bridge。
- **editor.js 现状**：v2.31.6（2026-04，Apache-2.0）仍活跃；但移动端长期 open 硬伤：#2908 移动端无法多块选择、#2866 DOM 内存泄漏、#2873/#2975 onChange 不触发（自动保存丢数据风险）、#2902/#2917 iOS 光标/滚动；undo 依赖第三方 editorjs-undo（v2 仍 beta，v1 全文档 re-render）。

- **成本结论**：迁移 12–18 人周 + Kotlin/JS 双栈长期维护；建议路线 A（继续 Compose 深化，新块 2–5 天/项）或路线 B（2 周 POC：中文 IME 键盘/undo 接图片删除/内存+onChange 三点证伪）；路线 C（仅分享导出走 HTML）可低成本并行。

## WebView 多块选择专项调研（评估报告补充）

产出：`docs/灵感编辑页-WebView多块选择专项调研.md`（独立补充报告，未提交时再定）。

- **根因定性**：editor.js #2908 是架构性（每块独立 contenteditable，官网原文承认）；移动端选择手柄被系统接管，自绘无法替代 → 生态内无解。社区插件 `editorjs-multiblock-selection-plugin` 只修桌面端块选择后 inline 工具不生效（#2474），不解决移动端。
- **选型分水岭**：跨块选择能力取决于文档模型而非 UI 形态——块隔离（editor.js）❌ vs 单文档（ProseMirror/Tiptap、BlockNote、Lexical、Quill）✅ 原生支持移动端拖手柄跨块。BlockNote = 块式 UI + ProseMirror 内核，形态最接近、MPL-2.0。
- **Android 兼容性共识**：ProseMirror 内核最强（Moby Dick 长文测试唯一通过）；Lexical Android 问题偏多（三星键盘覆盖、退格复活、pre-1.0）；Slate 系 Android 二等公民直接排除。
- **2026 Android WebView 新坑**（flutter_blocknote_editor changelog）：Chromium 148+ 对 file:// 收紧 CORS（origin=null，ES module/CSS/字体被拦）→ 须本地 HTTP 或 allowFileAccessFromFileURLs；编辑器池预热解决冷启动；**undo/redo 必须全留 JS 侧、原生永不回灌事务（单向流）**——与本项目双层撤销模型直接冲突，是隐藏大成本。
- **关键提醒**：本项目 Compose 侧跨块选择 2026-09-14 已被用户主动删除（e9abf6f7，交互不符预期）——若 WebView 方案核心卖点多块选择，POC 必须先验证其交互（原生手柄形态）优于被删的自绘手柄版。
- **POC 清单升级为 5 点**：①跨块选择（一票否决+与被删版对比）②中文 IME（Gboard/搜狗/三星）③键盘 inset ④undo 接自定义块 ⑤Chromium 148+ 资产加载/预热池冷启动。POC 对象从 editor.js 换成 BlockNote（或裸 Tiptap）。

## BlockNote 与灵感编辑器适配度调研

产出：`docs/BlockNote与灵感编辑器适配度调研.md`。

- **适配度结论**：15 项能力 7🟢/6🟡/2🔴（editor.js 是 3/4/8）——缺口从 8 项深度自研收敛为 2 项模型冲突。BlockNote v0.52.1（2026-07，MPL-2.0，React 栈，ProseMirror+Tiptap 内核）。
- **意外利好**：divider 内置（`---`+回车 input rule 与项目 GFM 语法一致）；markdown 导入导出官方 API（blocksToMarkdownLossy/tryParseMarkdownToBlocks，常用块全支持往返）；载体空块体系可整体废弃；跨帧焦点/非文本块焦点保护被单文档模型架构性消解；Block 模型 {id,type,props,content,children} 与 BodyBlock 同构。

- **最终立场**：适配度不构成否决也不构成放行——迁移与否仍由 5 点 POC 决定；自定义分割线块+字号 custom style 可作半天探针验证自定义 API 路径。

**★ v0.52 API 实测事实（文档示例偏旧，迁移必读）**：
- `createReactBlockSpec(config, impl)` 返回**工厂函数，必须调用一次**得 BlockSpec 再进 schema。
- style 的 `propSchema` 是单值类型 `"boolean" | "string"`（非对象）；React render 收 `{ value, contentRef, editor }`，children 由 core 渲染进 contentRef 元素；应用时 `styles: { fontSize: "24px" }`（直接字符串）。
- `blocksToMarkdownLossy` 是**同步**方法；解析是 `tryParseMarkdownToBlocks` / `tryParseHTMLToBlocks`（无 tryBlocksToMarkdownLossy 这个名字）。
- propSchema 的 `values` 会把 props 类型收紧为字面量联合（TS 层直接受益）。
- **React 19 强制**：@blocknote/mantine 0.52.1 → @mantine/core 9.6.1 peer react ^19.2.0，React 18 ERESOLVE 装不上。
- 体积实测：主 JS gzip 356KB + CSS gzip 38KB + Inter 字体（可剔除）。

**★ 两个关键发现**：
1. **`<hr>` 被内置 divider 抢占解析**（自定义块 parse 不命中）→ 迁移分割线三样式必须走 **extendBlockSpec 扩展内置 divider**，不能新建块（core 有 extendBlockSpec）。
2. **markdown 导出对自定义样式有损实锤**：波浪线导出成 `***`、fontSize 丢失；补偿方案验证可行：toExternalHTML 输出 `<hr data-divider-style="wavy">` + parse 从 data 属性回读 → 桥接层用 data 属性编码做样式往返。
