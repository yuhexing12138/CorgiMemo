## 11:19 日志（第 9 份）→ 弹层「飞出屏幕外」= 单位换算错（px vs dp）
- **现象**：键盘展开时重命名编辑框**直接向上飞出屏幕外**（过度上移）。

  - ★ 与既有约定一致：`setEditorMinHeight` 传的就是 **dp**（`heightDp: Float`），WebView `initial-scale=1.0` 下 1 CSS px = 1 dp。**凡是给 JS 的尺寸一律用 dp，禁止传物理 px**。

- **上轮方案（第十六轮）判错并回滚**：`flip({ fallbackPlacements: [] })` 禁用翻转

  顶到 `rect.top < 0`（视口外）→ 用户「编辑页完全看不到工具条，无法操作」。
  ⇒ `flip` 是「上方确实不够时翻到下方」的**唯一兜底**，抽掉它等于断了自保能力。
- **两处 `flip` 全部回滚**为 `flip()`：`RenamePanel`(弹层) + `MediaOnlyFormattingToolbarController`(工具条)。
- **正确修法（本轮实施）**：在**避让逻辑内部**自己划上限，不外包给 floating-ui。

- **★ 为什么 `overflow: visible` 救不了**：`will-change: transform` 让该元素

- **★ 一张表解释全部矛盾现象**（本案是「测量全绿但用户看不到」的教科书案例）：
  | 现象 | 解释 |
  |---|---|
  | 工具条可见 | 它在包裹层 bounds 内 |
  | 弹层不可见 | 它在 bounds 外、被合成层裁掉 |

  ```

  `wcFix=transform` ⇒ 没压住需改 `style` 直改。

## 第二十五轮：弹层「消失」真因定案 + 布局位移修法（17:03）

### `[layerProbe]` 铁证（真机 17:03 日志，54 条采样）

弹层 `popover=div.mantine-Popover-dropdown[pos=absolute z=300]`，

★ 连带**确实成立**（KDoc 对、我从 `FloatingPortal` 的推断**错了**）。
但真正的病灶在 `rect`：

```

04.487  tick  t=633.4 h=18.0 hit=null   ← 跳回屏外（被裁到 18px）

### ★★ 根因：`transform` 与 floating-ui `autoUpdate` 的重定位反馈环

- `transform` **不改变布局**，但**改变 `getBoundingClientRect()` 的返回**；
- 官方 floating-ui 的 `autoUpdate`（`ResizeObserver` + `IntersectionObserver`）
  **周期性回读参考元素几何**，读到「已位移」的 rect ⇒ 重算弹层位置
  ⇒ 把弹层算回**工具条未避让时的原始位**（`t≈633.4`，屏底外）；
- 下一轮观察回调再纠正 ⇒ 往复，**双方在同一份几何上互相干扰，谁也收敛不了**。

⇒ 同时**修正第二十二轮的因果误判**：`[shift]` 的 FINAL 段显示
工具条 `after=366.9 want=366.9 err=0.0` —— **我们的避让是精准的**，
问题不在避让量，而在**位移载体选错**。

### 修法（已实施）：`transform: translateY()` → `position: relative + top`

`writeShiftStyles` 生成的规则改为：
```css
.bn-formatting-toolbar[data-ime-shift] { position: relative !important; top: -260.5px !important; }
```

- `relative` 不脱离文档流（保留占位）⇒ 不影响后续兄弟布局；
- `top` 偏移**真实写入布局结果** ⇒ `getBoundingClientRect()` 反映
  **双方一致认可的最终位置** ⇒ floating-ui 重定位结果与我们相同 ⇒ **反馈环消失**；
- `z-index: auto` 下 `relative` **不创建新层叠上下文**，无 z 轴副作用；
- `position` 与 `top` **必须成对**出现，缺一不生效；
- 摘 `data-ime-shift` 属性后二者**同时**回落（`static`/`auto`），
  故「测量前摘属性拿原始 rect」的既有闭环机制**语义不变**。

const prevDy = shiftedMap.get(el) ?? 0;      // 上一帧已施加的「向上位移量」
const rect = el.getBoundingClientRect();      // 含位移的当前位
const rawBottom = rect.bottom + prevDy;       // 反算未位移位

⇒ `366.9 + 261.3 = 628.2`，与旧实现「摘属性后实测」的 `RAW bottom=628.2`
**完全一致** ⇒ 公式正确。

**2. 判定改用 `rawBottom` / `rawTop`**（不能用 `rect.bottom`）
新实现不再摘属性，`rect` 是"已避让后"的位置；若仍拿它比 `targetBottom`，

⇒ 又一次自激振荡（第七轮 `else if` 删记录那个坑的同类）。

**4. `MutationObserver` 收紧为「只在 `.bn-form-popover` 增删时调度」**
```tsx
let popPresent = !!document.querySelector(".bn-form-popover");
const obs = new MutationObserver(() => {
  const now = !!document.querySelector(".bn-form-popover");
  if (now === popPresent) return;

```
原实现对 `document.body` 的**任意子树变更**都重算（正文打字、图片加载、
floating-ui 改弹层 `style`……），其中任何一次 `applyShift` 的 DOM 写入又回头触发它。
键盘高度变化另有 `[imeHeightPx, imeGapDp]` 依赖触发，**不需要 mutation 兜底**。

**保留不动**：闭环校正 `for pass < 3`（它回读**实际**位置，语义不变，是通用保险）；

## 第二十九轮：Rename 弹层「不可见」根因定案 + 修法（17:39 日志）

### 症状
工具条避让**完全正确**（`err=0.0`，`rect=t331 b366.4`，键盘上沿 `370.9`），
但 Rename 弹层**整块落在键盘里**（`rect=t371.9 b409.4 h37.5`，顶边比键盘上沿低 1px）
⇒ 用户看到「工具条在、弹层不可见」。

### 铁证（19 帧恒定，零抖动）
```
tbTop=auto        cssTop=39.7272px  →  rect t=632.4 b=669.9  hit=null   ← 位移前：屏外
tbTop=-261.273px  cssTop=39.7272px  →  rect t=371.9 b=409.4  hit=self   ← 位移后
```
`cssTop` **全程恒定 39.7272px** ⇒ floating-ui 从头到尾都认为弹层该在
「工具条下 39.7px」（`yAxis=below gapToTb=-77.9`）。
`632.4 − 261.3 = 371.1 ≈ 371.9` ⇒ 弹层被工具条**连带上移**了同一量。

### ★★ 根因（推翻第二十二轮假设）
1. **锚点是选区矩形**（`posToDOMRect`），不是工具条；视频块选区约在 `y=460..628`。
2. 键盘升起 ⇒ 锚点泡进键盘 ⇒ floating-ui `shift()`/`flip()` 把弹层夹到
   **工具条正下方**（它眼里的"下方"，实际已无空间）。
3. 我方避让把工具条推到 `331`，弹层作为**子元素连带**跟着上去
   ⇒ 落点正好 `371.9`（键盘上沿下 1px）⇒ 被键盘吃满。
4. ⇒ **不是 `flip()` 朝向问题**（它本就是 `below`，因锚点在键盘里），
   **改 flip 参数无用**。
5. ⇒ **「只动工具条、弹层靠连带」的假设被证伪**：连带方向不对
   （弹层本就在工具条下方，一起上移后仍在下方 = 键盘区）。

### 修法（4 处）
1. `SHIFT_TARGETS` **弹层回归清单**：`[".bn-formatting-toolbar", ".bn-form-popover"]`。
2. **目标位分角色**：工具条 `keyboardTop−WANT_GAP`；
   弹层 `keyboardTop−WANT_GAP−工具条高−POP_ABOVE_GAP`（恒在工具条上方，
   重新引入 `POP_ABOVE_GAP=4`，防第十轮「弹层盖住工具条」重演）。
3. **弹层走 `margin-top` 而非 `position/top`**（★ 关键）：
   弹层原始是 `position:absolute`（floating-ui 定位），写 `relative` 会
   **把 absolute 覆盖成 relative** ⇒ 定位体系崩坏。`margin-top` 不改
   `position` 值、不改 `offsetParent`，只做布局推移。
4. **弹层判定/位移与工具条分流**：
   - 判定：弹层用**实际 `rect.bottom`**（不反算 `rawBottom`——往返算会把
     工具条连带位移误算成"我方施加的"，偏移 261.3px）；
   - 位移：弹层**累加**（`prevDy + overflow`），工具条仍重置；
     且弹层**不加 `+4`**（`overflow` 对它是相对量，+4 会过量 4px）；
   - `else` 分支：弹层**保留 `prevDy`**（归零会每帧一弹 ⇒ 闪烁）。

### ★ 关键约定（写代码时必守）
- **位移载体必须按元素原始 `position` 选**：`static` → `position:relative+top`；
  `absolute` → `margin-top`（改 `position` 会摧毁第三方定位体系）。
- **子元素连带位移会污染 `prevDy` 反算**：凡"父级也在清单内"的元素，
  一律禁用 `rawBottom = rect.bottom + prevDy`，改用实际 rect + 累加。
- `tsc --noEmit` EXIT=0（改动后已验证）。
