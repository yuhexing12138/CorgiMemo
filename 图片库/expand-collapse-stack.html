三种实现方案对比

原型已用方案 A 的思路实现（isExpanded 状态驱动 + CSS transition 动画）。 以下是三种方案在 Compose 端的落地对比：

方案 A（推荐） 推荐

在 SwipeableImageStack 内部新增 isExpanded 状态，展开时切换布局模式 （Box → Row + LazyRow），所有动画用 Animatable + LaunchedEffect 实现。

优点

  • 动画最连贯：同一批卡片实例不重建，transform 连续过渡
  • 状态内聚：isExpanded 与卡片 order 共存于同一作用域
  • 天然支持共享元素过渡（SharedTransitionScope）

缺点

  • SwipeableImageStack 复杂度增加（需处理两种布局测量）
  • Box 与 LazyRow 切换时需手动管理 transition spec
适用场景：追求动画流畅度、卡片实例不重建的生产环境实现
方案 B

新增一个独立的 ExpandedImageRow 组件，展开时用 AnimatedContent 替换 SwipeableImageStack。

优点

  • 职责分离：ExpandedImageRow 独立测试和复用
  • SwipeableImageStack 几乎零改动
  • 代码组织清晰，后续维护成本低

缺点

  • 组件切换时卡片实例重建，无法做 transform 连续过渡
  • 除非用 SharedTransitionScope，否则动画有跳变
  • 两个组件需同步图片数据源和当前 order
适用场景：希望代码组织清晰、可接受动画略逊的场景
方案 C

在现有 SwipeableImageStack 上层叠加一个展开视图，用 AnimatedVisibility 切换显示。

优点

  • 改动最小：SwipeableImageStack 完全不变
  • 展开视图独立开发，不影响现有逻辑
  • 适合快速验证概念

缺点

  • 叠加层与底层状态同步复杂（order、currentIndex）
  • 内存占用高：两套布局同时存在于组合树中
  • 层级管理易混乱，调试困难
适用场景：快速验证、不想动现有代码的原型阶段
